DPI vs PPI: What Matters for Print and Web

DPI and PPI sound alike but measure different things. Learn which one matters for print, which one matters for screens, and why 72 vs 300 DPI confuses everyone.

DPI and PPI are the most confused pair in all of imaging. People use them interchangeably, tools label them inconsistently, and the result is a mess of wrong advice.

The confusion has real costs. Designers set 300 DPI on web images that do not need it, and print buyers accept 72 DPI files that will never print well.

This article separates the two terms cleanly, explains where each one matters, and gives you a simple rule for deciding which number to care about in any situation.

DPI Defined: Dots of Ink

DPI stands for dots per inch, and it belongs to printers. It counts the tiny dots of ink a printer lays down in one inch of paper, and it decides how fine the printed detail can be.

A printer rated at 300 DPI can place 300 ink dots per inch. A printer rated at 600 DPI can place twice as many, which is why fine-art prints use the higher value.

In image files, DPI is a metadata tag that tells software the intended print density. It does not change the pixels; it tells the printer how to space them on the page.

When a platform asks for 300 DPI, it is asking for this tag. It wants the file to declare that its pixels are meant to be packed 300 to the inch.

PPI Defined: Pixels on a Screen

PPI stands for pixels per inch, and it belongs to screens. It counts how many physical pixels a display packs into one inch of its surface.

A phone with a 400 PPI screen squeezes 400 pixels into every inch, which is why text looks razor sharp even at small sizes. An old monitor at 96 PPI shows the same text with visible edges.

PPI is a property of the display hardware, not of the image file. You cannot change a screen PPI by editing a file, any more than you can change a monitor size by editing a photo.

Some image editors use PPI as the label for the same metadata tag that others call DPI. That overlap is the main reason the two terms get mixed up.

Why DPI and PPI Get Confused

The confusion has three causes. First, the terms sound alike and both involve inches. Second, some software uses them as synonyms for the same file tag. Third, both relate to how dense an image appears.

Photoshop, for example, labels the file resolution field as PPI, while a print shop calls the same number DPI. The file holds one number, and two industries give it two names.

The practical fix is to ask what the number controls. If it controls ink on paper, think DPI. If it controls pixels on a screen, think PPI. The context tells you which meaning applies.

For the file tag itself, the distinction barely matters. Whether the field is called DPI or PPI, it holds the same value, and the image DPI changer writes it correctly either way.

Print: DPI Is What Matters

In print, DPI decides everything about sharpness. A 3000-pixel image printed at 300 DPI covers 10 inches, while the same pixels at 150 DPI cover 20 inches with half the density.

The print standard is 300 DPI for anything held in the hand: books, brochures, magazines, and packaging. At that density the eye cannot pick out individual dots at reading distance.

Large prints relax the rule. A poster viewed from two meters away looks fine at 150 DPI, and a billboard seen from the road can drop to 50 DPI or lower without anyone noticing.

Before any print job, divide pixels by DPI to get the physical size. If the result is smaller than the size you need, get more pixels or accept a smaller print.

Web: Pixels Matter, DPI Does Not

On the web, browsers ignore the DPI tag completely. They display the image pixel for pixel, so a 1000-pixel image occupies 1000 screen pixels whether its tag says 72 or 300.

What matters on the web is the pixel dimensions relative to the display size. An image shown at 800 pixels wide should be roughly 800 to 1600 pixels in the file, depending on the screen density.

Setting 300 DPI on a web image changes nothing about how it looks or loads. The file size stays the same, the display stays the same, and the only difference is a number in the header that no browser reads.

The web rule is therefore simple: match the dimensions to the display, compress the file for speed, and forget DPI entirely until the image goes to print.

The 72 DPI Myth

The most persistent myth in imaging is that web images must be 72 DPI. It comes from the early Macintosh, whose screen displayed 72 pixels per inch, and it has been wrong for decades.

Modern screens range from 100 to over 400 PPI, so no single DPI value describes them all. A 72 DPI tag on a web image is a historical accident, not a requirement.

The myth survives because software keeps writing 72 into files by default. Cameras, screenshots, and exports all stamp 72 DPI when they have no better value to use.

Ignore the number on the web. Judge a web image by its pixel dimensions and its file size, and leave the DPI tag alone unless the image is headed for print.

The 300 DPI Standard for Print

The 300 DPI standard exists because of the limits of the human eye. At normal reading distance, the eye cannot resolve detail finer than about 300 dots per inch, so more density adds nothing visible.

That is why book printers, journals, and packaging firms all ask for 300. It is the point where quality stops improving for a handheld print, and asking for more would only inflate file sizes.

Fine art and archival work go to 600 DPI because those prints are examined closely, sometimes under magnification. The extra density preserves hairline detail that 300 DPI would soften.

Going beyond 600 DPI is almost never useful for print. The printer cannot place the dots accurately enough, and the file becomes enormous for no visible gain.

Screens, Retina, and PPI

Retina and high-density screens changed the web calculation. A phone with a 2x display uses two physical pixels for every CSS pixel, so an image needs twice the pixels to stay sharp.

This is a PPI effect, not a DPI effect. The screen packs more pixels per inch, so the image file must contain more pixels per inch of display to keep up.

The practical response is to serve images at 2x the display size. An image shown at 400 CSS pixels wide should be about 800 pixels in the file, which looks sharp on both standard and retina screens.

None of this involves the DPI tag. The file dimensions do the work, and the tag sits unread in the header while the browser renders the pixels.

Print Size Math: Pixels Divided by DPI

The formula for print size is one division: pixel width divided by DPI equals printed width in inches. A 3000-pixel image at 300 DPI prints 10 inches wide.

Work backwards from the size you need. An 8 by 10 inch print at 300 DPI needs 2400 by 3000 pixels, so any file smaller than that will print soft at that size.

PPI never enters this formula. The screen density of the device that captured the image is irrelevant to the printed result; only the pixel count and the DPI tag matter.

Use the image dimensions checker to confirm the pixel count, then the DPI changer to set the tag. The two tools together answer the print question completely.

Metadata vs Pixels: The Core Distinction

The DPI tag is metadata: a few bytes in the file header that describe the intended print density. Changing it rewrites those bytes and leaves every pixel untouched.

PPI is hardware: the physical density of a screen. It cannot be changed by editing a file, because it describes the display device rather than the image.

This distinction explains why DPI changes are lossless and instant, while PPI changes are impossible. One is a label on the file, and the other is a fact about the screen.

When someone says an image has low resolution, ask which one they mean. If they mean few pixels, the fix is a bigger file. If they mean a low DPI tag, the fix is a metadata edit.

When to Change DPI

Change DPI when a print workflow demands it. Book platforms, journals, and print shops check the tag, and a file with the wrong value is rejected before anyone looks at the pixels.

Change DPI when the tag is missing. A photo with no DPI value leaves the print size undefined, and the software that opens it will guess, often badly.

Change DPI when repurposing a screen image for print. A screenshot stamped at 300 DPI satisfies the print workflow, provided its pixels are enough for the size you need.

Do not change DPI for the web. It has no effect on display or loading, and the time is better spent matching the dimensions and compressing the file.

When DPI Does Not Help

DPI does not help when the pixels are too few. A 400 by 400 thumbnail stamped at 300 DPI is still a 400 by 400 thumbnail, and it prints at just over an inch wide.

DPI does not help a blurry image. Blur lives in the pixels, and no metadata edit can sharpen an out-of-focus photo or a shaky screenshot.

DPI does not help on screens. A browser ignores the tag, so a web image set to 300 DPI looks identical to the same image set to 72 DPI.

DPI does not help file size either. The tag is a few bytes, so changing it does not shrink a file that a portal rejects for being too heavy.

A Print Workflow That Gets It Right

Start with the physical size you need, in inches. Multiply by 300 to get the pixels you need, and confirm your file meets that number with the dimensions checker.

Set the DPI tag to 300 with the DPI changer, and look for the Verified DPI badge. The badge confirms the tag is stored correctly and will read back the same in any program.

Send a test print or a proof before the full run. The proof catches problems that numbers cannot, such as colors that shift on paper or details that vanish at print size.

Keep the stamped file and the original together. If the printer asks for a different DPI later, re-stamp the original rather than the already stamped copy.

A Web Workflow That Ignores DPI

Start with the display size in CSS pixels. Double it for retina screens, and that doubled number is the pixel width your file needs.

Compress the file until the quality loss is just visible, then step back one notch. That is the smallest file that still looks good, and it is the one your visitors will thank you for.

Check the dimensions with the dimensions checker and the weight with the compressor. Those two numbers, not DPI, decide whether the image is right for the web.

Leave the DPI tag exactly as it came from the camera or the export. Changing it wastes a step, and no browser will ever read it.

Quick Reference: DPI vs PPI

DPI is dots per inch, a print concept. It lives in the file as a metadata tag, it decides the printed size, and you change it with the DPI changer when a print workflow demands it.

PPI is pixels per inch, a screen concept. It describes the display hardware, it decides how sharp a screen looks, and you cannot change it by editing a file.

On the web, care about pixel dimensions and file size. In print, care about pixel dimensions and the DPI tag. The two worlds use different numbers, and mixing them up is how good images get rejected.

Frequently asked questions

Is DPI the same as PPI?

No, although some software uses the labels interchangeably for the same file tag. DPI counts ink dots per inch on paper, while PPI counts physical pixels per inch on a screen. The file tag is a print instruction, and the screen density is a hardware property you cannot change by editing a file.

Does a 300 DPI image look better on a website than a 72 DPI image?

No. Browsers ignore the DPI tag and display the image pixel for pixel, so the two files look identical on screen. Web sharpness comes from pixel dimensions, not from the DPI value. A 300 DPI tag on a web image changes nothing about its appearance or loading speed.

Why do print shops ask for 300 DPI while screens use 72 DPI?

Print and screens are different media with different density needs. At reading distance the eye resolves about 300 dots per inch on paper, so print needs that density to look smooth. Screens show pixels directly, and the old 72 figure was just the density of early Macintosh displays.

Can I convert a low PPI screen image into a high DPI print image?

Only in the metadata sense. You can stamp a 300 DPI tag onto any image, but the tag does not add pixels. A screenshot with few pixels will still print small at 300 DPI. Real print quality needs enough pixels, which you get from a larger original or a higher-resolution capture.

What PPI should my phone photos have for printing?

Phone photos do not have a PPI in the print sense; they have pixel dimensions and usually no DPI tag at all. Divide the pixel width by 300 to find the print width in inches. A 4000-pixel-wide phone photo prints about 13 inches wide at 300 DPI.

Do I need to worry about DPI for social media uploads?

No. Social platforms display images on screens, where only pixel dimensions and file size matter. Upload the right dimensions and a reasonably compressed file, and ignore the DPI tag entirely for social media.
