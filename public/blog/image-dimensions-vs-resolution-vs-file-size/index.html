Dimensions vs Resolution vs File Size

Dimensions, resolution, and file size are three different numbers. Learn what each one means, how they relate, and which one matters for web, print, and social.

Three numbers describe every image, and people mix them up constantly. Dimensions, resolution, and file size sound related, but each one measures something different.

The confusion causes real mistakes. People buy a high-megapixel camera and wonder why the print looks soft, or compress a file and wonder why it still will not upload.

This article untangles the three numbers, shows how they relate, and explains which one matters for the web, for print, and for social media.

Three Numbers, Three Meanings

Dimensions are the pixel width and height, such as 1920 by 1080. They describe how many pixels the image contains, and nothing else.

Resolution is the density of those pixels, usually given as DPI or PPI. It says how many pixels fit into one inch when the image is printed or displayed.

File size is the weight of the image on disk, usually in kilobytes or megabytes. It says how much storage the file needs and how long it takes to download.

Each number can change without the others moving. You can shrink a file without touching its dimensions, and you can change the DPI without touching a single pixel.

Dimensions: The Pixel Count

Dimensions are the most concrete of the three numbers. A 4000 by 3000 image contains 12 million pixels, arranged in 4,000 columns and 3,000 rows.

Dimensions decide how large an image can appear on screen without stretching. A 400-pixel image shown at 1200 pixels wide must invent two thirds of its pixels, and the invention looks blurry.

Dimensions also decide the maximum print size. Divide the pixel width by the print DPI to get the printable width in inches, so more pixels mean a larger sharp print.

When a platform rejects an image for being too small, it is almost always checking dimensions. Minimum width rules are pixel rules, and no amount of compression or DPI editing will satisfy them.

Resolution: DPI and PPI

Resolution says how tightly the pixels are packed. A 300 DPI image places 300 pixels in every inch, while a 72 DPI image places only 72 in the same inch.

On screen, DPI is mostly ignored. A browser shows the pixels one by one, so a 1000-pixel image looks the same at 72 DPI and at 300 DPI on a monitor.

In print, DPI is everything. A 3000-pixel image at 300 DPI prints 10 inches wide, while the same pixels at 150 DPI print 20 inches wide with visibly softer detail.

DPI is metadata, not pixels. Changing it with the image DPI changer rewrites a small number in the file header and leaves every pixel untouched, which is why the change is lossless.

File Size: The Weight on Disk

File size is measured in kilobytes or megabytes, and it depends on the dimensions, the format, and the compression. A large image saved as an uncompressed PNG can weigh ten times more than the same image saved as a compressed JPG.

Compression is the biggest lever on file size. Lowering JPG quality from 90 to 70 can halve the file while changing the dimensions and the DPI not at all.

Format matters too. PNG stores images without loss, so photos saved as PNG are heavy. JPG and WebP throw away data the eye barely notices, so they are far lighter for photographs.

File size decides upload success and page speed. Portals cap it in kilobytes, and browsers download it over the network, so a heavy file fails or delays even when its dimensions are perfect.

How the Three Numbers Relate

Dimensions set the ceiling for everything else. A 4000 by 3000 image can be printed large, shown large, and compressed many ways, while a 400 by 300 image cannot do any of those things well.

Resolution translates dimensions into physical size. The same 3000-pixel image is a 10-inch print at 300 DPI and a 20-inch print at 150 DPI, because DPI is just the conversion factor between pixels and inches.

File size is the cost of storing the pixels. More pixels cost more bytes, and less compression costs more bytes too, so a large, lightly compressed image is the heaviest file of all.

Think of it as a triangle: dimensions are the amount of detail, resolution is how densely it is packed, and file size is what you pay to keep it.

Why a Big File Can Have Small Dimensions

A small image saved as an uncompressed PNG can weigh several megabytes. The PNG format stores every pixel exactly, and a noisy photo has a lot of exact information to store.

Screenshots are the classic case. A 1200 by 800 screenshot saved as PNG can weigh 2 MB, while the same screenshot saved as JPG weighs 200 KB, because JPG discards the noise.

This surprises people who equate file size with quality. The heavy PNG is not better; it is just less efficient at storing the same pixels.

When a portal rejects a file for size, check the format first. Converting a PNG photo to JPG often solves the problem without touching the dimensions at all.

Why a Small File Can Have Huge Dimensions

A 6000 by 4000 photo saved as a low-quality JPG can weigh under 1 MB. Heavy compression discards most of the fine detail, leaving a large grid of rough pixels.

The dimensions look impressive, but the image does not. Zoom in and the detail is gone, replaced by blocky artifacts and smeared edges.

This is why marketplaces check dimensions and humans check quality. A file can pass the pixel minimum and still look terrible when a shopper zooms in.

For the web, this combination is actually useful. A large, heavily compressed hero image fills a wide screen and loads fast, because the viewer never zooms close enough to see the damage.

Print Math: Pixels Divided by DPI

Print size comes from one division: pixels divided by DPI equals inches. A 3000-pixel image at 300 DPI prints 10 inches wide, and at 150 DPI it prints 20 inches wide.

The standard for quality print is 300 DPI. At that density, individual pixels are too small for the eye to see at reading distance, so the print looks smooth.

Large-format prints relax the standard. A poster viewed from two meters away looks fine at 150 DPI, and a billboard viewed from the road can drop to 50 DPI or lower.

Before you send a file to print, do the division. If the result is smaller than the size you need, get a larger file or accept a smaller print, because no DPI setting can invent missing pixels.

Screen Math: Pixels Only, DPI Ignored

Screens do not use DPI the way printers do. A browser displays an image pixel for pixel, so a 1000-pixel image occupies 1000 screen pixels regardless of its DPI tag.

This is why a 72 DPI image and a 300 DPI image look identical on a website. The DPI value is metadata that browsers simply ignore.

High-density phone screens complicate the picture slightly. A phone with a 2x display uses two physical pixels per CSS pixel, so a 1000-pixel image shown at 500 CSS pixels still looks sharp.

The practical rule for the web is simple: match the dimensions to the display size, and forget DPI. A hero image shown at 1200 pixels wide should be about 1200 to 2400 pixels wide in the file.

Compression and File Size

Compression changes file size without changing dimensions or DPI. It rewrites the pixel data more efficiently, discarding detail the eye is unlikely to notice.

JPG and WebP are lossy formats: each save discards a little more detail. PNG is lossless: it shrinks the file without discarding anything, which is why PNG photos stay heavy.

Quality settings control the trade-off. A JPG at quality 90 keeps nearly all visible detail, while the same image at quality 50 is half the size with visible damage in gradients and fine textures.

Use the image compressor to find the balance for your images. It lets you preview the result and the file size together, so you can stop at the point where the savings are worth the damage.

Choosing Dimensions for the Web

For the web, match the dimensions to the largest size the image will ever be shown. An image displayed at 800 pixels wide rarely needs to be more than 1600 pixels in the file, even for retina screens.

Bigger files load slower and cost mobile users data. A 4000-pixel hero image shown at 1200 pixels wastes two thirds of its pixels on every single page view.

Thumbnails need far less. A 200-pixel avatar stored as a 2000-pixel file is ten times heavier than it needs to be, and the extra pixels are invisible.

Responsive images solve this properly: serve a small file to phones and a large one to desktops. But even without that, right-sizing the file to the display is the biggest single speed win.

Choosing Dimensions for Print

For print, work backwards from the physical size. Multiply the inches you need by 300 to get the pixels you need, so an 8 by 10 inch print needs 2400 by 3000 pixels.

Always check the DPI metadata too. A file with the right pixels but a 72 DPI tag will be treated as a huge print by some software, and the layout will be wrong even though the pixels are fine.

Set the DPI correctly with the image DPI changer after confirming the pixel count. The two numbers together tell the printer exactly what you want.

If the pixels are not enough, do not upscale and hope. A slightly smaller print at full quality looks better than a larger print made from invented pixels.

Choosing Dimensions for Social and Marketplaces

Social platforms crop aggressively, so the ratio matters as much as the pixel count. A 1080 by 1350 portrait fills a phone feed, while a 1080 by 1080 square is the safe choice across feeds.

Marketplaces want large, square-ish images with room to zoom. A 2000-pixel product photo on a white background satisfies most minimums and gives shoppers a clear view.

Video thumbnails are the exception that proves the rule. A 1280 by 720 thumbnail is small in pixels but must be readable at a glance, so bold shapes beat fine detail.

Check every image with the image dimensions checker before uploading to a new platform. Its batch table and minimum checks catch the failures before the platform does.

Common Myths About Dimensions, Resolution, and Size

The first myth is that a higher DPI makes a web image sharper. It does not, because browsers ignore DPI. Only the pixel dimensions decide sharpness on screen.

The second myth is that a bigger file is always a better image. A heavy PNG and a light JPG can hold identical pixels, and the JPG is the better file for the web in almost every case.

The third myth is that megapixels decide print quality. They are only half the story; the print size and the DPI complete it, and a 12-megapixel image printed at poster size is still soft.

The fourth myth is that changing the DPI changes the image. It changes a number in the header, not a single pixel, and the image looks exactly the same on screen before and after.

Quick Reference: Which Number Matters Where

On the web, dimensions matter most. Match the pixel width to the display size, keep the file size low with compression, and ignore DPI entirely.

In print, dimensions and DPI matter together. Multiply your inches by 300 to get the pixels you need, then set the DPI tag to match.

For uploads and portals, file size matters most. A file that passes the pixel minimum can still be rejected for weighing too many kilobytes.

For a shared vocabulary with your team, remember the three definitions: dimensions are the pixel count, resolution is the packing density, and file size is the storage cost. For the hands-on tools, see the Image Dimensions Checker: Complete Guide and the steps in How to Check Image Dimensions.

Frequently asked questions

Does changing the DPI of an image change its dimensions?

No. DPI is metadata stored in the file header, and changing it does not add or remove any pixels. A 3000 by 2000 image stays 3000 by 2000 whether its DPI tag says 72 or 300. Only the print size changes, because print size is pixels divided by DPI.

Why is my image file so large even though its dimensions are small?

The format and compression decide the weight more than the dimensions do. A small photo saved as an uncompressed PNG can weigh megabytes, while the same pixels saved as a JPG weigh a fraction of that. Convert to JPG or WebP to shrink the file without changing the dimensions.

What dimensions do I need for a sharp A4 print?

An A4 page is about 8.3 by 11.7 inches, so at 300 DPI you need roughly 2500 by 3500 pixels. A smaller file can still print on A4, but the detail will soften as the printer stretches the available pixels across the page.

Is a 72 DPI image bad quality?

Not necessarily. DPI only matters for print, and a 72 DPI tag says nothing about the pixels themselves. A 4000-pixel image tagged at 72 DPI is a high-quality file with the wrong metadata. Change the DPI tag and the print size is fixed without touching a pixel.

How do dimensions affect page loading speed?

Larger dimensions usually mean larger files, and larger files take longer to download. But the relationship is not fixed: a big, heavily compressed image can load faster than a small, uncompressed one. Check both the dimensions and the file size when you optimize for speed.

Can I increase an image dimensions without losing quality?

Not really. Upscaling invents pixels that were never captured, so the result is always softer than a true high-resolution original. AI upscalers do a better job than simple resizing, but they still guess at detail. The best fix is always a larger original file.
