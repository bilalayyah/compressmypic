Bild in Base64 umwandeln: In 4 Schritten

Wandeln Sie ein Bild in vier Schritten in Base64 um: hochladen, Ausgabe wählen, dann kopieren oder herunterladen. Für PNG, JPG, SVG, GIF und ICO.

Sie brauchen ein Bild als Text: ein Logo für ein Stylesheet, ein Icon für eine E-Mail oder ein Bild für einen JSON-Payload. Die Umwandlung dauert etwa eine Minute, wenn man die Schritte kennt.

Diese Anleitung führt Sie in vier Schritten durch das Umwandeln eines Bildes in Base64: Datei hochladen, Ausgabeformat wählen, Zeichenfolge kopieren oder herunterladen und in Ihren Code einfügen.

Keine Software zu installieren, kein Konto anzulegen und nichts, was irgendwo hochgeladen wird. Das Bild wird von Anfang bis Ende lokal in Ihrem Browser kodiert.

Was Sie brauchen, bevor Sie starten

Sie brauchen die Bilddatei selbst, im PNG-, JPG-, WebP-, GIF-, SVG-, BMP- oder ICO-Format, bis zu 15 MB. Logos, Icons und kleine Fotos sind die üblichen Kandidaten.

Wissen Sie, wohin die Zeichenfolge geht. Eine HTML-Seite will eine Data-URL, ein Stylesheet will einen CSS-url()-Wert, und eine API will meist die reine Zeichenfolge ohne Präfix.

Wenn das Bild groß ist, ziehen Sie in Betracht, es zuerst zu verkleinern. Aus einem 2-MB-Foto wird eine 2,7-MB-Zeichenfolge, die umständlich zu kopieren und langsam zu parsen ist, während eine komprimierte Version ein Zehntel davon sein kann.

Ein Browser ist die einzige Software, die Sie brauchen. Das Tool läuft in Chrome, Safari, Firefox und Edge, auf Desktop und Handy, ohne Erweiterung.

Schritt 1: Bild hochladen oder Screenshot einfügen

Öffnen Sie den Base64-Umwandler und ziehen Sie Ihr Bild in den Upload-Bereich. Sie können auch auf den Bereich klicken, um eine Datei auf Ihrem Gerät auszuwählen.

Wenn das Bild gerade auf Ihrem Bildschirm zu sehen ist, kopieren Sie es und fügen Sie es mit Strg+V ein. Das Tool akzeptiert Bilder direkt aus der Zwischenablage, sodass ein Screenshot kodiert werden kann, ohne vorher eine Datei zu speichern.

Das Tool liest die Datei und zeigt eine Vorschau mit ihren Dimensionen und ihrem Format. Prüfen Sie, ob die Vorschau das beabsichtigte Bild ist, denn die Zeichenfolge, die Sie kopieren, wird genau diese Datei sein.

Wenn Sie die falsche Datei hochgeladen haben, kodieren Sie eine andere aus dem Tool heraus. Die vorherige Ausgabe wird ersetzt, und Sie können weiterarbeiten, ohne die Seite neu zu laden.

Schritt 2: Das Ausgabeformat wählen

Vier Tabs sitzen über dem Ausgabebereich: Data-URL, Reines Base64, HTML und CSS. Wählen Sie den, der dazu passt, wohin die Zeichenfolge geht.

Wählen Sie Data-URL, wenn Sie eine vollständige URI für eine Bildquelle oder einen Stylesheet-Hintergrund brauchen. Sie enthält Medientyp und Kodierungsmarkierung, sodass sie überall funktioniert, wo eine URL funktioniert.

Wählen Sie Reines Base64, wenn Sie das Bild an eine API senden oder in einer Datenbank speichern. Die reine Ausgabe ist die Zeichenfolge allein, ohne Präfix – die Form, die die meisten APIs erwarten.

Wählen Sie HTML, wenn Sie ein fertiges Bildelement wollen. Das Tool erzeugt das Tag mit der Data-URL als Quelle und füllt die Breiten- und Höhenattribute automatisch aus. Wählen Sie CSS, wenn Sie einen url()-Wert für einen Hintergrund oder eine Maske wollen.

Schritt 3: Die Ausgabe kopieren oder herunterladen

Klicken Sie auf die Schaltfläche „Ausgabe kopieren“, um die Zeichenfolge in Ihre Zwischenablage zu legen. Für kurze Zeichenfolgen wie Icons und Logos ist das alles, was Sie brauchen.

Für lange Zeichenfolgen nutzen Sie stattdessen die Download-Schaltfläche. Das Kopieren einer Zeichenfolge mit mehreren Megabyte kann langsam oder unzuverlässig sein, während eine heruntergeladene Textdatei die exakte Ausgabe ohne Kürzung trägt.

Wenn Ihr Browser den Zugriff auf die Zwischenablage blockiert, sagt Ihnen das Tool das. Erlauben Sie die Zwischenablagen-Berechtigung für die Seite oder nutzen Sie die Download-Schaltfläche als Ausweg, der gar keine Berechtigung braucht.

Prüfen Sie den Overhead-Prozentsatz, der neben der Ausgabe angezeigt wird. Er sagt Ihnen, um wie viel größer die Zeichenfolge ist als die Originaldatei – meist etwa 33 Prozent plus ein wenig für die Hülle.

Schritt 4: Die Zeichenfolge in Ihren Code einfügen

Fügen Sie die Ausgabe dort ein, wo sie hingehört: die Data-URL in eine Bildquelle oder ein Stylesheet, die reine Zeichenfolge in ein JSON-Feld, das HTML-Snippet in eine Seite oder den CSS-Wert in eine Hintergrundeigenschaft.

Testen Sie das Ergebnis sofort. Öffnen Sie die Seite, senden Sie die Test-E-Mail oder rufen Sie die API auf und bestätigen Sie, dass das Bild erscheint. Eine Zeichenfolge, die in das falsche Feld eingefügt wurde, scheitert still oder zeigt ein kaputtes Bild.

Behalten Sie die Originalbilddatei. Wenn die eingebettete Version je geändert werden muss, kodieren Sie sie erneut aus dem Original, statt die Zeichenfolge zu dekodieren und erneut zu kodieren.

Für ein Logo oder Icon sollten Sie das Snippet in Ihrem Projekt als wiederverwendbare Variable oder als Teilstück speichern. So lebt die lange Zeichenfolge an einem Ort, statt in jede Datei eingefügt zu werden, die sie braucht.

Ein SVG-Logo kodieren

SVG-Logos kodieren sauber, weil sie bereits Text sind. Laden Sie die SVG-Datei hoch, und das Tool erzeugt eine Base64-Zeichenfolge, die zurück in dieselbe Vektorgrafik dekodiert.

Die Data-URL für ein SVG beginnt mit data:image/svg+xml;base64, gefolgt von der Zeichenfolge. Fügen Sie sie in eine Bildquelle ein, und das Logo rendert in jeder Größe scharf.

Achten Sie trotzdem auf die Größe. Ein komplexes SVG mit vielen Pfaden kann groß sein, und seine Base64-Form ist noch einmal ein Drittel größer. Ein einfaches Logo ist in Ordnung; eine detaillierte Illustration ist als Datei verlinkt vielleicht besser.

Für sehr kleine SVGs ziehen Sie ein einfaches URL-kodiertes SVG statt Base64 in Betracht. Es ist kürzer, braucht aber sorgfältiges Escaping – Base64 bleibt also für die meisten Leute die sicherere Standardeinstellung.

Ein Favicon kodieren

Favicon-ICO-Dateien funktionieren im Umwandler genau wie jedes andere Format. Laden Sie die .ico-Datei hoch und kopieren Sie die Data-URL zur Verwendung in einer Ein-Datei-Seite oder einer E-Mail-Vorlage.

Die meisten Websites sollten das Favicon als Datei verlinken, statt es einzubetten. Ein verlinktes Favicon wird vom Browser gecacht, während ein eingebettetes mit jeder Seite heruntergeladen wird, die es enthält.

Einbetten ist sinnvoll für Ein-Datei-Seiten, Offline-Dokumente und E-Mail-Vorlagen, in denen keine separate Datei abgerufen werden kann. In diesen Kontexten ist das eingebettete Icon die einzige Möglichkeit, dass das Favicon überhaupt erscheint.

Wenn Sie noch kein Favicon haben, kann der Favicon-Generator eines aus jedem Bild erstellen – und dann können Sie das Ergebnis hier kodieren.

Bilder für HTML-E-Mails kodieren

HTML-E-Mails können sich nicht auf externe Bilddateien verlassen, weil viele Clients Remote-Bilder standardmäßig blockieren. Das Bild als Data-URL einzubetten, lässt es sofort erscheinen – selbst offline.

Halten Sie eingebettete E-Mail-Bilder klein. Ein Logo oder ein kleiner Banner funktioniert gut, doch ein großes Foto macht die Nachricht schwer und langsam zu öffnen auf einem Handy.

Testen Sie vor dem Senden. Manche E-Mail-Clients blockieren Inline-Base64-Bilder, und Ihre Nachricht kann bei diesen Lesern mit kaputten Bildern ankommen. Senden Sie einen Test an die Clients, die Ihr Publikum nutzt.

Wenn ein Client Base64 blockiert, fallen Sie auf ein gehostetes Bild mit einer normalen URL zurück. Das gehostete Bild braucht, dass der Leser Remote-Inhalte lädt, funktioniert aber in jedem Client, der es erlaubt.

Bilder für einen API-JSON-Payload kodieren

JSON kann keine binären Daten tragen, sodass Bild-Upload-Endpunkte, die JSON akzeptieren, das Bild als Base64-Zeichenfolge erwarten. Der Tab für reines Base64 liefert Ihnen genau diese Form.

Kopieren Sie die reine Zeichenfolge in das JSON-Feld, das die API dokumentiert, und senden Sie den Medientyp in einem separaten Feld, wenn die API danach fragt. Der Server dekodiert die Zeichenfolge und baut die Datei wieder zusammen.

Achten Sie auf die Payload-Größe. Aus einem 1-MB-Bild wird ein 1,4-MB-JSON-Feld, und manche APIs lehnen Payloads über einem Limit ab. Komprimieren Sie das Bild vor der Kodierung, wenn die API eine Größenobergrenze hat.

Testen Sie zuerst mit einem kleinen Bild. Ein erfolgreicher Round-Trip mit einem winzigen Icon beweist, dass Feldnamen und Format stimmen, bevor Sie ein großes Produktionsbild senden.

Ein Bild vor der Kodierung verkleinern

Ein großes Bild zu kodieren, erzeugt eine sehr lange Zeichenfolge, und lange Zeichenfolgen sind umständlich zu kopieren, langsam zu parsen und schwer zu speichern. Zuerst zu verkleinern, lohnt sich fast immer.

Komprimieren Sie das Bild mit dem Bild-Kompressor, bevor Sie es kodieren. Ein Foto, das von 2 MB auf 200 KB reduziert wird, erzeugt eine zehnmal kürzere Zeichenfolge – mit einem Qualitätsverlust, der meist unsichtbar ist.

Skalieren Sie auch, wenn die Anzeigegröße klein ist. Ein Icon, das mit 64 Pixeln gezeigt wird, braucht keine 2000-Pixel-Quelle, und die kleinere Quelle kodiert in eine deutlich kürzere Zeichenfolge.

Konvertieren Sie Fotos vor der Kodierung zu JPG, wenn Transparenz nicht gebraucht wird. JPG-Dateien sind für Fotografien deutlich kleiner als PNG, und die kleinere Datei bedeutet eine kürzere Zeichenfolge.

Fehlersuche bei Problemen mit der Zwischenablage

Wenn die Kopieren-Schaltfläche nichts tut, hat Ihr Browser vielleicht den Zugriff auf die Zwischenablage blockiert. Das Tool zeigt eine Meldung, die die Blockierung erklärt, und Sie können die Berechtigung für die Seite erlauben.

Manche Browser erlauben Zwischenablagen-Schreibzugriffe nur nach einer Nutzeraktion auf einer sicheren Seite. Das Klicken auf die Schaltfläche zählt als Aktion, doch ein alter Browser oder eine restriktive Einstellung kann trotzdem ablehnen.

Die Download-Schaltfläche ist der zuverlässige Ausweg. Sie speichert die exakte Ausgabe als Textdatei ohne jede Zwischenablage, und Sie können die Datei öffnen und von dort kopieren.

Auf dem Handy können lange Zeichenfolgen langsam zu kopieren sein. Laden Sie stattdessen die Ausgabedatei herunter und teilen Sie sie dann in die App, in der Sie sie brauchen, statt mit der Zwischenablage zu kämpfen.

Fehlersuche bei sehr langen Zeichenfolgen

Eine lange Zeichenfolge ist normal für ein großes Bild, kann Ihren Editor aber träge machen. Eine 2-MB-Zeichenfolge in eine Codedatei einzufügen, kann einen schlanken Editor für Sekunden einfrieren.

Teilen Sie die Arbeit auf: Speichern Sie die Zeichenfolge in einer separaten Datei oder Variablen und verweisen Sie von dem Code darauf, der sie braucht. So bleiben Ihre Hauptdateien lesbar und Ihr Editor reaktionsschnell.

Wenn die Zeichenfolge Ihren Build bricht, prüfen Sie auf Zeilenlängenlimits. Manche Tools umbrechen oder kürzen sehr lange Zeilen, was die Zeichenfolge beschädigt. Eine heruntergeladene Datei vermeidet dieses Problem vollständig.

Wenn eine Zeichenfolge sich zu lang anfühlt, um sie zu verwalten, überdenken Sie das Einbetten überhaupt. Eine verlinkte Bilddatei ist oft die bessere Wahl für alles über ein paar hundert Kilobyte.

Ein weiteres Bild nach dem ersten kodieren

Um ein zweites Bild zu kodieren, laden Sie es aus dem Tool hoch, ohne die Seite neu zu laden. Das neue Bild ersetzt das alte, und die Ausgabe aktualisiert sich auf die neue Zeichenfolge.

Kopieren Sie die erste Ausgabe, bevor Sie wechseln, denn das Ersetzen des Bildes löscht die vorherige Zeichenfolge. Eine heruntergeladene Datei ist der sicherste Nachweis, wenn Sie beide Zeichenfolgen brauchen.

Ein Set von Icons auf diese Weise durchzuarbeiten, geht schnell. Hochladen, kopieren, das nächste hochladen, wieder kopieren – und das ganze Icon-Set ist in wenigen Minuten kodiert.

Halten Sie die Originaldateien organisiert, während Sie arbeiten. Ein Ordner mit Quellbildern und ein passender Ordner mit Ausgabetextdateien verhindert die Verwechslungen, die passieren, wenn alle Zeichenfolgen gleich aussehen.

Bilder für Social Media und Messaging kodieren

Social-Media-Beiträge und Chatnachrichten akzeptieren Bilder manchmal nur als Text – besonders in Bots, Webhooks und automatisierten Workflows. Eine Base64-Zeichenfolge lässt ein Bild innerhalb eines reinen Text-Payloads reisen.

Halten Sie diese Bilder winzig. Eine Chat-API kann die Nachrichtengröße auf ein paar Dutzend Kilobyte begrenzen, und ein Foto, das in Base64 kodiert ist, sprengt dieses Limit, bevor es überhaupt ankommt.

Für Chatbots kodiert ein kleines Icon oder ein Thumbnail unter 10 KB in eine Zeichenfolge, die bequem in eine Nachricht passt. Alles Größere sollte als Datei hochgeladen und per URL referenziert werden.

Manche Automatisierungstools akzeptieren eine Data-URL dort, wo sie sonst ein gehostetes Bild bräuchten. Das ist nützlich, wenn das Bild spontan erzeugt wird und es noch keinen Ort gibt, an dem es gehostet wird.

Testen Sie den vollständigen Round-Trip, bevor Sie ihn automatisieren. Senden Sie eine Nachricht mit dem kodierten Bild, bestätigen Sie, dass es auf der Empfängerseite rendert, und bauen Sie erst dann den Workflow darum herum auf.

Denken Sie daran, dass die Zeichenfolge für jeden sichtbar ist, der den Nachrichten-Payload sehen kann. Kodieren Sie keine privaten Fotos in Nachrichten, Logs oder Webhooks, in denen der Text gespeichert oder weitergeleitet werden könnte.

Kurzanleitung als Checkliste

Laden Sie das Bild hoch, wählen Sie den Ausgabe-Tab für Ihr Ziel und kopieren oder laden Sie die Zeichenfolge herunter. Testen Sie sie an Ort und Stelle, bevor Sie etwas veröffentlichen, das davon abhängt.

Verkleinern Sie große Bilder vor der Kodierung, nutzen Sie reines Base64 für APIs und bevorzugen Sie eine verlinkte Datei gegenüber einer eingebetteten Zeichenfolge für alles Große oder Seitenübergreifende.

Den vollständigen Hintergrund finden Sie in Bild in Base64 umwandeln: Die komplette Anleitung, und den Entscheidungsrahmen in Base64-Bilder: Wann einbetten – und wann nicht. Um eine Zeichenfolge zurück in eine Datei zu dekodieren, nutzen Sie den Base64-Decoder.

Häufige Fragen

Kann ich auf meinem Handy ein Bild in Base64 umwandeln?

Ja. Der Umwandler läuft in mobilen Browsern auf iOS und Android. Laden Sie das Bild aus Ihrer Galerie hoch, wählen Sie den Ausgabe-Tab und kopieren Sie die Zeichenfolge. Für sehr lange Zeichenfolgen laden Sie stattdessen die Ausgabedatei herunter, da mobile Zwischenablagen mit großem Text Schwierigkeiten haben können.

Warum fügt der HTML-Tab Breite und Höhe zum Bild-Tag hinzu?

Der Browser braucht die Dimensionen, um Platz zu reservieren, bevor das Bild dekodiert. Ohne sie verschiebt sich das Seitenlayout, wenn das Bild erscheint – das schadet dem Leseerlebnis und dem Layout-Shift-Wert. Das Tool füllt die Attribute automatisch aus den Bilddimensionen aus.

Soll ich für mein Website-Logo Base64 oder eine normale Bilddatei verwenden?

Für ein Logo, das auf vielen Seiten erscheint, ist eine normale verlinkte Datei meist besser, weil der Browser sie einmal cacht. Base64 gewinnt, wenn die Seite eine einzige Datei sein muss, wenn das Logo winzig ist oder wenn keine separate Anfrage erlaubt ist. Für die meisten Websites verlinken Sie das Logo.

Was ist der Unterschied zwischen einer Data-URL und reinem Base64?

Eine Data-URL ist die vollständige URI mit dem data-Präfix, Medientyp und Kodierungsmarkierung – fertig zur Verwendung als Bildquelle. Reines Base64 ist die Zeichenfolge allein, ohne Präfix – die Form, die APIs und Datenbanken meist erwarten. Das Tool erzeugt beide aus demselben Bild.

Entfernt das Umwandeln in Base64 Metadaten aus meinem Bild?

Die Kodierung selbst entfernt nichts, denn die Zeichenfolge trägt die exakten Originalbytes. Manche Workflows entfernen Metadaten jedoch vor der Kodierung, um die Zeichenfolge kürzer zu halten. Wenn Datenschutz wichtig ist, entfernen Sie die Metadaten zuerst mit dem Tool zum Entfernen von Metadaten und kodieren Sie dann die saubere Datei.

Kann ich einen Screenshot direkt kodieren, ohne eine Datei zu speichern?

Ja. Kopieren Sie den Screenshot und drücken Sie Strg+V im Tool, und er wird sofort kodiert. Das ist der schnellste Weg, eine Data-URL für eine Bildschirmaufnahme, ein UI-Element oder ein Diagramm zu erhalten, das Sie gerade ansehen.
