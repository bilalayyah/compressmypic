Bildoptimierung für Core Web Vitals

Wie Bildoptimierung die Core Web Vitals verbessert: LCP, CLS und INP erklärt, mit praktischen Lösungen für langsame Seiten.

Core Web Vitals sind die Geschwindigkeitswerte, mit denen Google Ihre Seiten beurteilt. Sie messen, wie schnell der größte Inhalt erscheint, wie stabil das Layout ist und wie schnell die Seite reagiert.

Bilder beeinflussen alle drei Werte. Ein schweres Titelbild verzögert den größten Paint, eine fehlende Breite verursacht Layoutverschiebung, und eine aufgeblähte Seite verlangsamt die Interaktion.

Dieser Artikel erklärt, wie Bildoptimierung jeden Wert bewegt und was man zuerst auf einer langsamen Seite beheben sollte.

Was sind Core Web Vitals?

Core Web Vitals sind drei Kennzahlen, die das Nutzererlebnis beim Laden einer Seite beschreiben. Sie werden an echten Besuchern gemessen, nicht im Labor.

Largest Contentful Paint, kurz LCP, misst, wie lange das größte sichtbare Element braucht, um zu erscheinen. Auf den meisten Seiten ist dieses Element ein Bild.

Cumulative Layout Shift, kurz CLS, misst, wie stark sich die Seite beim Laden bewegt. Bilder ohne Abmessungen sind die häufigste Ursache.

Interaction to Next Paint, kurz INP, misst, wie schnell die Seite auf Klicks und Tippen reagiert. Schwere Seiten mit vielen großen Bildern reagieren langsamer.

Google nutzt diese Werte in den Suchrankings. Schnellere Seiten ranken besser, und Bildoptimierung ist der größte einzelne Hebel, den die meisten Websites haben.

LCP: Warum das Titelbild ihn entscheidet

Der LCP wird meist vom Titelbild entschieden. Es ist das größte Element auf dem Bildschirm, die Seite gilt also erst als geladen, wenn es erscheint.

Ein 5-MB-Titelbild kann bei mobiler Verbindung Sekunden zum Herunterladen brauchen. Während dieser Sekunden sieht der Besucher eine leere Stelle, wo das Titelbild hingehört.

Das Titelbild auf ein paar hundert Kilobyte zu komprimieren, verkürzt diese Wartezeit stark. Das Bild erscheint früher, und der LCP-Wert verbessert sich sofort.

Auch Abmessungen spielen eine Rolle. Ein Titelbild, das mit doppelter Anzeigegröße geliefert wird, verschwendet Bandbreite für Pixel, die niemand sieht, und verzögert den Paint weiter.

Auch das Vorladen des Titelbilds hilft. Dem Browser früh das wichtigste Bild zu nennen, lässt ihn vor allem anderen mit dem Herunterladen beginnen.

Einen langsamen LCP Schritt für Schritt beheben

Finden Sie zuerst das LCP-Element. Geschwindigkeitstools nennen es direkt, und es ist meist das Titelbild oder ein großes Banner.

Optimieren Sie dieses Bild als Zweites mit dem Optimierer für Webbilder. Verwenden Sie die Titelbild-Voreinstellung, die es richtig dimensioniert und die Qualität hoch hält.

Stellen Sie als Drittes sicher, dass Lazy Loading für das Titelbild ausgeschaltet ist. Das wichtigste Bild zu verzögern, ist der häufigste LCP-Fehler.

Laden Sie als Viertes das Titelbild im Seitenkopf vor. Der Browser holt es dann zuerst, bevor Stylesheets und Skripte um Bandbreite konkurrieren.

Testen Sie als Fünftes die Seite erneut. Die LCP-Zeit sollte stark gefallen sein, oft um mehrere Sekunden auf dem Handy.

CLS: Wie Bilder das Layout verschieben

CLS misst unerwartete Bewegung. Wenn ein Bild spät ohne reservierten Platz lädt, springt der Text darunter nach unten, und der Besucher verliert seine Stelle.

Die Lösung ist einfach: Fügen Sie immer Breite und Höhe in den img-Tag ein. Der Browser reserviert dann den Platz, bevor das Bild ankommt.

Der Button „Bild-Tag kopieren“ des Optimierers fügt diese Abmessungen automatisch ein. Den Tag wie angegeben einzufügen, verhindert die Verschiebung vollständig.

Auch das Seitenverhältnis spielt eine Rolle. Ein Bild mit falschem Verhältnis verzerrt sich, wenn es seinen reservierten Platz füllt, was selbst ohne Verschiebung defekt aussieht.

Prüfen Sie die Seite, indem Sie sie frisch laden und auf Bewegung achten. Jeder Sprung, den Sie sehen, ist ein CLS-Problem, das darauf wartet, Ihrem Wert zu schaden.

INP: Wie Bildgewicht die Interaktion verlangsamt

INP misst die Reaktionsfähigkeit. Wenn ein Besucher auf einen Button tippt, sollte die Seite schnell reagieren, und schwere Seiten reagieren langsam.

Bilder beeinflussen INP indirekt. Eine Seite mit Megabyte an Bildern hält den Browser mit Herunterladen und Dekodieren beschäftigt, was seine Reaktion auf Tippen verzögert.

Lazy Loading hilft hier. Bilder unter dem Falz müssen nicht heruntergeladen werden, bevor die Seite interaktiv wird – sie zu verschieben, entlastet den Browser.

Auch das Dekodieren großer Bilder kostet Zeit. Ein übergroßes Bild braucht länger zum Dekodieren als ein richtig dimensioniertes, selbst nach dem Herunterladen.

Die Lösung ist dieselbe wie beim LCP: Jedes Bild richtig dimensionieren, die unter dem Falz per Lazy Loading laden und das Gesamtgewicht der Seite niedrig halten.

Core Web Vitals richtig messen

Messen Sie auf echten Geräten, nicht nur mit einer schnellen Büroverbindung. Die meisten Besucher stöbern auf Handys, und mobile Werte sind es, die zählen.

Verwenden Sie die kostenlosen Geschwindigkeitstools, um eine Basislinie zu erhalten. Notieren Sie die LCP-, CLS- und INP-Zahlen, bevor Sie etwas ändern.

Ändern Sie eine Sache nach der anderen. Das Titelbild zu optimieren und dann erneut zu testen, sagt Ihnen genau, wie viel das Titelbild gekostet hat.

Testen Sie nach jeder Runde von Korrekturen erneut. Werte bewegen sich in Schritten, und jeder Schritt zeigt, ob die letzte Änderung geholfen hat.

Denken Sie daran, dass Werte je nach Besucher variieren. Ein einzelner Test ist eine Momentaufnahme; mehrere Tests über Tage hinweg geben das echte Bild.

Ein Bildbudget für eine Seite festlegen

Ein Bildbudget begrenzt das Gesamtgewicht der Bilder auf einer Seite. Ein übliches Budget ist 1 MB für eine Inhaltsseite und 2 MB für eine Galerie.

Teilen Sie das Budget durch die Anzahl der Bilder. Zehn Bilder, die sich ein 1-MB-Budget teilen, bekommen jeweils 100 KB, was ein vernünftiges Ziel ist.

Geben Sie dem Titelbild einen größeren Anteil. Es verdient 300 KB oder 400 KB, während unterstützende Bilder jeweils 100 KB bekommen.

Setzen Sie das Budget in Ihrem Veröffentlichungsablauf durch. Eine Checkliste mit Bildgewicht verhindert, dass schwere Bilder die Live-Website erreichen.

Prüfen Sie das Budget, wenn sich das Design ändert. Ein neues Theme mit größeren Bildern braucht ein größeres Budget oder kleinere Bilder dazu.

Formate und Core Web Vitals

WebP ist das beste Format für Core Web Vitals. Es ist kleiner als JPG bei gleicher Qualität, was dem LCP direkt hilft.

Moderne Browser unterstützen alle WebP. Das Format ist für Mainstream-Websites kein Risiko mehr, und der Geschwindigkeitsgewinn ist real.

JPG bleibt der Fallback für ältere Systeme. Wenn Kompatibilität wichtiger ist als Geschwindigkeit, ist JPG die sichere Wahl.

PNG schadet Core Web Vitals bei Fotos. Seine großen Dateien verzögern den LCP und blähen die Seite auf, reservieren Sie PNG also nur für Grafiken.

Liefern Sie das kleinste Format, das der Browser des Besuchers unterstützt. Diese eine Regel erfasst den größten Teil des Formatnutzens, den es gibt.

Responsive Bilder und Auflösungswechsel

Responsive Bilder liefern unterschiedliche Größen an unterschiedliche Bildschirme. Ein Handy bekommt eine kleine Datei, während ein Desktop eine größere bekommt.

Das HTML-Attribut srcset listet die verfügbaren Größen auf, und der Browser wählt die richtige für den Bildschirm, auf dem er läuft.

Das ist wichtig für den LCP auf dem Handy. Ein Handy, das ein Titelbild in Desktop-Größe herunterlädt, verschwendet Sekunden mit Pixeln, die sein kleiner Bildschirm nicht zeigen kann.

Erzeugen Sie zwei oder drei Größen pro Bild: eine Handygröße, eine Tabletgröße und eine Desktopgröße. Die Voreinstellungen des Optimierers erzeugen jede mit einem Klick.

Testen Sie nach dem Hinzufügen responsiver Bilder auf einem echten Handy. Die LCP-Verbesserung auf dem Handy ist oft dramatisch.

Häufige Core-Web-Vitals-Fehler

Das Titelbild per Lazy Loading zu laden, ist der häufigste Fehler. Es verzögert das LCP-Element und garantiert einen schlechten Wert.

Fehlende Breite und Höhe sind der zweite. Bilder ohne Abmessungen verschieben das Layout und schädigen den CLS-Wert.

Übergroße Bilder zu liefern, ist der dritte. Ein 4000-Pixel-Bild, das mit 800 Pixeln angezeigt wird, verschwendet Bandbreite und verzögert den Paint.

Bilder unter dem Falz zu vergessen, ist der vierte. Eine Seite kann ein schnelles Titelbild haben und trotzdem insgesamt langsam sein, wenn zwanzig nicht optimierte Thumbnails folgen.

Diese vier Fehler zu beheben, löst die meisten bildbezogenen Core-Web-Vitals-Probleme. Sie sind einfach, und sie funktionieren.

Was zuerst beheben: Eine Prioritätenreihenfolge

Beheben Sie zuerst das LCP-Bild. Es hat den größten einzelnen Effekt auf den Wert und auf den ersten Eindruck des Besuchers.

Beheben Sie als Zweites fehlende Abmessungen. Breite und Höhe zu jedem img-Tag hinzuzufügen, geht schnell und beseitigt Layoutverschiebungen.

Beheben Sie als Drittes das Gesamtgewicht. Laden Sie Bilder unter dem Falz per Lazy Loading und komprimieren Sie den Rest, um die Seite unter ihr Budget zu bringen.

Beheben Sie als Viertes die Responsivität. Responsive Bilder helfen mobilen Besuchern am meisten, und mobile Werte zählen am meisten.

Testen Sie nach jedem Schritt erneut. Die Werte sagen Ihnen, wann die Seite gut genug ist und wann mehr Arbeit nötig ist.

Felddaten vs. Labordaten

Core Web Vitals gibt es in zwei Arten: Labordaten aus einem einzelnen Test und Felddaten von echten Besuchern über Wochen hinweg.

Labordaten sind sofort und wiederholbar. Sie sagen Ihnen, wie die Seite bei schneller Verbindung in einem kontrollierten Test abschneidet.

Felddaten sind langsamer, aber ehrlich. Sie spiegeln echte Besucher auf echten Handys mit echten Verbindungen wider, einschließlich der langsamen.

Google rankt nach Felddaten. Eine Seite, die im Labor gut, im Feld aber schlecht abschneidet, rankt trotzdem schlecht.

Verwenden Sie Labordaten, um Probleme zu finden, und Felddaten, um Korrekturen zu bestätigen. Die beiden gemeinsam geben das vollständige Bild Ihrer Seitengeschwindigkeit.

Wenn das LCP-Element kein Bild ist

Manchmal ist der größte Paint ein Textblock, kein Bild. In diesem Fall hilft Bildoptimierung weniger, und Schriften und Stylesheets zählen mehr.

Prüfen Sie, was das Geschwindigkeitstool als LCP-Element nennt. Wenn es Text ist, schauen Sie sich das Laden von Schriften und renderblockierende Styles an.

Bilder können trotzdem einen Text-LCP verzögern. Ein schweres Hintergrundbild oder ein langsam ladendes Logo kann die ganze Seite aufhalten.

Optimieren Sie die Bilder trotzdem. Eine leichtere Seite hilft jeder Kennzahl, selbst wenn das LCP-Element selbst Text ist.

Optimieren Sie nicht blind. Zu wissen, welches Element den Wert treibt, sagt Ihnen, wo Sie Ihre Mühe investieren sollten.

CLS jenseits von Bildern: Schriften und Anzeigen

Bilder sind die häufigste CLS-Ursache, aber nicht die einzige. Webschriften und Anzeigen verschieben ebenfalls das Layout, während sie laden.

Schriften verschieben Text, wenn sie sich austauschen. font-display swap mit einem nahen Fallback zu verwenden, verringert den sichtbaren Sprung.

Anzeigen verschieben Inhalte, wenn sie spät laden. Platz für Anzeigenplätze zu reservieren, verhindert, dass die Seite springt, wenn die Anzeige ankommt.

Beheben Sie zuerst Bilder, da sie der einfachste Gewinn sind. Schauen Sie sich dann Schriften und Anzeigen an, wenn der CLS-Wert immer noch schlecht ist.

Eine Seite ohne Layoutverschiebung wirkt ruhig und professionell. Besucher bemerken die Stabilität, selbst wenn sie sie nicht benennen können.

INP und schwere Skripte

Bilder sind selten das Haupt-INP-Problem. Schweres JavaScript ist meist die größere Ursache langsamer Interaktion.

Trotzdem hilft Bildarbeit dem INP. Eine leichtere Seite lässt dem Browser mehr Zeit, auf Tippen und Klicks zu reagieren.

Auch Dekodierungskosten zählen. Ein übergroßes Bild braucht länger zum Dekodieren als ein richtig dimensioniertes, und das Dekodieren blockiert die Interaktion.

Halten Sie Drittanbieter-Skripte schlank. Analytics, Chat-Widgets und soziale Einbettungen konkurrieren alle mit Ihrer Seite um die Aufmerksamkeit des Browsers.

Sehen Sie INP als Budget. Jedes Skript und jedes Bild gibt davon aus, und die Seite muss reagieren, bevor das Budget aufgebraucht ist.

Mobile First: Warum Handynoten am meisten zählen

Die meisten Besucher stöbern auf Handys, und Google rankt nach mobilen Werten. Eine Seite, die auf dem Desktop schnell, auf dem Handy aber langsam ist, rankt schlecht.

Handys haben langsamere Verbindungen und schwächere Prozessoren. Dasselbe Titelbild braucht auf einem Handy länger zum Herunterladen und Dekodieren als auf einem Laptop.

Optimieren Sie zuerst fürs Handy. Eine Seite, die auf dem Handy schnell ist, ist überall schnell, während das Umgekehrte nicht gilt.

Testen Sie auf einem echten Handy, nicht nur in einem Desktop-Simulator. Der Simulator verbirgt die reale Langsamkeit, die Besucher tatsächlich spüren.

Mobile-First-Optimierung ist kein Trend. So funktioniert das Web jetzt, und die Werte spiegeln es wider.

Laufende Überwachung der Core Web Vitals

Core Web Vitals ändern sich im Laufe der Zeit. Neue Bilder, neue Plugins und neue Themes können die Werte still schädigen.

Prüfen Sie die Werte mindestens monatlich. Eine regelmäßige Prüfung entdeckt Probleme, bevor sie Rankings beeinflussen.

Richten Sie Warnungen ein, wenn Ihre Plattform sie unterstützt. Eine Warnung, wenn der LCP die Schwelle überschreitet, spart Wochen langsamer Rankings.

Prüfen Sie die Werte nach jedem Redesign. Ein neues Theme verändert jeden Bildplatz, und die alten Optimierungen passen vielleicht nicht mehr.

Geschwindigkeit ist eine Gewohnheit, kein Projekt. Die Websites, die schnell bleiben, sind die, die weiter zusehen.

Eine letzte Prüfung vor der Veröffentlichung

Lassen Sie das Geschwindigkeitstool ein letztes Mal laufen, nachdem alle Korrekturen fertig sind. Vergewissern Sie sich, dass LCP, CLS und INP alle im grünen Bereich liegen, bevor Sie weitermachen.

Laden Sie die Seite auf einem echten Handy über eine mobile Verbindung. Die Zahlen in einem Labortest sind nützlich, aber das Gefühl auf einem Handy ist die Wahrheit.

Häufige Fragen

Was ist ein guter LCP-Wert?

Google betrachtet einen LCP unter 2,5 Sekunden als gut. Die meisten Seiten verfehlen dieses Ziel wegen eines schweren Titelbilds. Das Titelbild zu komprimieren, es in der richtigen Größe zu liefern und es vorzuladen, sind die schnellsten Wege, unter die Schwelle zu kommen.

Wie verursachen Bilder Layoutverschiebungen?

Wenn ein Bild ohne Breiten- und Höhenattribute lädt, weiß der Browser nicht, wie viel Platz er reservieren soll. Das Bild kommt spät an und drückt den Inhalt darunter nach unten, was als Layoutverschiebung zählt. Abmessungen im Tag einzufügen, verhindert das.

Verbessert Lazy Loading die Core Web Vitals?

Ja, bei Bildern unter dem Falz. Sie zu verschieben, gibt Bandbreite für das Titelbild frei und macht die Seite früher interaktiv. Laden Sie Titelbild oder Logo nie per Lazy Loading, denn sie zu verzögern, schadet dem LCP direkt.

Warum ist mein mobiler LCP-Wert schlechter als der Desktop-Wert?

Mobile Verbindungen sind langsamer und Handyprozessoren schwächer, dasselbe Titelbild braucht also länger zum Herunterladen und Dekodieren. Das Titelbild zu optimieren, eine kleinere mobile Version zu liefern und es vorzuladen, schließt den größten Teil der Lücke.

Kann Bildoptimierung allein einen schlechten Core-Web-Vitals-Wert beheben?

Oft ja, wenn Bilder das Hauptproblem sind. Eine Seite mit 5 MB Bildern verbessert sich dramatisch, sobald sie optimiert sind. Wenn der Wert schlecht bleibt, liegt das Problem vielleicht bei langsamem Hosting, schweren Skripten oder renderblockierenden Stylesheets.

Wie oft sollte ich die Core Web Vitals erneut prüfen?

Nach jeder Designänderung und mindestens einmal im Monat. Neue Bilder, neue Themes und neue Plugins können die Werte still schädigen. Eine monatliche Prüfung entdeckt Probleme, bevor sie Rankings beeinflussen.
