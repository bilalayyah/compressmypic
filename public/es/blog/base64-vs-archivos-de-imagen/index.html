Base64 vs archivos de imagen: rendimiento

Las cadenas Base64 y los archivos de imagen llevan la misma foto de formas distintas. Compare tamaño, velocidad, caché y edición.

Cada imagen en la web existe en una de dos formas: como un archivo con un nombre y una URL, o como una cadena Base64 incrustada en el código. Ambas llevan los mismos píxeles, pero se comportan de forma muy distinta.

Elegir la forma equivocada cuesta rendimiento, desperdicia ancho de banda o convierte una actualización simple en una tarea dolorosa. Elegir la forma correcta es sobre todo cuestión de saber en qué es bueno cada uno.

Este artículo compara las cadenas Base64 y los archivos de imagen cara a cara: tamaño, velocidad, caché, edición y los casos de uso en los que cada uno gana con claridad.

Dos maneras de guardar la misma imagen

Un archivo de imagen son datos binarios con un nombre, un formato y una ubicación. Un navegador lo busca con una solicitud, lo guarda en caché y lo muestra cada vez que la página lo referencia.

Una cadena Base64 son los mismos datos binarios reescritos como texto. Vive dentro de HTML, CSS, JSON o una base de datos, y el navegador la decodifica en el acto sin ninguna solicitud.

Los píxeles son idénticos en ambas formas. Un archivo PNG y su cadena Base64 se decodifican en los mismos bytes, las mismas dimensiones y la misma foto.

Todo lo demás difiere: el tamaño, la velocidad, el caché, la edición y las herramientas. Esas diferencias son de lo que trata esta comparación.

Tamaño: la brecha del 33 por ciento

Una cadena Base64 es unos 33 por ciento más grande que el archivo que codifica. Una imagen de 90 KB se convierte en una cadena de 120 KB, y una foto de 1 MB se convierte en una cadena de 1,4 MB.

La brecha es una propiedad fija de la codificación. Cuatro caracteres de texto llevan tres bytes de datos, así que la cadena siempre necesita un tercio más de caracteres que los bytes que tiene el archivo.

Para las imágenes pequeñas, la brecha es insignificante. Un ícono de 3 KB se convierte en una cadena de 4 KB, y nadie mide un solo kilobyte. Para las imágenes grandes, la brecha domina la decisión.

El tamaño de archivo también importa para el almacenamiento. Una base de datos llena de imágenes Base64 es un tercio más grande que las mismas imágenes guardadas como archivos, y ese costo se repite en cada copia de seguridad.

Rendimiento: velocidad de carga

Una imagen enlazada cuesta una solicitud pero se muestra de forma progresiva. El navegador muestra primero el texto y completa la imagen cuando llega, así que la página se siente rápida incluso en una conexión lenta.

Una imagen Base64 incrustada no cuesta ninguna solicitud pero bloquea la visualización. El navegador debe descargar todo el documento HTML, incluida la cadena, antes de poder mostrar nada.

Para una página con un ícono pequeño, incrustar es más rápido. La solicitud ahorrada supera los bytes extra, y el ícono aparece con la primera pintura.

Para una página con muchas imágenes o imágenes grandes, enlazar es más rápido. El texto se muestra de inmediato, las imágenes llegan en flujo y el navegador puede priorizar lo que el lector ve primero.

Caché: la diferencia decisiva

El caché es donde los archivos de imagen ganan de forma decisiva. Un archivo enlazado se descarga una vez y se reutiliza en cada página que lo referencia, durante el tiempo que permitan los encabezados de caché.

Una cadena Base64 se descarga de nuevo con cada página que la contiene. Un logotipo incrustado en cincuenta páginas cuesta cincuenta descargas, mientras que el mismo logotipo enlazado cuesta una.

Esta es la razón más grande para preferir los archivos para las imágenes compartidas. El extra del 33 por ciento es un costo único, pero la pérdida de caché se repite en cada vista de página.

Para los documentos de una sola página, los correos y los archivos sin conexión, el caché no aplica y el argumento desaparece. Por eso incrustar es la práctica estándar en exactamente esos contextos.

Portabilidad: mover imágenes

Las cadenas Base64 viajan dentro del texto, lo que las hace portables de formas en que los archivos no lo son. Una cadena se puede pegar en un mensaje de chat, guardar en una fila de base de datos o incrustar en un JSON.

Los archivos de imagen necesitan una ubicación: una URL, una carpeta o un adjunto. Mover un archivo significa mover también la referencia, y una referencia rota produce una imagen rota.

Las API son el caso más claro para las cadenas. JSON no puede llevar datos binarios, así que cualquier imagen que viaje dentro de un JSON debe ser Base64, y no hay alternativa basada en archivos.

Para los sitios web, los archivos son más portables en la práctica. Un archivo se puede referenciar desde cualquier página, cualquier hoja de estilos y cualquier correo, mientras que una cadena debe copiarse en cada lugar por separado.

Edición y control de versiones

Actualizar una imagen enlazada es un intercambio de archivo. Reemplace el archivo, conserve el nombre, y cada página que lo referencia muestra la versión nueva de inmediato.

Actualizar una imagen incrustada significa encontrar la cadena, reemplazar un muro de texto y esperar haber reemplazado la correcta. El código cambia aunque la lógica no haya cambiado.

El control de versiones sufre con las cadenas. Un cambio de imagen de una línea se convierte en una diferencia de mil líneas, lo que ahoga los cambios reales de código y hace dolorosas las revisiones.

Los archivos se versionan sin problema. Una imagen cambiada es un archivo binario cambiado, la diferencia es una sola línea y el historial muestra exactamente cuándo cambió la foto y qué reemplazó.

Búsqueda, accesibilidad y uso compartido

Los motores de búsqueda indexan los archivos de imagen enlazados y los muestran en la búsqueda de imágenes. Una imagen Base64 incrustada es en gran parte invisible para ese sistema, así que no trae tráfico de búsqueda de imágenes.

Los lectores de pantalla y las herramientas de accesibilidad funcionan con ambas formas, pero solo cuando el marcado es correcto. Un elemento de imagen necesita un atributo alt tanto si su fuente es un archivo como si es una cadena.

Los lectores pueden hacer clic derecho en una imagen enlazada y guardarla, compartirla o abrirla en una pestaña nueva. Una imagen incrustada ofrece el mismo menú en la mayoría de los navegadores, pero el archivo guardado tiene un nombre generado y sin contexto.

Las vistas previas para compartir en redes sociales también prefieren archivos. Una página que depende de imágenes incrustadas puede no mostrar ninguna miniatura de vista previa cuando se comparte, porque el rastreador no puede extraer una con facilidad.

API y transferencia de datos

Las API que aceptan JSON esperan las imágenes como cadenas Base64, porque JSON no tiene un tipo binario. La cadena viaja en un campo, el servidor la decodifica y el archivo se reconstruye del otro lado.

Las subidas multipart son la alternativa basada en archivos, y son más eficientes para las imágenes grandes. Una solicitud multipart envía el binario directamente, sin el extra del 33 por ciento.

Elija Base64 para las imágenes pequeñas en flujos JSON, como avatares, firmas y miniaturas. Elija la subida multipart para las imágenes grandes, donde el extra se mediría en megabytes.

Las bases de datos siguen la misma lógica. Las imágenes pequeñas guardadas como texto son convenientes, mientras que las imágenes grandes pertenecen al almacenamiento de objetos con una referencia en la base de datos.

Correo: las cadenas ganan en pequeño, los archivos ganan en grande

Los correos son mensajes únicos, así que una imagen incrustada viaja con el texto y se muestra incluso cuando el lector está sin conexión. Esa es una ventaja real sobre una imagen enlazada que puede estar bloqueada.

Las imágenes pequeñas se incrustan bien en el correo: logotipos, íconos y banners pequeños de menos de 10 KB. Hacen que el mensaje sea reconocible en el momento en que se abre.

Las fotografías grandes deberían mantenerse enlazadas o dejarse fuera. Una foto incrustada pesada hace que el mensaje sea lento de abrir, y algunos servidores de correo rechazan mensajes por encima de un límite de tamaño.

Pruebe en los clientes que usa su público. Algunos bloquean por completo las imágenes Base64 en línea, lo que hace que todo el esfuerzo de incrustación no tenga sentido para esos lectores.

Consideraciones de seguridad

Una cadena Base64 oculta su contenido de una inspección casual. Un revisor que escanea el código no puede ver lo que muestra la imagen sin decodificarla, lo que hace más difícil la revisión de seguridad.

Los encabezados de política de seguridad de contenido pueden bloquear las URL de datos. Una política estricta que permite imágenes solo desde su propio dominio rechazará una imagen incrustada a menos que se permita data: de forma explícita.

Los archivos de imagen son más fáciles de auditar. Un archivo se puede escanear, hashear y verificar contra una lista de contenido conocido, mientras que una cadena debe decodificarse primero antes de que cualquiera de eso sea posible.

Nunca decodifique una cadena de una fuente no confiable y sirva el resultado a ciegas. Valide los bytes decodificados como una imagen real antes de guardarlos o mostrarlos.

Cuándo ganan con claridad los archivos de imagen

Los archivos de imagen ganan para las fotografías, para los logotipos de todo el sitio y para cualquier cosa de más de 50 KB. El ahorro de caché y la velocidad de visualización superan por mucho el ahorro de solicitudes.

Los archivos ganan para las imágenes que cambian. Un intercambio de archivo actualiza cada referencia a la vez, mientras que una actualización de cadena significa editar cada archivo que contiene la copia incrustada.

Los archivos ganan para las imágenes que necesitan encontrarse. Los motores de búsqueda, las vistas previas sociales y la búsqueda de imágenes funcionan mejor con archivos enlazados que con cadenas incrustadas.

Los archivos ganan para los equipos. Un diseñador puede reemplazar un archivo sin tocar el código, un desarrollador puede revisar el cambio sin problema y el historial de versiones se mantiene legible.

Cuándo ganan con claridad las cadenas Base64

Las cadenas ganan para los documentos de un solo archivo que deben funcionar sin conexión. Un informe HTML, una página web guardada o un correo no pueden buscar archivos externos, así que incrustar es la única opción.

Las cadenas ganan para los íconos diminutos de menos de 2 KB. El extra es menos de un kilobyte, la solicitud ahorrada es real y la pérdida de caché es insignificante para una imagen tan pequeña.

Las cadenas ganan para las cargas JSON y los campos de base de datos. Los sistemas basados en texto no pueden llevar datos binarios, así que Base64 es la forma estándar de mover una imagen a través de ellos.

Las cadenas ganan para las imágenes generadas sin hogar. Una imagen creada al momento por un script se puede incrustar de inmediato, sin guardarla primero en un servidor y obtener una URL.

El enfoque híbrido

La mayoría de los proyectos reales usan ambas formas. Los íconos pequeños se incrustan, las fotografías se enlazan y las cargas de API llevan Base64 mientras el sitio web sirve archivos.

La regla híbrida es simple: incruste lo que sea pequeño y esencial, enlace lo que sea grande o compartido, y use cadenas donde el transporte sea basado en texto.

Documente la elección por tipo de imagen, no por imagen. Una regla como «los íconos de menos de 5 KB se incrustan, todo lo demás se enlaza» es fácil de seguir y fácil de auditar.

Revise la regla cuando el proyecto cambie. Una página de destino que crece hasta convertirse en un sitio completo puede necesitar que su logotipo incrustado se convierta de vuelta a un archivo enlazado.

Cómo migrar entre las dos formas

Pasar de cadenas a archivos es sencillo. Decodifique la cadena con el decodificador de Base64 a imagen, guarde el archivo, súbalo y reemplace la cadena con la URL.

Pasar de archivos a cadenas es igual de fácil. Codifique el archivo con el codificador de imagen a Base64, copie la salida y péguela donde estaba la URL.

Haga la migración un tipo de imagen a la vez, y mida antes y después. Una migración que hace el sitio más lento es una migración que vale la pena revertir.

Conserve los originales durante el cambio. Un archivo decodificado y su cadena fuente deberían existir ambos hasta que la versión nueva esté probada y confirmada.

Costo: ancho de banda y almacenamiento

El ancho de banda es el costo más concreto de la elección Base64. Una página con 1 MB de imágenes incrustadas transfiere unos 1,33 MB de datos de imagen, mientras que las mismas imágenes enlazadas transfieren 1 MB, y esa diferencia se repite en cada vista de página.

En una conexión móvil medida, el tercio extra es dinero real para el lector. Un sitio que incrusta mucho puede costarles a sus visitantes móviles notablemente más datos que el mismo sitio con imágenes enlazadas.

El almacenamiento sigue la misma proporción. Una base de datos que guarda 10 GB de imágenes como Base64 guarda 13,3 GB de texto, y cada copia de seguridad, replicación y migración lleva el peso extra.

El almacenamiento de objetos es más barato que el almacenamiento de base de datos para las imágenes, que es otra razón por la que las imágenes grandes pertenecen a los archivos. Una referencia en la base de datos cuesta unas pocas docenas de caracteres, mientras que la imagen en sí vive donde el almacenamiento es barato.

El cómputo es el costo más pequeño. Codificar y decodificar son operaciones rápidas, y el tiempo de CPU es insignificante junto a los costos de red y almacenamiento, así que las discusiones de rendimiento deberían centrarse en los bytes, no en los ciclos.

Cuando usted estime el costo de incrustar, multiplique por la cantidad de vistas de página. Un extra de 100 KB que parece trivial en una visita se convierte en 10 GB de transferencia extra en cien mil visitas.

Referencia rápida: cadenas o archivos

Use archivos de imagen para fotografías, logotipos compartidos, imágenes grandes y cualquier cosa que necesite caché, indexación en búsqueda o actualizaciones frecuentes.

Use cadenas Base64 para íconos diminutos, documentos de un solo archivo, correos y cargas JSON, donde el transporte basado en texto hace que los archivos sean imposibles o poco prácticos.

Las dos formas llevan los mismos píxeles, así que la elección trata del sistema alrededor de la imagen, no de la imagen en sí. Elija la forma que se ajuste al transporte, al caché y al equipo.

Para las herramientas, use el codificador de imagen a Base64 y el decodificador de Base64 a imagen. Para el marco de decisión sobre incrustar, lea Imágenes Base64: cuándo incrustarlas y cuándo no y los pasos en Cómo convertir una imagen a Base64.

Preguntas frecuentes

¿Una imagen Base64 carga más lento que un archivo de imagen normal?

Depende del tamaño y el contexto. Un ícono diminuto incrustado carga más rápido porque ahorra una solicitud, mientras que una foto grande incrustada carga más lento porque bloquea la visualización y no se puede guardar en caché. Para la mayoría de las imágenes de más de 10 KB, un archivo enlazado carga más rápido, sobre todo en visitas repetidas donde el caché ayuda.

¿Puedo convertir una cadena Base64 de vuelta a un archivo y alojarlo con normalidad?

Sí. Pegue la cadena en el decodificador de Base64 a imagen, descárguela como Original, PNG, JPG o WebP, y suba el archivo a su servidor. Reemplace la cadena incrustada con la URL del archivo, y la imagen se convierte de nuevo en un archivo normal en caché.

¿Las imágenes Base64 funcionan en todos los navegadores?

Las URL de datos funcionan en todos los navegadores modernos, incluidos Chrome, Safari, Firefox y Edge. Los navegadores muy viejos tenían límites de tamaño en las URL de datos, pero esos límites desaparecieron en las versiones actuales. Los clientes de correo son la excepción, porque algunos aún bloquean las imágenes Base64 en línea.

¿Por qué mi página web es tan lenta después de incrustar varias imágenes?

Porque las cadenas incrustadas hicieron el documento HTML mucho más grande, y el navegador debe descargar todo antes de mostrarlo. Cada imagen también cuesta 33 por ciento más bytes que el archivo. Vuelva a enlazar las imágenes más grandes como archivos y mantenga incrustados solo los íconos diminutos.

¿Las cadenas Base64 son seguras para guardar avatares de usuarios en una base de datos?

Son convenientes pero no inherentemente seguras. Base64 es codificación, no cifrado, así que cualquiera con acceso a la base de datos puede decodificar la cadena y obtener la imagen. Guarde los avatares como archivos en almacenamiento de objetos con una referencia en la base de datos para uso a gran escala, y trate el contenido de la base de datos como sensible de cualquier manera.

¿Cuándo debería usar la subida multipart en lugar de Base64 en una API?

Use la subida multipart para las imágenes grandes, porque envía el binario directamente sin el extra del 33 por ciento. Use Base64 cuando la API acepta solo JSON, cuando la imagen es pequeña o cuando el cliente no puede armar con facilidad una solicitud multipart. Muchas API admiten ambas, así que revise la documentación.
