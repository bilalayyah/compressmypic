Imagen a Base64 para incrustarla en código

Los desarrolladores a menudo necesitan una imagen como texto en lugar de como archivo. Un ícono dentro de una hoja de estilos, un logotipo dentro de un correo HTML o una imagen dentro de un JSON necesitan la imagen convertida en caracteres.

Base64 es la codificación que hace eso posible. Convierte los bytes binarios de una imagen en una cadena de texto simple que puede vivir dentro del código, el marcado y los mensajes.

Esta guía explica cómo funciona el conversor de imagen a Base64 de CompressMyPic, para qué sirve cada formato de salida y cuándo incrustar una imagen es inteligente y cuándo es un error.

¿Qué es Base64?

Base64 es una forma de representar datos binarios como texto. Toma los bytes sin procesar de un archivo y los reescribe usando 64 caracteres seguros: las letras de la A a la Z, de la a a la z, los dígitos del 0 al 9, más y barra, con signos igual como relleno.

Los caracteres son seguros porque aparecen en todos los sistemas de texto. Un correo, un archivo JSON, una hoja de estilos y una base de datos pueden contener una cadena Base64 sin corromperla, lo que no es cierto de los bytes sin procesar de una imagen.

Base64 no es cifrado ni compresión. Cualquiera que reciba la cadena puede decodificarla de vuelta a la imagen original, y la cadena siempre es más larga que el archivo del que salió.

Piénselo como una traducción, no como una transformación. La imagen sigue siendo la misma imagen; solo cambió el alfabeto con el que se escribe.

Cómo funciona la codificación Base64

La codificación lee el archivo de imagen de tres bytes a la vez. Cada grupo de tres bytes, 24 bits en total, se divide en cuatro grupos de seis bits, y cada grupo de seis bits se convierte en un carácter Base64.

Cuando la longitud del archivo no es múltiplo de tres, el codificador agrega signos igual como relleno. Un signo igual significa que el último grupo tenía dos bytes, y dos signos igual significan que tenía solo uno.

El resultado es una cadena de texto que contiene toda la imagen. Decodificar invierte el proceso con exactitud y convierte los caracteres de vuelta a los bytes originales sin ninguna pérdida.

El conversor hace todo esto de forma local en su navegador. La imagen se lee, se codifica y se muestra sin salir jamás de su dispositivo, así que los diagramas privados y los recursos de clientes se mantienen privados.

El 33 por ciento extra

La salida Base64 es unos 33 por ciento más grande que el archivo original. Una imagen de 90 KB se convierte en una cadena de unos 120 KB, porque cuatro caracteres de texto llevan solo tres bytes de datos.

El extra es una propiedad fija de la codificación, no un defecto de la herramienta. Todo codificador Base64 en cualquier lenguaje produce el mismo aumento de tamaño para la misma entrada.

Las salidas HTML y CSS son un poco más grandes todavía, porque agregan un envoltorio alrededor de la cadena. La etiqueta de imagen agrega marcado, y la función CSS agrega su propia sintaxis, además del 33 por ciento.

Este extra es lo primero que debe considerar antes de incrustar. Un ícono pequeño crece de 3 KB a 4 KB, lo que nadie nota, pero una foto de 2 MB crece a 2,7 MB, lo que todo el mundo nota.

Cuatro formatos de salida en una sola herramienta

El conversor ofrece cuatro formatos de salida, cada uno pensado para un trabajo distinto. Usted elige la pestaña que se ajuste a su código, y la herramienta genera el fragmento exacto que necesita.

La pestaña URL de datos le da la URI de datos completa, lista para pegar en una fuente de imagen o una hoja de estilos. Incluye el tipo de medio, el marcador de codificación y la cadena Base64 en una sola pieza.

La pestaña Base64 sin formato le da solo la cadena en sí, sin prefijo. Esa es la forma que las cargas de API y las bases de datos por lo general quieren, porque el código receptor agrega su propio contexto.

La pestaña de imagen HTML le da un elemento de imagen completo con la URL de datos como fuente, más los atributos de ancho y alto completados de forma automática. La pestaña CSS le da una función url() que envuelve la URL de datos, lista para un fondo o una máscara.

URL de datos explicadas

Una URL de datos empieza con la palabra data, seguida del tipo de medio, el marcador de codificación y la cadena Base64. Una típica se ve así: data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA.

Los navegadores entienden las URL de datos en cualquier lugar donde funcionaría una URL normal. Usted puede usar una como fuente de imagen, fondo de hoja de estilos o destino de enlace, y el navegador la decodificará y la mostrará.

La ventaja es la autocontención. Una página que usa URL de datos no tiene archivos de imagen separados que buscar, así que funciona sin conexión, en un solo archivo y en contextos donde las solicitudes externas están bloqueadas.

La desventaja es el tamaño. El extra del 33 por ciento aplica a cada imagen incrustada, y una página con muchas URL de datos se vuelve pesada y lenta de procesar.

Base64 sin formato explicado

El Base64 sin formato es la cadena sin el prefijo de datos. Es lo que usted envía cuando el receptor ya conoce el tipo de imagen, o cuando el tipo viaja en un campo aparte.

Las cargas de API son el caso de uso principal. Un objeto JSON puede llevar un campo llamado image con la cadena sin formato, más un campo llamado mimeType con el formato, y el servidor reconstruye el archivo a partir de los dos.

Las bases de datos usan el Base64 sin formato de la misma manera. Guardar una imagen como texto en una columna de texto evita los tipos de columna binaria, que algunos sistemas manejan mal.

Cuando usted copie Base64 sin formato, conserve el relleno. Los signos igual del final son parte de la codificación, y quitarlos puede romper los decodificadores que esperan una cadena completa.

El fragmento de imagen HTML

La pestaña HTML genera un elemento de imagen completo con la URL de datos como fuente. También completa los atributos de ancho y alto de forma automática a partir de las dimensiones de la imagen.

Esos atributos importan más de lo que parecen. Sin ellos, el navegador no conoce el tamaño de la imagen hasta que decodifica la cadena, y el diseño de la página se mueve cuando la imagen por fin aparece.

Con el ancho y el alto presentes, el navegador reserva de inmediato la cantidad correcta de espacio. El diseño se mantiene estable, lo que es mejor para los lectores y para las puntuaciones de cambio de diseño.

El fragmento está listo para pegar en cualquier archivo HTML. Agregue un atributo alt que describa la imagen antes de publicarla, porque la herramienta no puede saber qué muestra la foto.

El fragmento CSS url()

La pestaña CSS envuelve la URL de datos en una función url() y produce un valor que usted puede pegar en una propiedad background-image o similar. Es la forma más rápida de poner una imagen pequeña en una hoja de estilos.

Las imágenes CSS incrustadas son comunes para íconos, patrones y fondos decorativos. Cargan con la hoja de estilos, así que no hay una solicitud separada ni un destello de decoración faltante.

El intercambio es el peso de la hoja de estilos. Una hoja de estilos llena de imágenes incrustadas crece mucho, y los navegadores no pueden guardar las imágenes en caché por separado del CSS que las contiene.

Use la forma CSS para imágenes pequeñas y estables que rara vez cambian. Un logotipo o un patrón repetido califica; una galería de fotos no, porque la hoja de estilos se volvería enorme.

Calidad: la codificación no cambia nada

Codificar una imagen a Base64 no cambia un solo píxel. El proceso es totalmente reversible, y decodificar la cadena devuelve los bytes originales exactos.

Los GIF animados conservan su animación, los archivos SVG conservan su código y las fotografías conservan cada detalle. La codificación es una representación distinta, no una imagen distinta.

Esta es una diferencia importante con la conversión de formatos. Cambiar un PNG a JPG pierde datos, pero codificar un PNG a Base64 no pierde nada en absoluto.

Lo único que cambia es el tamaño. La cadena es alrededor de un tercio más grande que el archivo, y ese costo es el precio de llevar datos binarios como texto.

Qué formatos y tamaños son compatibles

El conversor acepta archivos PNG, JPG, WebP, GIF, SVG, BMP e ICO, de hasta 15 MB cada uno. Eso cubre logotipos, íconos, fotos e imágenes animadas en una sola herramienta.

Los archivos SVG se codifican sin problema porque ya son texto. La herramienta lee el código SVG y lo codifica como cualquier otro archivo, y produce una cadena que se decodifica de vuelta al mismo gráfico vectorial.

Los archivos ICO de favicon también funcionan, lo que es útil cuando un sitio necesita su ícono incrustado en una página de un solo archivo o una plantilla de correo. El ICO codificado se decodifica de vuelta a un archivo de ícono válido.

Para los archivos cercanos al límite de 15 MB, considere achicar primero. Un PNG grande comprimido a un JPG más pequeño antes de codificar produce una cadena mucho más corta, y la pérdida de calidad a menudo es invisible.

Cuándo incrustar una imagen Base64

Incruste imágenes pequeñas que sean esenciales para la página. Los íconos, los logotipos y los gráficos decorativos diminutos de menos de unos pocos kilobytes son ideales, porque el extra es insignificante y la solicitud ahorrada es real.

Incruste imágenes en documentos de un solo archivo. Un correo HTML, un informe independiente o una página sin conexión no pueden buscar archivos externos, así que incrustar es la única manera de que las imágenes aparezcan.

Incruste imágenes en cargas de API y archivos de configuración. Cuando la imagen debe viajar dentro de JSON o dentro de un registro de base de datos, Base64 es la forma estándar de llevarla.

Incruste cuando la imagen rara vez cambia. Un logotipo que se mantiene igual durante años no cuesta nada incrustarlo, mientras que una imagen que se actualiza cada semana obliga a cambiar el código cada vez.

Cuándo no incrustar

No incruste fotos grandes. Una fotografía de 2 MB se convierte en una cadena de 2,7 MB dentro de su HTML, y el navegador debe descargar y procesar todo eso antes de que la página pueda mostrarse.

No incruste imágenes que aparecen en muchas páginas. Un logotipo incrustado en cada página se descarga cada vez, mientras que un logotipo enlazado se guarda en caché una vez y se reutiliza en todo el sitio.

No incruste imágenes en correos sin revisar el cliente. Algunos clientes de correo bloquean las imágenes Base64 en línea, y su mensaje puede llegar con imágenes rotas para esos lectores.

No incruste imágenes que necesitan indexarse o compartirse. Un motor de búsqueda no puede descubrir con facilidad una imagen incrustada, y un lector no puede hacer clic derecho y guardarla como puede hacerlo con un archivo normal.

Base64 en correos y API

Los correos HTML son uno de los usos más antiguos de las imágenes Base64. Un correo es un solo mensaje, así que una imagen incrustada viaja con él y se muestra incluso cuando el lector está sin conexión.

No todos los clientes de correo están de acuerdo, sin embargo. Algunos bloquean las imágenes Base64 en línea por razones de seguridad, así que pruebe su plantilla en los clientes que su público usa en realidad antes de depender de la incrustación.

Las API usan Base64 por una razón distinta: JSON no puede llevar datos binarios. Un endpoint de subida de imágenes que acepta JSON espera la imagen como una cadena Base64, a menudo con el tipo de medio en un campo aparte.

Cuando usted arme esa carga, use la pestaña de Base64 sin formato. Le da la cadena sin el prefijo de datos, que es la forma que esperan la mayoría de las API.

Privacidad: la codificación ocurre en su navegador

Codificar una imagen en línea significaría subirla a un servidor, lo que es una mala idea para íconos propios, diagramas confidenciales o recursos de clientes. Esta herramienta nunca hace eso.

El archivo lo lee su navegador, se codifica en su dispositivo y la cadena se le muestra de forma local. Ninguna copia de la imagen ni de la cadena sale de su computadora.

Esto también significa que la herramienta funciona sin conexión una vez que la página cargó. Usted puede codificar íconos en un avión o en una oficina segura sin ningún acceso a la red.

Para los equipos que manejan material visual sensible, la codificación local es la función decisiva. La cadena que usted copia es suya, y ningún servidor ve jamás la imagen ni su forma codificada.

Cómo usar la herramienta de imagen a Base64

Abra el conversor de imagen a Base64 y suelte su imagen en la zona de subida, o pegue una captura directamente desde el portapapeles. Se aceptan archivos de hasta 15 MB.

Elija la pestaña de salida que se ajuste a su trabajo: URL de datos para una URI completa, Sin formato para cargas de API, HTML para un elemento de imagen listo o CSS para un fondo de hoja de estilos.

Copie la salida con el botón de copiar, o descárguela como un archivo cuando la cadena sea larga y copiar se sienta riesgoso. La descarga guarda el texto exacto, sin recortes.

Para la versión paso a paso, lea Cómo convertir una imagen a Base64, y para el marco de decisión, vea Imágenes Base64: cuándo incrustarlas y cuándo no. Para invertir el proceso, use el decodificador de Base64 a imagen.

Preguntas frecuentes

¿La codificación Base64 es lo mismo que comprimir una imagen?

No, es lo contrario en cuanto al tamaño. La compresión hace un archivo más pequeño, mientras que Base64 lo hace unos 33 por ciento más grande. La codificación cambia la representación de binario a texto sin cambiar ningún píxel. Si usted necesita un archivo más pequeño, comprima primero la imagen y luego codifique el resultado comprimido.

¿Puedo incrustar una imagen Base64 en un documento de Word o un PDF?

No directamente como una cadena Base64. Los archivos Word y PDF guardan las imágenes como datos binarios dentro del documento, no como texto Base64. Base64 es para código web, correos, cargas JSON y otros formatos basados en texto. Convierta primero la imagen a un archivo normal para usarla en documentos.

¿Por qué mi cadena Base64 es tan larga?

Porque lleva toda la imagen como texto, y el texto es un medio menos eficiente que el binario. Una imagen de 90 KB se convierte en unos 120 KB de caracteres, y una foto de 1 MB se convierte en unos 1,4 MB de texto. La longitud es normal. Para las cadenas muy largas, use el botón de descarga en lugar de copiar.

¿La codificación Base64 funciona para GIF animados?

Sí. La codificación no toca los datos de píxeles, así que un GIF animado se codifica en una cadena que se decodifica de vuelta al mismo archivo animado. La animación, la cantidad de fotogramas y la sincronización se conservan con exactitud.

¿Cuál es la imagen más grande que puedo convertir a Base64 aquí?

Se aceptan archivos de hasta 15 MB. Los archivos más grandes producen cadenas extremadamente largas que son incómodas de copiar y lentas de procesar en un navegador. Achique o comprima las imágenes grandes antes de codificar, y considere enlazar en lugar de incrustar para cualquier cosa de más de unos pocos cientos de kilobytes.

¿Los motores de búsqueda pueden ver las imágenes incrustadas como Base64?

En su mayoría no. Un motor de búsqueda técnicamente puede decodificar una URL de datos, pero las imágenes incrustadas no se indexan, no se clasifican ni se muestran en la búsqueda de imágenes como los archivos de imagen enlazados. Si el tráfico de búsqueda de imágenes importa, enlace la imagen como un archivo en lugar de incrustarla.
