Comment convertir une image en Base64

Convertissez une image en Base64 en quatre étapes : envoyez, choisissez la sortie URL de données, brute, HTML ou CSS, puis copiez ou téléchargez.

Il vous faut une image sous forme de texte : un logo pour une feuille de style, une icône pour un e-mail, ou une image pour une charge utile JSON. La conversion prend environ une minute quand on connaît les étapes.

Ce guide vous accompagne pour convertir une image en Base64 en quatre étapes : envoyez le fichier, choisissez le format de sortie, copiez ou téléchargez la chaîne, et collez-la dans votre code.

Aucun logiciel à installer, aucun compte à créer, et rien n'est envoyé nulle part. L'image est encodée en local dans votre navigateur, du début à la fin.

Ce qu'il vous faut avant de commencer

Il vous faut le fichier image lui-même, en format PNG, JPG, WebP, GIF, SVG, BMP ou ICO, jusqu'à 15 Mo. Les logos, les icônes et les petites photos sont les candidats habituels.

Sachez où va la chaîne. Une page HTML veut une URL de données, une feuille de style veut une valeur CSS url(), et une API veut généralement la chaîne brute sans préfixe.

Si l'image est grande, envisagez de la réduire d'abord. Une photo de 2 Mo devient une chaîne de 2,7 Mo, difficile à copier et lente à analyser, tandis qu'une version compressée peut faire un dixième de cela.

Un navigateur est le seul logiciel nécessaire. L'outil fonctionne sur Chrome, Safari, Firefox et Edge, sur ordinateur et sur mobile, sans extension.

Étape 1 : envoyez l'image ou collez une capture

Ouvrez le convertisseur d'image en Base64 et glissez votre image dans la zone d'envoi. Vous pouvez aussi cliquer sur la zone pour choisir un fichier sur votre appareil.

Si l'image est sur votre écran en ce moment, copiez-la et collez-la avec Ctrl+V. L'outil accepte directement les images du presse-papiers, donc une capture peut être encodée sans enregistrer de fichier d'abord.

L'outil lit le fichier et affiche un aperçu avec ses dimensions et son format. Vérifiez que l'aperçu est bien l'image voulue, parce que la chaîne copiée sera exactement ce fichier.

Si vous avez envoyé le mauvais fichier, encodez-en un autre depuis l'outil. La sortie précédente est remplacée, et vous pouvez continuer à travailler sans recharger la page.

Étape 2 : choisissez le format de sortie

Quatre onglets se trouvent au-dessus de la zone de sortie : URL de données, Brut, HTML et CSS. Choisissez celui qui correspond à l'endroit où va la chaîne.

Choisissez URL de données quand vous avez besoin d'un URI complet pour une source d'image ou un fond de feuille de style. Il inclut le type de média et le marqueur d'encodage, donc il fonctionne partout où une URL fonctionne.

Choisissez Brut quand vous envoyez l'image à une API ou que vous la stockez dans une base de données. La sortie brute est la chaîne seule, sans préfixe, qui est la forme attendue par la plupart des API.

Choisissez HTML quand vous voulez un élément d'image prêt. L'outil génère la balise avec l'URL de données comme source et remplit automatiquement les attributs de largeur et de hauteur. Choisissez CSS quand vous voulez une valeur url() pour un fond ou un masque.

Étape 3 : copiez la sortie ou téléchargez-la

Cliquez sur le bouton Copier la sortie pour placer la chaîne dans votre presse-papiers. Pour les chaînes courtes comme les icônes et les logos, c'est tout ce qu'il faut.

Pour les longues chaînes, utilisez plutôt le bouton de téléchargement. Copier une chaîne de plusieurs méga-octets peut être lent ou peu fiable, tandis qu'un fichier texte téléchargé porte la sortie exacte sans troncature.

Si votre navigateur bloque l'accès au presse-papiers, l'outil vous le dira. Autorisez la permission du presse-papiers pour la page, ou utilisez le bouton de téléchargement comme solution de repli qui n'a besoin d'aucune permission.

Vérifiez le pourcentage de surcoût affiché à côté de la sortie. Il vous dit de combien la chaîne est plus grande que le fichier original, ce qui est généralement autour de 33 pour cent plus un peu pour l'enveloppe.

Étape 4 : collez la chaîne dans votre code

Collez la sortie à sa place : l'URL de données dans une source d'image ou une feuille de style, la chaîne brute dans un champ JSON, l'extrait HTML dans une page, ou la valeur CSS dans une propriété de fond.

Testez le résultat immédiatement. Ouvrez la page, envoyez l'e-mail de test, ou appelez l'API, et confirmez que l'image apparaît. Une chaîne collée dans le mauvais champ échouera silencieusement ou affichera une image cassée.

Gardez le fichier image original. Si la version intégrée doit changer un jour, vous réencoderez à partir de l'original plutôt que de décoder la chaîne pour la réencoder.

Pour un logo ou une icône, envisagez d'enregistrer l'extrait dans votre projet comme une variable ou un fragment réutilisable. Ainsi, la longue chaîne vit à un seul endroit au lieu d'être collée dans chaque fichier qui en a besoin.

Encoder un logo SVG

Les logos SVG s'encodent proprement parce qu'ils sont déjà du texte. Envoyez le fichier SVG et l'outil produit une chaîne Base64 qui se décode en le même graphique vectoriel.

L'URL de données pour un SVG commence par data:image/svg+xml;base64, suivi de la chaîne. Collez-la dans une source d'image et le logo s'affiche net à n'importe quelle taille.

Surveillez quand même la taille. Un SVG complexe avec beaucoup de chemins peut être grand, et sa forme Base64 est encore un tiers plus grande. Un logo simple va bien ; une illustration détaillée vaut peut-être mieux liée en fichier.

Pour les très petits SVG, envisagez un SVG encodé en URL simple au lieu du Base64. Il est plus court, mais il demande un échappement soigneux, donc le Base64 reste le choix par défaut le plus sûr pour la plupart des gens.

Encoder un favicon

Les fichiers ICO de favicon fonctionnent dans le convertisseur comme n'importe quel autre format. Envoyez le fichier .ico et copiez l'URL de données pour l'utiliser dans une page en un seul fichier ou un modèle d'e-mail.

La plupart des sites devraient lier le favicon en fichier au lieu de l'intégrer. Un favicon lié est mis en cache par le navigateur, tandis qu'un favicon intégré est téléchargé avec chaque page qui le contient.

L'intégration a du sens pour les pages en un seul fichier, les documents hors ligne et les modèles d'e-mails, où aucun fichier séparé ne peut être récupéré. Dans ces contextes, l'icône intégrée est le seul moyen pour que le favicon apparaisse.

Si vous n'avez pas encore de favicon, le générateur de favicon peut en créer un à partir de n'importe quelle image, et vous pourrez ensuite encoder le résultat ici.

Encoder des images pour un e-mail HTML

Les e-mails HTML ne peuvent pas compter sur des fichiers d'images externes, parce que beaucoup de clients bloquent les images distantes par défaut. Intégrer l'image en URL de données la fait apparaître immédiatement, même hors ligne.

Gardez les images d'e-mail intégrées petites. Un logo ou une petite bannière fonctionne bien, mais une grande photographie rend le message lourd et lent à ouvrir sur un téléphone.

Testez avant d'envoyer. Certains clients de messagerie bloquent les images Base64 en ligne, et votre message peut arriver avec des images cassées pour ces lecteurs. Envoyez un test aux clients utilisés par votre public.

Quand un client bloque le Base64, revenez à une image hébergée avec une URL normale. L'image hébergée demande au lecteur de charger du contenu distant, mais elle fonctionne dans chaque client qui l'autorise.

Encoder des images pour une charge utile JSON d'API

Le JSON ne peut pas transporter de données binaires, donc les points de terminaison de téléversement d'image qui acceptent le JSON attendent l'image sous forme de chaîne Base64. L'onglet de sortie brute vous donne exactement cette forme.

Copiez la chaîne brute dans le champ JSON documenté par l'API, et envoyez le type de média dans un champ séparé si l'API le demande. Le serveur décode la chaîne et reconstruit le fichier.

Surveillez la taille de la charge utile. Une image de 1 Mo devient un champ JSON de 1,4 Mo, et certaines API rejettent les charges utiles au-dessus d'une limite. Compressez l'image avant l'encodage si l'API a un plafond de taille.

Testez d'abord avec une petite image. Un aller-retour réussi avec une minuscule icône prouve que les noms de champs et le format sont corrects avant d'envoyer une grande image de production.

Réduire une image avant l'encodage

Encoder une grande image produit une très longue chaîne, et les longues chaînes sont difficiles à copier, lentes à analyser et lourdes à stocker. Réduire d'abord vaut presque toujours le coup.

Compressez l'image avec le compresseur d'images avant de l'encoder. Une photo réduite de 2 Mo à 200 Ko produit une chaîne dix fois plus courte, avec une perte de qualité généralement invisible.

Redimensionnez aussi quand la taille d'affichage est petite. Une icône affichée à 64 pixels n'a pas besoin d'une source de 2000 pixels, et la source plus petite s'encode en une chaîne bien plus courte.

Pour les photos, convertissez en JPG avant l'encodage si la transparence n'est pas nécessaire. Les fichiers JPG sont bien plus petits que les PNG pour les photographies, et le fichier plus petit veut dire une chaîne plus courte.

Dépannage des problèmes de copie dans le presse-papiers

Si le bouton de copie ne fait rien, votre navigateur a peut-être bloqué l'accès au presse-papiers. L'outil affichera un message expliquant le blocage, et vous pourrez autoriser la permission pour la page.

Certains navigateurs n'autorisent les écritures dans le presse-papiers qu'après un geste de l'utilisateur sur une page sécurisée. Cliquer sur le bouton compte comme un geste, mais un vieux navigateur ou un réglage restrictif peut quand même refuser.

Le bouton de téléchargement est la solution de repli fiable. Il enregistre la sortie exacte sous forme de fichier texte sans presse-papiers, et vous pouvez ouvrir le fichier et copier à partir de là.

Sur mobile, les longues chaînes peuvent être lentes à copier. Téléchargez plutôt le fichier de sortie, puis partagez-le vers l'application où vous en avez besoin, plutôt que de lutter avec le presse-papiers.

Dépannage des très longues chaînes

Une longue chaîne est normale pour une grande image, mais elle peut rendre votre éditeur lent. Coller une chaîne de 2 Mo dans un fichier de code peut figer un éditeur léger pendant quelques secondes.

Divisez le travail : stockez la chaîne dans un fichier séparé ou une variable, et référencez-la depuis le code qui en a besoin. Cela garde vos fichiers principaux lisibles et votre éditeur réactif.

Si la chaîne casse votre build, vérifiez les limites de longueur de ligne. Certains outils enveloppent ou tronquent les très longues lignes, ce qui corrompt la chaîne. Un fichier téléchargé évite entièrement ce problème.

Quand une chaîne paraît trop longue à gérer, reconsidérez l'intégration. Un fichier d'image lié est souvent le meilleur choix pour tout ce qui dépasse quelques centaines de kilo-octets.

Encoder une autre image après la première

Pour encoder une deuxième image, envoyez-la depuis l'outil sans recharger la page. La nouvelle image remplace l'ancienne, et la sortie se met à jour avec la nouvelle chaîne.

Copiez la première sortie avant de changer, parce que remplacer l'image efface la chaîne précédente. Un fichier téléchargé est le relevé le plus sûr si vous avez besoin des deux chaînes.

Traiter un ensemble d'icônes est rapide ainsi. Envoyez, copiez, envoyez la suivante, copiez à nouveau, et tout l'ensemble d'icônes est encodé en quelques minutes.

Gardez les fichiers originaux organisés pendant que vous travaillez. Un dossier d'images sources et un dossier correspondant de fichiers de sortie en texte évitent les confusions qui surviennent quand toutes les chaînes se ressemblent.

Encoder des images pour les réseaux sociaux et la messagerie

Les publications sociales et les messages de chat n'acceptent parfois les images que sous forme de texte, surtout dans les bots, les webhooks et les flux automatisés. Une chaîne Base64 permet à une image de voyager dans une charge utile en texte seul.

Gardez ces images minuscules. Une API de chat peut plafonner la taille des messages à quelques dizaines de kilo-octets, et une photo encodée en Base64 dépassera cette limite avant même d'arriver.

Pour les chatbots, une petite icône ou une miniature de moins de 10 Ko s'encode en une chaîne qui tient confortablement dans un message. Tout ce qui est plus grand devrait être envoyé en fichier et référencé par URL à la place.

Certains outils d'automatisation acceptent une URL de données là où ils auraient autrement besoin d'une image hébergée. C'est utile quand l'image est générée à la volée et qu'il n'y a nulle part où l'héberger pour l'instant.

Testez l'aller-retour complet avant de l'automatiser. Envoyez un message avec l'image encodée, confirmez qu'elle s'affiche du côté destinataire, et seulement ensuite construisez le flux autour.

Rappelez-vous que la chaîne est visible pour quiconque peut voir la charge utile du message. N'encodez pas de photos privées dans des messages, des journaux ou des webhooks où le texte pourrait être stocké ou transféré.

Aide-mémoire rapide

Envoyez l'image, choisissez l'onglet de sortie pour votre destination, et copiez ou téléchargez la chaîne. Testez-la en place avant de publier quoi que ce soit qui en dépend.

Réduisez les grandes images avant l'encodage, utilisez le Base64 brut pour les API, et préférez un fichier lié à une chaîne intégrée pour tout ce qui est grand ou partagé sur plusieurs pages.

Questions fréquentes

Puis-je convertir une image en Base64 sur mon téléphone ?

Oui. Le convertisseur fonctionne dans les navigateurs mobiles sur iOS et Android. Envoyez l’image depuis votre galerie, choisissez l’onglet de sortie, et copiez la chaîne. Pour les très longues chaînes, téléchargez plutôt le fichier de sortie, puisque les presse-papiers mobiles peuvent peiner avec les grands textes.

Pourquoi l’onglet HTML ajoute-t-il la largeur et la hauteur à la balise d’image ?

Le navigateur a besoin des dimensions pour réserver l’espace avant que l’image ne se décode. Sans elles, la mise en page de la page bouge quand l’image apparaît, ce qui nuit à l’expérience de lecture et au score de décalage de mise en page. L’outil remplit automatiquement les attributs à partir des dimensions de l’image.

Dois-je utiliser le Base64 ou un fichier d’image normal pour le logo de mon site web ?

Pour un logo qui apparaît sur beaucoup de pages, un fichier lié normal est généralement meilleur parce que le navigateur le met en cache une fois. Le Base64 gagne quand la page doit être un seul fichier, quand le logo est minuscule, ou quand aucune requête séparée n’est autorisée. Pour la plupart des sites, liez le logo.

Quelle est la différence entre une URL de données et du Base64 brut ?

Une URL de données est l’URI complet avec le préfixe data, le type de média et le marqueur d’encodage, prêt à utiliser comme source d’image. Le Base64 brut est la chaîne seule, sans préfixe, qui est la forme attendue généralement par les API et les bases de données. L’outil génère les deux à partir de la même image.

La conversion en Base64 retire-t-elle les métadonnées de mon image ?

L’encodage lui-même ne retire rien, parce que la chaîne porte les octets originaux exacts. Cependant, certains flux retirent les métadonnées avant l’encodage pour garder la chaîne plus courte. Si la confidentialité compte, retirez d’abord les métadonnées avec l’outil de suppression des métadonnées, puis encodez le fichier propre.

Puis-je encoder une capture directement sans enregistrer de fichier ?

Oui. Copiez la capture et appuyez sur Ctrl+V dans l’outil, et elle sera encodée immédiatement. C’est le moyen le plus rapide d’obtenir une URL de données pour une capture d’écran, un élément d’interface ou un schéma que vous regardez en ce moment.
