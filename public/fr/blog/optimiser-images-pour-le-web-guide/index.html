Optimiser les images pour le web : guide complet

Le guide complet pour optimiser les images de votre site : préréglages pour les images principales, de produits et de cartes, Core Web Vitals, et HTML à copier-coller.

Un site web n’est rapide que dans la mesure où ses images le sont. Le texte se charge en millisecondes, mais une seule photo non optimisée peut bloquer une page pendant des secondes.

L’outil d’optimisation des images pour le web est conçu pour ce problème. Il compresse les images pour des emplacements précis du site web, puis vous remet le HTML à coller directement dans votre page.

Ce guide explique les préréglages, les réglages, et comment utiliser l’outil pour rendre tout un site plus rapide.

Qu’est-ce que l’optimisation d’images web ?

L’optimisation web consiste à préparer une image pour un travail précis sur une page. Une image principale, une photo de produit et une miniature ont chacune besoin de tailles et de formats différents.

Elle couvre quatre choses : la taille du fichier, les dimensions, le format et le HTML. Bien régler les quatre rend l’image rapide à charger et nette à regarder.

La taille du fichier décide de la vitesse de téléchargement. Les dimensions décident de la façon dont l’image s’insère dans son emplacement. Le format décide de la compatibilité et de la qualité.

Le HTML décide de la façon dont le navigateur traite l’image. Le chargement différé, la largeur, la hauteur et le texte alternatif vivent tous dans la balise, et ils influent tous sur la vitesse et l’accessibilité.

L’optimiseur gère les quatre ensemble. C’est ce qui le distingue d’un simple compresseur, qui ne gère que la taille du fichier.

Les cinq préréglages de performance web

L’outil propose cinq préréglages, chacun correspondant à un vrai emplacement de site web. Ils définissent les dimensions, le format et la qualité en un clic.

Produit e-commerce est le préréglage par défaut. Il plafonne les images à 1 200 pixels de large en WebP à 82 % de qualité, ce qui convient parfaitement aux photos de produits.

D’autres préréglages couvrent les images principales, les cartes, les miniatures et le partage social. Chacun correspond à l’emplacement dont il porte le nom.

Les préréglages sont des points de départ, pas des prisons. Vous pouvez personnaliser n’importe quel réglage après avoir choisi un préréglage, en combinant selon votre page.

Commencez par le préréglage le plus proche de votre emplacement. Ajustez ensuite seulement si le résultat ne convient pas à la conception.

Optimiser les images principales

Les images principales remplissent le haut de la page, donc elles comptent le plus pour les premières impressions et pour le Largest Contentful Paint.

Une image principale devrait être assez grande pour paraître nette sur les écrans larges, mais pas plus. Une image principale surdimensionnée gaspille de la bande passante en pixels que personne ne voit.

Utilisez le WebP pour les images principales sur les sites modernes. Il garde la grande image plus légère que le JPG à qualité égale.

Ne chargez jamais une image principale en différé. Elle est au-dessus de la ligne de flottaison, donc le navigateur devrait la récupérer immédiatement, pas attendre un défilement.

Préchargez l’image principale quand vous pouvez. Informer tôt le navigateur de l’image la plus importante fait gagner du temps réel sur le premier affichage.

Optimiser les images de produits

Les images de produits vendent le produit, donc elles doivent rester nettes. Le préréglage e-commerce les plafonne à 1 200 pixels, ce qui convient à la plupart des mises en page de boutique.

Gardez l’arrière-plan propre et le produit centré. Une photo de produit soignée se compresse mieux et paraît plus professionnelle.

Utilisez des dimensions cohérentes dans tout le catalogue. Une grille de tailles mixtes paraît désordonnée, aussi bonne que soit la compression.

Le WebP est idéal pour les photos de produits sur les boutiques modernes. Pour les places de marché qui exigent le JPG, changez le format et gardez les mêmes dimensions.

Vérifiez la page produit sur un téléphone après l’envoi. La plupart des acheteurs naviguent sur mobile, et l’image doit y avoir bonne allure d’abord.

Les cartes et les miniatures

Les cartes et les miniatures s’affichent en petit, donc elles ont besoin du moins de données. Une image de 400 pixels suffit largement pour une carte affichée à 300 pixels.

Les petites images tolèrent une compression plus forte. Une miniature à qualité inférieure paraît quand même propre, parce que la taille d’affichage cache la douceur.

Chargez en différé les cartes sous la ligne de flottaison. Elles ne sont pas visibles quand la page s’ouvre, donc le navigateur peut les récupérer plus tard.

Gardez le ratio d’aspect cohérent entre les cartes. Une grille de ratios mixtes paraît désordonnée et force le navigateur à recalculer la mise en page.

Les miniatures sont là où l’optimisation rapporte le plus. Une page avec vingt cartes économise des mégaoctets quand chaque miniature est bien dimensionnée.

Le bouton Copier la balise d’image

Le bouton Copier la balise d’image écrit le HTML complet de votre image optimisée. Il inclut la source, les dimensions, le texte alternatif et le comportement de chargement.

Le texte alternatif est généré à partir du nom de fichier ou de votre description. Un bon texte alternatif aide l’accessibilité et les moteurs de recherche à comprendre l’image.

La balise inclut les attributs de largeur et de hauteur. Ceux-ci évitent le décalage de mise en page, une métrique des Core Web Vitals qui influe sur le classement.

Le chargement différé est inclus pour les images sous la ligne de flottaison. Il dit au navigateur d’attendre que l’image approche de la fenêtre avant de la télécharger.

Collez la balise directement dans votre page. Elle est prête à l’emploi, sans édition manuelle nécessaire.

Le chargement différé bien fait

Le chargement différé reporte les images jusqu’à ce qu’elles soient nécessaires. C’est l’un des gains de vitesse les plus faciles sur toute page chargée en images.

Appliquez-le aux images sous la ligne de flottaison. Elles ne sont pas visibles quand la page s’ouvre, donc les télécharger tôt gaspille de la bande passante.

Ne chargez jamais en différé l’image principale ou le logo. Ceux-ci sont visibles immédiatement, et les retarder nuit à la première impression et au score LCP.

L’optimiseur ajoute automatiquement le chargement différé pour les préréglages adaptés. Le préréglage d’image principale le laisse désactivé, ce qui est le bon comportement.

Testez la page après avoir ajouté le chargement différé. Faites défiler et confirmez que les images apparaissent en douceur à mesure qu’elles entrent dans la vue.

Les formats pour le web

Le WebP est le meilleur format pour la plupart des images web. Il est plus petit que le JPG à qualité égale et prend en charge la transparence comme le PNG.

Le JPG reste essentiel pour la compatibilité. Les e-mails, le partage social et les systèmes anciens préfèrent encore le JPG, et le préréglage Social OG y bascule automatiquement.

Le PNG convient aux graphiques d’interface, pas aux photos. Un logo ou une icône reste parfait au pixel près en PNG, tandis qu’une photo en PNG gaspille de la bande passante.

Le SVG n’est pas géré par cet outil. C’est un format vectoriel, et l’optimiseur travaille avec des images matricielles comme le JPG, le PNG et le WebP.

En cas de doute, utilisez le WebP pour le site et le JPG pour le partage. L’optimiseur rend le passage de l’un à l’autre un travail d’un clic.

Le curseur de qualité : de 20 à 95 %

Le curseur de qualité va de 20 à 95 %, pas de 0 à 100. Cette plage est délibérée, et elle vous protège des mauvais choix.

Sous 20 %, les images s’effondrent visiblement. Aucun emplacement de site web ne profite d’une qualité aussi basse, donc l’outil ne la propose pas.

Au-dessus de 95 %, le fichier grossit vite pour presque aucun gain visible. Les données supplémentaires préservent des détails que l’œil ne peut pas voir.

La plupart des préréglages se situent entre 75 et 85 %. Cette plage donne des résultats propres à de petites tailles de fichier pour presque chaque image.

Ajustez le curseur seulement quand le résultat du préréglage ne convient pas à l’image. Une photo détaillée peut vouloir 85, tandis qu’un graphique simple se contente de 70.

La suppression des EXIF et le poids de la page

Les photos d’appareil photo portent des métadonnées cachées : localisation GPS, modèle d’appareil et réglages. Ces données ajoutent du poids et divulguent des informations privées.

L’optimiseur supprime les données EXIF et GPS pendant la compression. Le fichier téléchargé ne garde aucune trace du lieu ou du moment où il a été pris.

La suppression n’économise que quelques kilooctets par image, mais cela s’additionne. Vingt images économisent ensemble une quantité significative.

La confidentialité est le plus grand bénéfice. Une photo publiée sur un site public ne devrait pas contenir le lieu où elle a été prise.

Pour le travail client, la suppression est essentielle. Les produits non lancés et les lieux privés ne doivent pas fuiter par les métadonnées des images.

L’optimisation par lots pour des sites entiers

Vous pouvez optimiser beaucoup d’images en un seul lot. Déposez trente images de blog, choisissez un préréglage, et téléchargez-les toutes ensemble.

Le mode par lots est idéal pour les migrations de site. Déplacer un blog vers un nouveau thème signifie réoptimiser chaque image, et un lot le gère en quelques minutes.

Vérifiez quelques résultats avant de télécharger tout le lot. Une seule image douce peut se cacher parmi de bonnes.

Gardez le préréglage cohérent dans tout le lot. Des réglages mixtes produisent des résultats mixtes, qui paraissent désordonnés sur le site en direct.

Pour des cibles exactes de taille de fichier au lieu de préréglages, le compresseur à taille de fichier cible accepte n’importe quel chiffre tapé.

Le partage social et les images Open Graph

Quand quelqu’un partage votre page, la plateforme montre une image d’aperçu. Cette image est souvent la première chose qu’un nouveau visiteur voit.

Les images Open Graph ont besoin de dimensions précises, généralement 1 200 × 630 pixels. Le préréglage Social OG les dimensionne correctement et bascule en JPG.

Gardez le fichier sous quelques centaines de kilooctets. Une image d’aperçu lourde se charge lentement dans la carte de partage, et certaines plateformes l’ignorent complètement.

Testez la carte de partage avant la publication. Chaque grande plateforme propose un débogueur qui montre exactement à quoi ressemblera l’aperçu.

Une bonne image de partage est simple et audacieuse. Le texte devrait être grand, le sujet centré, et l’arrière-plan épuré.

Les écrans Retina et haute densité

Les écrans Retina concentrent plus de pixels dans la même taille physique. Une image nette sur un écran normal peut paraître douce sur un écran Retina.

La solution est de servir une image deux fois plus large que sa taille d’affichage. Une miniature affichée à 400 pixels de large devrait faire 800 pixels dans le fichier.

Les préréglages de l’optimiseur en tiennent compte. Un préréglage de carte produit une image qui reste nette sur les écrans haute densité sans gaspiller de bande passante.

Pour les petites miniatures, cela compte peu. Pour les grandes images vedettes, la différence entre standard et prêt pour Retina est visible.

Testez sur un vrai écran haute densité quand vous pouvez. Les captures d’écran du résultat cachent la douceur même que vous essayez de vérifier.

Le texte alternatif et l’accessibilité

Chaque image web a besoin d’un texte alternatif. Il décrit l’image pour les lecteurs d’écran et pour les moteurs de recherche, et il s’affiche quand l’image ne se charge pas.

L’optimiseur génère le texte alternatif à partir du nom de fichier ou de votre description. Modifiez-le quand le texte généré ne décrit pas bien l’image.

Écrivez le texte alternatif comme une phrase. Décrivez ce que montre l’image, pas à quoi elle sert, et gardez-le sous environ 125 caractères.

Les images décoratives ont besoin d’un texte alternatif vide, pas d’une description. Un texte alternatif vide dit aux lecteurs d’écran d’ignorer entièrement l’image.

Un bon texte alternatif aide aussi le référencement. Les moteurs de recherche le lisent pour comprendre l’image, ce qui peut apporter du trafic depuis la recherche d’images.

Les CDN et la mise en cache des images

Un réseau de diffusion de contenu sert vos images depuis des serveurs proches de chaque visiteur. Cela réduit le temps de téléchargement, surtout pour un public mondial.

Les images optimisées profitent le plus d’un CDN. Un petit fichier servi à proximité se charge presque instantanément, tandis qu’un gros fichier servi de loin rampe.

Les en-têtes de cache disent aux navigateurs de garder les images localement. Un visiteur qui revient charge alors la page sans télécharger à nouveau les images.

Fixez de longues durées de cache pour les images qui changent rarement. Un logo ou une photo de produit peut se mettre en cache en sécurité pendant des mois.

L’optimisation et la diffusion fonctionnent ensemble. Une petite image sur un CDN rapide bat une grosse image sur un serveur lent à chaque fois.

Le WebP avec une solution de repli JPG

Certains navigateurs anciens ne peuvent pas ouvrir le WebP. Servir le WebP seul laisserait ces visiteurs avec des images cassées.

L’élément picture résout cela. Il liste le WebP d’abord et le JPG ensuite, et le navigateur choisit le premier format qu’il prend en charge.

Générez les deux versions de chaque image. L’optimiseur produit la copie WebP, et une copie JPG du même préréglage sert de solution de repli.

Testez la solution de repli sur un navigateur ou un appareil ancien. La version JPG devrait apparaître sans accroc, sans différence visible.

À mesure que la prise en charge du WebP grandit, la solution de repli compte moins. Pour l’instant, c’est une assurance bon marché contre les images cassées.

Mesurer l’amélioration

Les chiffres avant et après rendent le bénéfice concret. Notez le poids total des images et le temps de chargement avant l’optimisation, puis mesurez à nouveau après.

Une page typique passe de plusieurs mégaoctets à moins d’un. Ce changement se voit immédiatement dans les scores de vitesse et dans la sensation de la page.

Vérifiez les Core Web Vitals après optimisation. Le LCP devrait s’améliorer le plus, car l’image principale est généralement le plus grand affichage.

Demandez à un collègue de charger la page sur son téléphone. Un appareil neuf sur une vraie connexion est le test honnête de votre travail.

Gardez un simple relevé des économies. Quand quelqu’un demande pourquoi les images doivent être optimisées, les chiffres répondent mieux que n’importe quel argument.

Pour des cibles simples de taille, le compresseur 200 Ko couvre la plupart des images web.

Questions fréquentes

Quel préréglage utiliser pour une image principale ?

Utilisez le préréglage d’image principale, qui dimensionne l’image pour une bannière pleine largeur et garde la qualité élevée. Ne chargez jamais une image principale en différé, car elle est au-dessus de la ligne de flottaison et influe sur le Largest Contentful Paint. Utilisez le WebP quand le site le prend en charge pour le plus petit fichier à cette qualité.

Pourquoi l’outil bascule-t-il en JPG pour les images de partage social ?

Les plateformes sociales et les clients de messagerie gèrent le JPG plus sûrement que le WebP. Le préréglage Social OG et E-mail change le format automatiquement pour que vos images partagées s’affichent correctement partout, même sur les systèmes anciens qui ne peuvent pas ouvrir le WebP.

Dois-je garder le chargement différé sur mon image principale ?

Non. Le chargement différé retarde le téléchargement jusqu’à ce que l’image approche de la fenêtre, ce qui est faux pour une image principale visible immédiatement. Cela nuira à votre score de Largest Contentful Paint. Gardez le chargement différé pour les images sous la ligne de flottaison seulement.

Que fait l’option Réduire seulement ?

Elle protège les petites images contre l’agrandissement. Quand elle est activée, l’outil ne réduit que les images plus grandes que les dimensions du préréglage et laisse les plus petites intactes. Cela garde les icônes et les miniatures nettes au lieu de les étirer.

Pourquoi les fichiers téléchargés sont-ils nommés avec -web à la fin ?

Le suffixe -web marque le fichier comme la version optimisée pour le web, donc il ne sera pas confondu avec l’original. Un nom comme hero-1200-web.webp vous dit instantanément que le fichier est prêt pour le site web.

Puis-je utiliser l’outil d’optimisation des images pour le web au lieu du compresseur d’images en lot ?

Utilisez l’outil d’optimisation web quand vous avez besoin de préréglages, de balises HTML et de dimensionnement propre à un emplacement pour un site web. Utilisez le compresseur en lot quand vous avez seulement besoin de fichiers plus petits sans réglages propres au web. Pour des limites exactes de taille de fichier, utilisez le compresseur à taille de fichier cible.
