Base64 ke Gambar: Dekode Teks Jadi File

Dekode string Base64 menjadi gambar. Dekode otomatis saat ditempel, varian URL-safe, pratinjau transparansi, dan unduhan PNG, JPG, WebP, atau format asli.

Dinding teks yang panjang tiba di email, pesan chat, atau respons API, dan di suatu tempat di dalamnya ada sebuah gambar. Teks itu adalah string Base64, dan gambarnya sedang menunggu untuk didekode.

Dekoding mengubah string itu kembali menjadi file gambar aslinya. Proses ini adalah kebalikan dari encoding, dan sama lossless-nya: byte yang keluar adalah byte yang masuk.

Panduan ini menjelaskan cara kerja decoder Base64 ke gambar CompressMyPic, apa yang diterimanya, apa yang ditampilkannya, dan cara mendapatkan file gambar yang bisa dipakai dari string Base64 apa pun.

Apa Itu Decoder Base64 ke Gambar?

Decoder Base64 ke gambar mengambil string teks dan mengubahnya kembali menjadi file gambar yang bisa Anda lihat, unduh, dan pakai. Decoder membalik proses encoding secara persis.

Anda menempel string ke alat, dan gambar hasil dekode muncul sebagai pratinjau beserta dimensi dan ukuran file-nya. Anda lalu mengunduhnya dalam format asli atau mengubahnya ke PNG, JPG, atau WebP.

Alat menerima string dengan atau tanpa awalan data:image. Alat juga menangani varian URL-safe dan string dengan jeda baris yang tidak disengaja, yang umum terjadi saat teks disalin dari email atau dokumen.

Semua proses berjalan lokal di browser Anda. String didekode di perangkat Anda, dan baik teks maupun gambar tidak diunggah ke server mana pun.

Cara Kerja Dekoding Base64

Dekoding membaca string empat karakter setiap kalinya. Setiap kelompok empat karakter membawa 24 bit data, yang dipecah decoder kembali menjadi tiga byte dari file asli.

Tanda sama dengan di akhir string adalah padding, dan memberi tahu decoder berapa banyak byte yang dimiliki kelompok terakhir. Satu tanda sama dengan berarti dua byte, dan dua tanda sama dengan berarti satu byte.

Proses ini persis. String yang di-encode dengan benar didekode menjadi file yang sama byte demi byte dengan file yang di-encode, tanpa kehilangan kualitas, animasi, atau transparansi.

Jika string-nya rusak, decoder gagal dengan pesan error yang jelas, bukan menghasilkan gambar yang rusak. Perilaku gagal-cepat ini penting, karena gambar yang rusak secara diam-diam lebih buruk daripada error yang jujur.

String Dengan dan Tanpa Awalan data:image

String gambar Base64 hadir dalam dua bentuk. Data URL lengkap dimulai dengan data:image/png;base64, diikuti string-nya, sementara string mentah hanyalah karakter yang ter-encode saja.

Decoder menerima keduanya. Tempel Data URL lengkap dari halaman web, atau tempel string mentah dari payload JSON, dan alat akan mengenali bentuk mana yang diterimanya.

Hal ini penting karena kedua bentuk itu muncul di tempat yang berbeda. Kode web memakai Data URL, sementara API dan database biasanya menyimpan string mentah dengan tipe media di kolom terpisah.

Saat Anda menempel string, periksa apakah string itu dimulai dengan data:. Jika ya, tipe medianya sudah dinyatakan. Jika tidak, decoder membaca header gambar untuk mengidentifikasi formatnya sendiri.

Varian URL-Safe dan Jeda Baris

Base64 standar memakai karakter plus dan slash, yang punya arti khusus di dalam URL. Varian URL-safe menggantinya dengan dash dan underscore, sehingga string bisa berjalan dengan aman di alamat web.

Decoder memahami kedua alfabet itu. String yang disalin dari parameter URL didekode sama baiknya dengan string yang disalin dari file JSON, tanpa perlu konversi manual.

Jeda baris adalah kecelakaan umum lainnya. Klien email dan dokumen membungkus string panjang ke beberapa baris, menyisipkan jeda yang bukan bagian dari encoding.

Decoder menoleransi jeda itu dan mengabaikannya. Decoder juga menoleransi spasi tambahan, sehingga string yang terbungkus, dikutip, atau ditempel dengan whitespace di sekitarnya tetap didekode dengan benar.

Dekode Otomatis saat Ditempel

Anda tidak perlu mengklik tombol untuk mendekode. Menempel string Base64 ke alat memicu dekode secara otomatis, dan pratinjaunya muncul dalam beberapa saat.

Dekoding otomatis adalah kemudahan kecil yang penting saat Anda mengerjakan banyak string. Tempel, periksa pratinjaunya, unduh, lalu tempel berikutnya, tanpa klik tambahan per gambar.

Jika string sangat panjang, dekode bisa memakan waktu satu atau dua detik. String bermegabyte membawa banyak teks, dan browser butuh waktu sejenak untuk mengubahnya kembali menjadi data biner.

Alat mendekode secepat yang diizinkan browser, dan tidak ada perjalanan pulang-pergi ke server yang memperlambatnya. String besar didekode secepat perangkat Anda sendiri.

Pratinjau Papan Catur

Gambar hasil dekode muncul di atas latar papan catur, dan itulah cara standar untuk menunjukkan transparansi. Kotak abu-abu dan putih di belakang gambar menandai area tempat gambar tembus pandang.

Papan catur sangat berguna untuk ikon dan logo. PNG dengan latar transparan terlihat identik dengan PNG berlatar putih di halaman putih polos, tapi papan catur langsung mengungkapkan perbedaannya.

Jika papan catur terlihat menembus bagian tengah gambar yang seharusnya solid, gambar sumber memang punya transparansi di sana. Itu informasi tentang file, bukan cacat pada decoder.

Gunakan pratinjau untuk memutuskan format unduhan. Jika gambar punya transparansi yang perlu dipertahankan, unduh sebagai PNG atau dalam format aslinya, bukan sebagai JPG.

Metrik: Dimensi, Format, dan Ukuran

Di samping pratinjau, alat menampilkan dimensi gambar hasil dekode dalam piksel, format yang terdeteksi, dan ukuran file biner dalam kilobyte atau megabyte.

Ukuran biner selalu lebih kecil daripada teks Base64 yang Anda tempel, sekitar seperempatnya. Itulah overhead encoding 33 persen yang berjalan terbalik, dan selisih itu memang diharapkan.

Dimensi memberi tahu apakah gambar bisa dipakai untuk keperluan Anda. Ikon 64 kali 64 yang didekode dari string adalah favicon, bukan gambar hero, dan tidak ada format unduhan yang akan mengubah itu.

Periksa juga formatnya. String yang mengklaim sebagai PNG tapi didekode sebagai JPEG memberi tahu sesuatu tentang sumbernya, dan pilihan unduhan menyesuaikan dengan apa sebenarnya file itu.

Format Unduhan: Asli, PNG, JPG, WebP

Begitu string terdekode, Anda memilih format unduhan. Original menjaga file persis seperti saat di-encode, byte demi byte, dan ini pilihan paling aman saat Anda tidak yakin.

PNG adalah pilihan tepat untuk gambar dengan transparansi atau tepi yang tajam. PNG mempertahankan piksel secara persis dan menjaga channel alpha tetap utuh, sehingga logo dan ikon selamat dalam perjalanan pulang-pergi.

JPG adalah pilihan tepat untuk foto yang perlu berukuran kecil. JPG mengompres gambar dan membuang transparansi, jadi pakai hanya saat gambar sepenuhnya opaque.

WebP adalah jalan tengah yang modern: lebih kecil daripada PNG untuk sebagian besar gambar, dengan dukungan transparansi. WebP adalah default yang baik saat tujuannya situs web modern. Setiap unduhan diberi nama decoded_image dengan ekstensi yang cocok, sehingga mudah ditemukan di folder unduhan Anda.

Transparansi dan Jebakan JPG

Transparansi adalah hal yang paling mudah hilang saat Anda mendekode. PNG dengan latar transparan yang diunduh sebagai JPG akan membuat area transparannya terisi, biasanya dengan putih atau hitam.

Isian itu permanen. Begitu gambar disimpan sebagai JPG, informasi transparansinya hilang, dan mengonversinya kembali ke PNG tidak akan mengembalikannya.

Selalu periksa pratinjau papan catur sebelum memilih JPG. Jika ada bagian gambar yang menunjukkan papan catur, gambar itu punya transparansi, dan JPG adalah format yang salah.

Saat ragu, unduh sebagai Original. Pilihan itu mempertahankan file persis seperti saat di-encode, dan Anda bisa mengonversinya nanti setelah memeriksanya dengan benar.

GIF Animasi dan SVG Vektor

GIF animasi bertahan dalam dekoding secara utuh saat diunduh sebagai Original. Frame, waktu, dan pengaturan loop semuanya adalah bagian dari data biner, dan dekoding mengembalikannya secara persis.

Mengonversi GIF animasi ke PNG atau JPG menghancurkan animasinya, karena format-format itu hanya menyimpan satu frame diam. Alat akan memberi tahu Anda dengan hanya menampilkan frame pertama di pratinjau hasil konversi.

File SVG adalah vektor, dan didekode kembali menjadi kode SVG yang sama dengan yang di-encode. Diunduh sebagai Original, file itu adalah SVG yang valid dan diskalakan tanpa kehilangan ketajaman.

Anda juga bisa mengonversi SVG hasil dekode menjadi PNG raster. Itu berguna saat tujuannya membutuhkan gambar berukuran tetap, bukan vektor yang bisa diskalakan, dan alat merender SVG dengan tajam pada ukuran intrinsiknya.

Apa yang Terjadi dengan String yang Rusak

String yang rusak atau string Base64 yang bukan gambar akan gagal dengan pesan error yang jelas. Alat tidak menebak, dan tidak menghasilkan file gambar yang sebagian atau rusak.

Penyebab umumnya adalah string yang terpotong saat disalin, karakter yang diubah aplikasi chat atau editor dokumen, atau string yang memang bukan gambar sejak awal.

Saat Anda melihat error itu, periksa dulu string-nya. Bandingkan panjangnya dengan aslinya jika Anda bisa, dan cari karakter yang hilang di awal atau akhir, tempat pemotongan biasanya terjadi.

Jika string berasal dari respons API, periksa apakah respons itu terpotong. Payload JSON yang terpotong menghasilkan string yang terpotong, dan tidak ada decoder yang bisa memperbaiki ekor yang hilang.

Error yang paling membingungkan adalah string yang terdekode tapi menghasilkan gambar yang salah. Biasanya penyebabnya adalah string dari gambar yang berbeda, tertukar saat disalin dari dokumen yang berisi banyak gambar.

Jika gambar hasil dekode terlihat seperti gambar lain, periksa sumber string Anda. Dokumen dengan banyak gambar tersemat sering menukar urutannya, dan satu-satunya perbaikan adalah menyalin ulang dari sumber yang benar.

Error juga bisa berasal dari karakter yang berubah saat melewati aplikasi chat. Beberapa aplikasi mengganti tanda plus dengan spasi, dan itu merusak string tanpa terlihat jelas.

Jika Anda mencurigai hal itu, minta pengirim mengirim string sebagai file teks, bukan ditempel di pesan chat. File teks menjaga karakter tetap utuh selama pengiriman.

Terakhir, simpan salinan string asli sebelum mencoba memperbaikinya. Perbaikan yang salah bisa merusak string lebih jauh, dan salinan asli adalah jalan kembali Anda.

SVG Tanpa Penanda base64

Beberapa Data URL SVG sama sekali bukan Base64. Mereka membawa kode SVG secara langsung sebagai teks yang di-encode URL, dan terlihat seperti data:image/svg+xml tanpa penanda semicolon base64.

Menempel string seperti itu ke decoder menghasilkan error encoding, karena alat mengharapkan karakter Base64 dan menemukan kurung sudut serta tanda kutip.

Perbaikannya adalah mengenali bentuknya. Jika string berisi tag SVG yang bisa dibaca seperti svg dan path, string itu adalah Data URL SVG biasa, bukan Base64, dan tidak butuh dekoding.

Simpan teks itu langsung sebagai file .svg. Buka editor teks, tempel kode SVG hasil dekode, dan simpan dengan ekstensi svg untuk mendapatkan file vektor yang valid.

Privasi: Dekoding Terjadi di Browser Anda

String Base64 sering membawa materi sensitif: respons API internal, ikon privat, token QR, atau diagram rahasia. Menempel string seperti itu ke alat online yang mengunggahnya akan berisiko.

Decoder ini bekerja secara lokal. String ditempel ke browser Anda, didekode di perangkat Anda, dan gambar yang dihasilkan tidak pernah meninggalkan komputer Anda.

Artinya alat juga berfungsi offline setelah halaman dimuat. Anda bisa mendekode string di pesawat, di kantor yang aman, atau di mana pun tanpa koneksi.

Untuk tim yang menangani data internal, dekoding lokal adalah fitur yang membuat alat ini aman dipakai. Tidak ada salinan string atau gambar yang ada di mana pun kecuali di mesin Anda sendiri.

Mendekode Gambar yang Ditemukan di Dokumen

String Base64 bersembunyi di tempat yang mungkin tidak Anda duga. Dokumen Word, PDF, dan file desain terkadang menyimpan gambar tersemat sebagai Base64 di dalam struktur XML atau JSON-nya, dan fragmen yang disalin bisa langsung didekode.

Saat Anda menemukan fragmen seperti itu, salin string dengan hati-hati, termasuk panjang penuhnya. Format dokumen sering membagi string panjang ke beberapa baris, jadi periksa apakah ada karakter yang hilang saat teks terbungkus.

Kode QR adalah kasus yang berbeda. Kode QR bisa berisi gambar kecil sebagai Data URL, tapi sebagian besar kode QR berisi tautan. Jika kode itu didekode menjadi teks yang dimulai dengan data:image, tempel teks itu ke decoder.

Aplikasi chat adalah sumber umum lainnya. Beberapa sistem chat mengirim gambar sebagai Base64 di dalam payload pesannya, dan payload yang disalin bisa didekode untuk mengembalikan gambar aslinya.

Dalam setiap kasus, pemeriksaan yang sama berlaku: konfirmasikan string lengkap, waspadai pemotongan di ujungnya, dan unduh sebagai Original terlebih dahulu. Format asli adalah kebenarannya, dan konversi apa pun bisa menunggu sampai Anda melihatnya.

Berhati-hatilah dengan string dari dokumen yang tidak tepercaya. Dekoding itu sendiri aman, tapi dokumen di sekitarnya bisa jadi upaya phishing, jadi perlakukan isi gambar dengan kecurigaan yang sama seperti lampiran yang tidak terduga.

Cara Menggunakan Decoder Base64 ke Gambar

Buka decoder Base64 ke gambar dan tempel string Anda ke area input. Dekoding dimulai otomatis, dan pratinjau muncul beserta dimensi dan ukuran file-nya.

Periksa pratinjau papan catur untuk transparansi, lalu pilih format unduhan: Original untuk menjaga file tetap persis, atau PNG, JPG, atau WebP untuk mengonversinya. File diunduh sebagai decoded_image dengan ekstensi yang cocok.

Jika string gagal, baca pesan error dan periksa pemotongan atau awalan yang hilang. Sebagian besar kegagalan adalah string yang rusak, bukan masalah pada alatnya.

Untuk versi langkah demi langkah, baca Cara Mengubah Base64 Menjadi Gambar, dan untuk perbandingan performa, lihat Base64 vs File Gambar: Performa dan Kegunaannya. Untuk membuat string sejak awal, gunakan encoder gambar ke Base64.

Pertanyaan umum

Bisakah decoder menangani string Base64 yang padding-nya hilang?

Tergantung seberapa banyak yang hilang. String yang kehilangan tanda sama dengan di akhirnya terkadang masih bisa didekode, karena decoder bisa menyimpulkan padding dari panjangnya. String yang kehilangan karakter di tengah tidak bisa diperbaiki. Jika dekode gagal, dapatkan salinan baru dari string lengkap dari sumbernya.

Kenapa gambar hasil dekode terlihat lebih kecil dari yang saya harapkan?

Gambar hasil dekode punya dimensi persis seperti file aslinya, yang mungkin lebih kecil dari ukuran yang Anda bayangkan. Ikon 64 kali 64 yang didekode dari string adalah gambar kecil, dan mengunduhnya dalam format berbeda tidak akan menambah piksel. Periksa dimensi yang ditampilkan di samping pratinjau sebelum mengunduh.

Bisakah saya mendekode beberapa string Base64 sekaligus?

Alat mendekode satu string setiap kalinya. Tempel satu string, unduh gambarnya, hapus input, lalu tempel berikutnya. Tombol clear menghapus string panjang dengan cepat, sehingga Anda bisa lanjut ke gambar berikutnya tanpa memilih dan menghapus ribuan karakter secara manual.

Apakah aman mendekode string Base64 yang saya terima dari orang asing?

Dekoding itu sendiri aman, karena alat hanya mengubah teks menjadi file gambar secara lokal di browser Anda. Jangan membuka atau menjalankan file apa pun yang datang bersama string itu, dan jangan mempercayai isi gambar secara membabi buta. Gambar hasil dekode hanyalah piksel, tapi pesan di sekitarnya bisa jadi upaya phishing.

Apa yang harus saya lakukan jika gambar hasil dekode berlatar putih, bukan transparan?

Pertama, periksa pratinjau papan catur. Jika pratinjau menunjukkan transparansi, unduh sebagai Original atau PNG, bukan JPG, karena JPG mengisi area transparan. Jika pratinjau juga menampilkan putih, gambar asli memang berlatar putih, dan tidak ada format unduhan yang bisa mengembalikan transparansi yang tidak pernah ada.

Bisakah saya mendekode string Base64 secara offline?

Bisa, begitu halaman sudah dimuat. Semua dekoding terjadi di browser Anda tanpa melibatkan server, sehingga koneksi internet tidak dibutuhkan setelah halaman awal dimuat. Hal ini membuat alat berguna di pesawat, di kantor yang aman, dan di mana pun dengan konektivitas yang tidak bisa diandalkan.
