Cara Mengubah Base64 Menjadi Gambar

Ubah string Base64 menjadi gambar dalam empat langkah: tempel, pratinjau, pilih Original, PNG, JPG, atau WebP, lalu unduh. Menangani string URL-safe dan jeda baris.

Sebuah string Base64 berada di clipboard, email, atau respons API Anda, dan Anda membutuhkan gambar yang dikandungnya. Konversinya memakan waktu sekitar satu menit begitu Anda tahu langkah-langkahnya.

Panduan ini memandu Anda mengubah Base64 menjadi gambar dalam empat langkah: tempel string, tinjau pratinjau, pilih format unduhan, lalu simpan file-nya.

Tanpa software yang perlu diinstal, tanpa akun yang perlu dibuat, dan tanpa ada yang diunggah ke mana pun. String didekode secara lokal di browser Anda dari awal sampai akhir.

Yang Anda Butuhkan Sebelum Memulai

Anda membutuhkan string Base64 itu sendiri, disalin secara lengkap. String yang terpotong tidak bisa didekode, jadi pastikan salinannya mencakup awal dan akhir.

Ketahui gambar itu untuk apa, karena itu menentukan format unduhan. Original menjaga file tetap persis, PNG menjaga transparansi, JPG mengecilkan foto, dan WebP adalah pilihan modern yang ringkas.

Browser adalah satu-satunya software yang Anda butuhkan. Alat ini berjalan di Chrome, Safari, Firefox, dan Edge, di desktop dan di HP, tanpa ekstensi.

Jika string itu dibungkus HTML atau CSS, Anda bisa menempel semuanya. Decoder menoleransi tanda kutip dan pembungkus url() di sekitar string.

Langkah 1: Tempel String Base64

Buka decoder Base64 ke gambar dan tempel string ke area input. Dekoding dimulai otomatis, tanpa tombol yang perlu diklik.

Alat menerima string dengan atau tanpa awalan data:image. Data URL lengkap dari halaman web dan string mentah dari payload JSON sama-sama berfungsi.

String URL-safe juga berfungsi. Jika string memakai dash dan underscore, bukan plus dan slash, decoder mengenali variannya dan mendekodenya dengan benar.

Jeda baris dan spasi tambahan diabaikan. String yang terbungkus klien email atau ditempel dengan whitespace di sekitarnya tetap terdekode tanpa pembersihan apa pun.

Langkah 2: Tinjau Pratinjau dan Metrik

Gambar hasil dekode muncul di atas latar papan catur, dengan dimensi dan ukuran file-nya ditampilkan di sampingnya. Periksa bahwa gambar itu memang yang Anda harapkan.

Perhatikan papan catur dengan saksama. Kotak abu-abu dan putih yang terlihat menembus gambar berarti transparansi, dan itu menentukan apakah JPG aman dipakai.

Periksa dimensinya. Ikon kecil yang didekode dari string adalah gambar kecil, dan tidak ada format unduhan yang akan membuatnya lebih besar atau lebih tajam daripada yang sudah ada.

Periksa ukuran file binernya. Ukuran itu seharusnya sekitar tiga perempat dari panjang teks yang Anda tempel, karena dekoding menghilangkan overhead encoding 33 persen.

Langkah 3: Pilih Format Unduhan

Pilih Original saat Anda menginginkan file persis seperti saat di-encode. Ini pilihan paling aman, terutama untuk GIF animasi dan SVG vektor, yang kehilangan sifat khususnya saat dikonversi.

Pilih PNG saat gambar punya transparansi atau tepi yang tajam. PNG mempertahankan piksel secara persis dan menjaga channel alpha, sehingga logo dan ikon selamat dalam perjalanan pulang-pergi.

Pilih JPG saat gambar adalah foto dan Anda menginginkan file terkecil. JPG membuang transparansi, jadi pakai hanya saat pratinjau papan catur tidak menunjukkan area tembus pandang.

Pilih WebP saat tujuannya adalah situs web modern. WebP lebih kecil daripada PNG untuk sebagian besar gambar dan mendukung transparansi, sehingga menjadi default yang baik untuk web.

Langkah 4: Unduh File Gambar

Klik tombol unduh. File tersimpan sebagai decoded_image dengan ekstensi yang cocok dengan format pilihan Anda, contohnya decoded_image.png atau decoded_image.jpg.

Segera ganti nama file menjadi sesuatu yang bermakna. Folder yang penuh file bernama decoded_image membingungkan, sementara nama seperti company-logo.png memberi tahu apa isinya berbulan-bulan kemudian.

Buka file yang diunduh dan konfirmasikan tampilannya benar. Pratinjau di alat memang bisa diandalkan, tapi pemeriksaan akhir pada file sebenarnya hanya butuh beberapa detik dan menangkap kesalahpahaman apa pun.

Jika Anda perlu meng-encode gambar itu lagi nanti, encoder gambar ke Base64 mengambil file yang diunduh dan menghasilkan string baru darinya.

Mendekode String Tanpa Awalan

Banyak string tiba tanpa awalan data:image, terutama dari API dan database. Decoder membaca header gambar untuk mengidentifikasi formatnya, sehingga awalan yang hilang bukan masalah.

Tempel string mentah apa adanya. Alat mendeteksi apakah byte-nya menjelaskan file PNG, JPG, GIF, WebP, SVG, BMP, atau ICO, dan menampilkan format yang terdeteksi di samping pratinjau.

Jika formatnya terdeteksi salah, header file itu sendiri tidak biasa. Unduh sebagai Original dalam kasus itu, dan periksa file dengan penampil gambar sebelum mengonversinya.

Saat Anda membagikan string itu ke orang lain, pertimbangkan menambahkan awalan sendiri. Data URL menjelaskan dirinya sendiri, dan orang berikutnya yang menerimanya akan tahu formatnya tanpa menebak.

Mendekode String URL-Safe

Base64 URL-safe mengganti plus dengan dash dan slash dengan underscore, sehingga string bisa berada di dalam alamat web tanpa di-escape. Bentuknya terlihat hampir identik dengan Base64 standar.

Decoder menerima kedua alfabet itu tanpa pengaturan yang perlu diubah. Tempel string dan string itu terdekode, apa pun varian yang dipakainya.

Jika string gagal terdekode, periksa campuran kedua alfabet itu. String yang terkonversi sebagian, dengan beberapa tanda plus dan beberapa dash, rusak dan butuh salinan baru dari sumbernya.

Padding juga bisa hilang dalam string URL-safe, karena beberapa sistem menghapus tanda sama dengan di akhir. Decoder menoleransi padding yang hilang dalam sebagian besar kasus, tapi string yang lengkap selalu lebih aman.

Mendekode String yang Dibungkus HTML atau CSS

String sering disalin bersama kode di sekitarnya, seperti tag gambar dengan sumber Data URL, atau fungsi url() CSS yang membungkus nilainya.

Anda bisa menempel seluruh snippet itu. Decoder menoleransi tanda kutip HTML dan pembungkus url() CSS di sekitar string, dan mengekstrak konten Base64 dari dalamnya.

Jika tempelan gagal, lepaskan pembungkusnya sendiri. Salin hanya bagian antara koma setelah base64 dan tanda kutip penutup, lalu tempel string bersih itu.

Untuk tag gambar HTML, string berada di dalam atribut src setelah data:image/png;base64,. Untuk CSS, string berada di dalam tanda kurung url(), biasanya dibungkus tanda kutip.

Mengonversi String BMP atau ICO Lama menjadi WebP

String favicon dan bitmap lama terdekode menjadi file BMP atau ICO, yang besar dan kurang didukung di web modern. Mengonversinya ke WebP memperbaiki kedua masalah itu sekaligus.

Tempel string, tunggu pratinjaunya, lalu pilih WebP sebagai format unduhan. Alat mengonversi gambar hasil dekode menjadi file modern yang ringkas.

Periksa dulu transparansinya. Favicon ICO sering punya area transparan, dan WebP mempertahankannya, sehingga ikon hasil konversi terlihat sama seperti aslinya.

Untuk favicon secara khusus, pertimbangkan mengunduh sebagai PNG. Browser menerima favicon PNG secara luas, dan file itu lebih sederhana dirujuk dari HTML Anda.

Mendekode String SVG menjadi File PNG

String Base64 SVG terdekode menjadi kode vektor, yang tajam pada ukuran berapa pun tapi tidak diterima di mana-mana. Beberapa platform menginginkan gambar raster, dan PNG adalah pilihan yang umum.

Tempel string, konfirmasikan pratinjau menampilkan grafis vektor dengan benar, lalu pilih PNG sebagai format unduhan. Alat merender SVG menjadi PNG pada dimensi intrinsiknya.

PNG yang dihasilkan adalah gambar berukuran tetap, sehingga tidak akan diskalakan seperti SVG aslinya. Jika tujuannya membutuhkan gambar besar, render pada ukuran yang lebih besar sebelum mengunduh, atau pertahankan SVG-nya.

Jika string itu adalah Data URL SVG biasa tanpa penanda base64, string itu akan gagal dengan error encoding. String itu sama sekali bukan Base64, jadi simpan kode SVG secara langsung sebagai file.

Troubleshooting String yang Rusak

String yang gagal terdekode biasanya terpotong, diubah, atau memang bukan gambar sejak awal. Alat melaporkan error yang jelas, bukan menghasilkan file yang rusak.

Periksa awal dan akhir string terlebih dahulu. Pemotongan biasanya memotong ekornya, sehingga string yang berakhir di tengah kata atau tanpa padding-nya adalah tanda salinan yang tidak lengkap.

Cari karakter yang tidak termasuk dalam Base64. Kurung sudut, tanda kutip di dalam string, atau URL dengan parameter tambahan semuanya menunjukkan salinan itu ikut mengambil teks di sekitarnya.

Saat sumbernya respons API, periksa apakah respons itu sendiri terpotong. Payload JSON yang terpotong menghasilkan string yang terpotong, dan hanya request baru yang bisa memperbaikinya.

String yang terpotong di tengah sering berasal dari batas panjang pesan. Beberapa aplikasi chat membatasi panjang satu pesan, dan string yang panjang terpotong tanpa peringatan.

Jika Anda menerima string lewat chat, tanyakan apakah pengirim mengirimnya sebagai file. File lampiran tidak punya batas panjang pesan, dan string tiba secara utuh.

Email juga bisa memotong string. Klien email yang membungkus teks pada 76 karakter menyisipkan jeda baris, dan meskipun decoder menoleransinya, beberapa klien justru menghapus karakter saat membungkus.

Untuk string yang sangat panjang, cara paling aman adalah berbagi lewat tautan file atau penyimpanan cloud. Pengirim mengunggah file teks berisi string, dan penerima mengunduhnya tanpa perubahan apa pun.

Saat Anda mencurigai string terpotong, bandingkan panjangnya dengan yang diharapkan. String Base64 yang lengkap panjangnya kelipatan empat, dan panjang yang bukan kelipatan empat adalah tanda ada yang hilang.

Troubleshooting Error Encoding SVG

Error encoding SVG muncul saat string yang ditempel adalah Data URL SVG biasa, bukan Base64. String itu berisi tag SVG yang bisa dibaca, bukan karakter yang ter-encode.

Kenali dari tampilannya. Jika Anda bisa membaca kata-kata seperti svg, path, atau rect di dalamnya, string itu adalah kode SVG yang di-encode URL, bukan Base64.

Untuk mendapatkan file-nya, salin kode SVG keluar dari Data URL, dekode escape persen apa pun, dan simpan hasilnya sebagai file .svg di editor teks.

Jangan mencoba memaksanya melalui decoder. Alat mengharapkan karakter Base64, dan tidak ada pengaturan yang akan membuatnya menerima markup SVG biasa sebagai string ter-encode.

Menghapus Input untuk String Berikutnya

String panjang sulit dihapus dengan tangan, sehingga alat menyediakan tombol clear yang mengosongkan input dalam satu klik. Gunakan di antara dekode untuk memulai dari awal.

Hapus sebelum menempel string berikutnya, bukan sesudahnya. Menempel di atas string panjang bisa menyisakan fragmen string lama, dan itu merusak dekode yang baru.

Unduh gambar saat ini sebelum Anda menghapus. Menghapus menghilangkan string dan pratinjau secara bersamaan, dan gambar hasil dekode hanya ada sebagai file yang diunduh setelah itu.

Mengerjakan batch string dengan cara ini cepat: tempel, unduh, hapus, lalu tempel berikutnya, tanpa scrolling atau seleksi manual di antaranya.

Meng-encode Ulang Gambar yang Diunduh

Terkadang gambar hasil dekode perlu kembali ke bentuk teks, misalnya setelah mengonversi BMP lama menjadi WebP modern. Encoder menangani langkah itu.

Buka encoder gambar ke Base64, unggah file yang diunduh, dan salin string baru dalam format output yang Anda butuhkan.

String baru lebih pendek daripada aslinya saat konversi mengecilkan file. BMP yang dikonversi ke WebP sebelum di-encode ulang menghasilkan string yang jauh lebih pendek daripada aslinya.

Simpan kedua string sampai Anda yakin string yang baru berfungsi. String asli adalah satu-satunya salinan file asli, dan menghapusnya sebelum pengujian adalah risiko yang tidak perlu.

Mendekode Gambar dari Pesan Chat dan Dokumen

Aplikasi chat dan alat kolaborasi terkadang menampilkan gambar sebagai string Base64 dalam data pesannya, terutama dalam bot, webhook, dan percakapan yang diekspor. Payload yang disalin bisa didekode untuk mengembalikan gambarnya.

Saat Anda menyalin dari ekspor chat, waspadai string yang terbagi ke beberapa baris atau terbungkus escaping JSON. Backslash sebelum slash dan tanda kutip adalah artefak escaping, bukan bagian dari string, dan harus dihapus sebelum dekoding.

Dokumen adalah sumber yang serupa. File Word atau desain yang diekspor bisa berisi gambar tersemat sebagai blok Base64 di dalam XML-nya, dan menyalin blok itu langsung memberi Anda gambarnya.

Peringatan pemotongan yang sama berlaku di mana-mana. String yang disalin dari pesan yang terpotong di tengah jalan akan gagal terdekode, dan satu-satunya perbaikan adalah salinan lengkap dari sumbernya.

Untuk ekspor chat yang besar, dekode satu gambar setiap kalinya dan segera ganti nama setiap unduhan. Batch file yang semuanya bernama decoded_image membingungkan, sementara nama seperti team-photo-decoded.png tetap berguna.

Ingat bahwa gambar hasil dekode dari log chat bisa jadi thumbnail, bukan aslinya. Periksa dimensi di samping pratinjau sebelum Anda menganggap file itu beresolusi penuh.

Saat string berasal dari sistem yang Anda kendalikan, pertimbangkan mengubah alur kerja untuk mengirim file, bukan string. Transfer file lebih efisien, dan perjalanan pulang-pergi Base64 ada terutama untuk sistem yang tidak bisa membawa data biner.

Saat string berasal dari sistem yang tidak Anda kendalikan, dekoding adalah satu-satunya pilihan, dan alat ini menanganinya secara lokal tanpa mengunggah string ke mana pun.

Untuk string yang diterima lewat email, periksa lampirannya terlebih dahulu. Pengirim yang bijak mengirim string panjang sebagai file .txt terlampir, bukan ditempel di badan email yang bisa membungkus teks.

Jika email hanya berisi string di badannya, salin dengan hati-hati dari awal sampai akhir. Satu baris yang terlewat saat menyalin sudah cukup untuk membuat dekode gagal.

Checklist Referensi Cepat

Tempel string lengkap, periksa pratinjau dan papan catur untuk transparansi, pilih Original, PNG, JPG, atau WebP, lalu unduh sebagai decoded_image dengan ekstensi yang tepat.

Hapus input di antara string, segera ganti nama unduhan, dan simpan string asli sampai file baru teruji.

Pertanyaan umum

Bisakah saya mendekode string Base64 di HP?

Bisa. Decoder berjalan di browser HP iOS dan Android. Tempel string, tinjau pratinjaunya, lalu unduh gambarnya. Untuk string yang sangat panjang, menempel bisa lambat, jadi uji dulu dengan string pendek untuk mengonfirmasi alur kerjanya.

Berapa string Base64 terbesar yang bisa saya dekode?

Tidak ada batas tetap di alat ini, tapi string yang sangat besar butuh waktu lebih lama karena browser harus mengurai semua teks dan membangun ulang data biner. String bermegabyte bisa berfungsi, meskipun bisa lambat di HP lama. Jika string terlalu besar untuk ditangani, mintalah gambar sebagai file dari sumbernya.

Kenapa file hasil dekode namanya berbeda dari aslinya?

String Base64 tidak membawa nama file asli, sehingga alat tidak bisa mengetahuinya. Setiap unduhan diberi nama decoded_image dengan ekstensi yang cocok. Ganti nama file segera setelah mengunduh agar folder Anda tetap teratur.

Bisakah saya mendekode string Base64 yang berasal dari PDF atau dokumen Word?

Hanya jika string itu sendiri adalah gambar Base64 yang valid. Dokumen sering menyimpan gambar dalam bentuk lain, seperti data biner tersemat atau stream terkompres, yang bukan Base64. Ekstrak dulu gambar dari dokumen, lalu encode atau dekode sesuai kebutuhan.

Apakah mendekode string Base64 menurunkan kualitasnya?

Tidak. Dekoding adalah kebalikan persis dari encoding, sehingga byte yang keluar adalah byte yang masuk. Kehilangan kualitas apa pun terjadi sebelum encoding, saat gambar dikompres atau dikonversi, dan dekoding tidak bisa menambah atau memperbaikinya.

Apa yang harus saya lakukan jika string terdekode tapi gambarnya terlihat salah?

Pertama, periksa apakah Anda mengunduh format yang tepat. PNG transparan yang diunduh sebagai JPG akan membuat transparansinya terisi, dan GIF animasi yang dikonversi ke PNG kehilangan animasinya. Unduh sebagai Original untuk melihat file yang sebenarnya, lalu putuskan konversinya dari sana.
