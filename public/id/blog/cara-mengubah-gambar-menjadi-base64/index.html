Cara Mengubah Gambar Menjadi Base64 di Kode

Ubah gambar menjadi Base64: unggah, pilih output Data URL, mentah, HTML, atau CSS, lalu salin atau unduh. Berfungsi untuk PNG, JPG, SVG, GIF, dan ICO.

Anda membutuhkan gambar sebagai teks: logo untuk stylesheet, ikon untuk email, atau gambar untuk payload JSON. Konversinya memakan waktu sekitar satu menit begitu Anda tahu langkah-langkahnya.

Panduan ini memandu Anda mengubah gambar menjadi Base64 dalam empat langkah: unggah file, pilih format output, salin atau unduh string-nya, lalu tempel ke dalam kode Anda.

Tanpa software yang perlu diinstal, tanpa akun yang perlu dibuat, dan tanpa ada yang diunggah ke mana pun. Gambar di-encode secara lokal di browser Anda dari awal sampai akhir.

Yang Anda Butuhkan Sebelum Memulai

Anda membutuhkan file gambar itu sendiri, dalam format PNG, JPG, WebP, GIF, SVG, BMP, atau ICO, hingga 15 MB. Logo, ikon, dan foto kecil adalah kandidat yang umum.

Ketahui ke mana string itu akan pergi. Halaman HTML menginginkan Data URL, stylesheet menginginkan nilai url() CSS, dan API biasanya menginginkan string mentah tanpa awalan apa pun.

Jika gambarnya besar, pertimbangkan untuk mengecilkannya terlebih dahulu. Foto 2 MB menjadi string 2,7 MB, yang sulit disalin dan lambat diurai, sementara versi terkompresnya bisa sepersepuluh dari itu.

Browser adalah satu-satunya software yang Anda butuhkan. Alat ini berjalan di Chrome, Safari, Firefox, dan Edge, di desktop dan di HP, tanpa ekstensi.

Langkah 1: Unggah Gambar atau Tempel Tangkapan Layar

Buka konverter gambar ke Base64 dan seret gambar Anda ke area unggah. Anda juga bisa mengklik area tersebut untuk memilih file dari perangkat.

Jika gambar sedang tampil di layar Anda, salin lalu tempel dengan Ctrl+V. Alat menerima gambar dari clipboard secara langsung, sehingga tangkapan layar bisa di-encode tanpa menyimpan file terlebih dahulu.

Alat membaca file dan menampilkan pratinjau beserta dimensi dan formatnya. Periksa bahwa pratinjau itu memang gambar yang Anda maksud, karena string yang Anda salin adalah file yang persis ini.

Jika Anda mengunggah file yang salah, encode gambar lain dari dalam alat. Output sebelumnya diganti, dan Anda bisa terus bekerja tanpa memuat ulang halaman.

Langkah 2: Pilih Format Output

Empat tab berada di atas area output: Data URL, Raw, HTML, dan CSS. Pilih tab yang cocok dengan tempat string itu akan pergi.

Pilih Data URL saat Anda butuh URI lengkap untuk sumber gambar atau background stylesheet. Format ini menyertakan tipe media dan penanda encoding, sehingga berfungsi di mana pun URL berfungsi.

Pilih Raw saat Anda mengirim gambar ke API atau menyimpannya di database. Output mentah adalah string saja, tanpa awalan, dan itulah bentuk yang diharapkan sebagian besar API.

Pilih HTML saat Anda menginginkan elemen gambar yang siap pakai. Alat menghasilkan tag dengan Data URL sebagai sumbernya dan mengisi atribut lebar dan tinggi secara otomatis. Pilih CSS saat Anda menginginkan nilai url() untuk background atau mask.

Langkah 3: Salin Output atau Unduh

Klik tombol Copy Output untuk menaruh string ke clipboard Anda. Untuk string pendek seperti ikon dan logo, ini saja sudah cukup.

Untuk string panjang, gunakan tombol unduh. Menyalin string bermegabyte bisa lambat atau tidak bisa diandalkan, sementara file teks yang diunduh membawa output yang persis tanpa pemotongan.

Jika browser Anda memblokir akses clipboard, alat akan memberi tahu Anda. Izinkan izin clipboard untuk halaman itu, atau gunakan tombol unduh sebagai jalan keluar yang tidak butuh izin sama sekali.

Periksa persentase overhead yang ditampilkan di samping output. Persentase itu memberi tahu seberapa besar string dibandingkan file aslinya, yang biasanya sekitar 33 persen ditambah sedikit untuk pembungkusnya.

Langkah 4: Tempel String ke Dalam Kode Anda

Tempel output di tempatnya: Data URL ke sumber gambar atau stylesheet, string mentah ke kolom JSON, snippet HTML ke halaman, atau nilai CSS ke properti background.

Segera uji hasilnya. Buka halamannya, kirim email uji, atau panggil API-nya, dan konfirmasikan gambarnya muncul. String yang ditempel ke kolom yang salah akan gagal secara diam-diam atau menampilkan gambar rusak.

Simpan file gambar aslinya. Jika versi yang disematkan suatu saat perlu diubah, Anda akan meng-encode ulang dari file asli, bukan mendekode string lalu meng-encodenya lagi.

Untuk logo atau ikon, pertimbangkan menyimpan snippet itu di proyek Anda sebagai variabel atau partial yang bisa dipakai ulang. Dengan begitu string yang panjang tinggal di satu tempat, bukan ditempel ke setiap file yang membutuhkannya.

Meng-encode Logo SVG

Logo SVG ter-encode dengan bersih karena sudah berupa teks. Unggah file SVG dan alat menghasilkan string Base64 yang didekode kembali menjadi grafis vektor yang sama.

Data URL untuk SVG dimulai dengan data:image/svg+xml;base64, diikuti string-nya. Tempel ke sumber gambar dan logo dirender tajam pada ukuran berapa pun.

Tapi perhatikan ukurannya. SVG yang kompleks dengan banyak path bisa berukuran besar, dan bentuk Base64-nya sepertiga lebih besar lagi. Logo sederhana tidak masalah; ilustrasi yang detail mungkin lebih baik ditautkan sebagai file.

Untuk SVG yang sangat kecil, pertimbangkan SVG yang di-encode URL biasa, bukan Base64. Bentuk itu lebih pendek, tapi butuh escaping yang hati-hati, sehingga Base64 tetap menjadi default yang lebih aman bagi kebanyakan orang.

Meng-encode Favicon

File ICO favicon berfungsi di konverter sama seperti format lainnya. Unggah file .ico dan salin Data URL-nya untuk dipakai di halaman satu file atau template email.

Sebagian besar situs sebaiknya menautkan favicon sebagai file, bukan menyematkannya. Favicon yang ditautkan di-cache oleh browser, sementara favicon yang disematkan diunduh bersama setiap halaman yang memuatnya.

Penyematan masuk akal untuk halaman satu file, dokumen offline, dan template email, tempat tidak ada file terpisah yang bisa diambil. Dalam konteks itu, ikon yang disematkan adalah satu-satunya cara favicon muncul.

Jika Anda belum punya favicon, generator favicon bisa membuatnya dari gambar apa pun, lalu Anda bisa meng-encode hasilnya di sini.

Meng-encode Gambar untuk Email HTML

Email HTML tidak bisa mengandalkan file gambar eksternal, karena banyak klien memblokir gambar jarak jauh secara default. Menyematkan gambar sebagai Data URL membuatnya langsung muncul, bahkan saat offline.

Jagalah gambar email yang disematkan tetap kecil. Logo atau banner kecil berfungsi dengan baik, tapi foto besar membuat pesan berat dan lambat dibuka di HP.

Uji sebelum mengirim. Beberapa klien email memblokir gambar Base64 inline, dan pesan Anda bisa tiba dengan gambar rusak bagi pembaca itu. Kirim uji ke klien yang dipakai audiens Anda.

Saat klien memblokir Base64, kembali ke gambar yang di-host dengan URL normal. Gambar yang di-host membutuhkan pembaca memuat konten jarak jauh, tapi berfungsi di setiap klien yang mengizinkannya.

Meng-encode Gambar untuk Payload JSON API

JSON tidak bisa membawa data biner, sehingga endpoint unggah gambar yang menerima JSON mengharapkan gambar sebagai string Base64. Tab output mentah memberi Anda bentuk yang persis itu.

Salin string mentah ke kolom JSON yang didokumentasikan API, dan kirim tipe media di kolom terpisah jika API memintanya. Server mendekode string dan membangun ulang file.

Perhatikan ukuran payload. Gambar 1 MB menjadi kolom JSON 1,4 MB, dan beberapa API menolak payload di atas batas. Kompres gambar sebelum meng-encode jika API punya batas ukuran.

Uji dulu dengan gambar kecil. Round trip yang berhasil dengan ikon kecil membuktikan nama kolom dan formatnya sudah benar sebelum Anda mengirim gambar produksi yang besar.

Mengecilkan Gambar Sebelum Meng-encode

Meng-encode gambar besar menghasilkan string yang sangat panjang, dan string panjang sulit disalin, lambat diurai, dan berat disimpan. Mengecilkan terlebih dahulu hampir selalu sepadan.

Kompres gambar dengan kompresor gambar sebelum Anda meng-encodenya. Foto yang dikurangi dari 2 MB menjadi 200 KB menghasilkan string sepuluh kali lebih pendek, dengan kehilangan kualitas yang biasanya tidak terlihat.

Ubah ukuran juga saat ukuran tampilannya kecil. Ikon yang ditampilkan pada 64 piksel tidak butuh sumber 2000 piksel, dan sumber yang lebih kecil ter-encode menjadi string yang jauh lebih pendek.

Untuk foto, konversi ke JPG sebelum meng-encode jika transparansi tidak dibutuhkan. File JPG jauh lebih kecil daripada PNG untuk foto, dan file yang lebih kecil berarti string yang lebih pendek.

Format file juga memengaruhi panjang string. Foto yang disimpan sebagai PNG bisa sepuluh kali lebih besar daripada foto yang sama sebagai JPG, dan string Base64-nya ikut sepuluh kali lebih panjang.

Sebelum meng-encode foto, tanyakan apakah transparansi dibutuhkan. Jika tidak, konversi ke JPG terlebih dahulu. Langkah kecil itu sering memangkas string hingga sepertiganya tanpa perubahan yang terlihat.

Untuk ikon dan logo, pertimbangkan SVG, bukan PNG. SVG yang sederhana ter-encode menjadi string yang jauh lebih pendek daripada PNG dengan ukuran tampilan yang sama.

Perhatikan juga dimensi tampilan. Gambar yang ditampilkan selebar 200 piksel tidak butuh sumber 2000 piksel. Mengubah ukuran ke 400 piksel sebelum meng-encode memangkas string secara dramatis.

Buat kebiasaan memeriksa ukuran file sebelum meng-encode. Jika file di atas 500 KB, kecilkan dulu. Jika di bawah 50 KB, Anda bisa langsung meng-encode tanpa khawatir string-nya terlalu panjang.

Troubleshooting Masalah Salin Clipboard

Jika tombol salin tidak melakukan apa-apa, browser Anda mungkin memblokir akses clipboard. Alat akan menampilkan pesan yang menjelaskan pemblokiran itu, dan Anda bisa mengizinkan izin untuk halaman tersebut.

Beberapa browser hanya mengizinkan penulisan clipboard setelah gestur pengguna di halaman yang aman. Mengklik tombol dihitung sebagai gestur, tapi browser lama atau pengaturan yang ketat tetap bisa menolak.

Tombol unduh adalah jalan keluar yang bisa diandalkan. Tombol itu menyimpan output persis sebagai file teks tanpa melibatkan clipboard, dan Anda bisa membuka file itu lalu menyalin dari sana.

Di HP, string panjang bisa lambat disalin. Unduh file output sebagai gantinya, lalu bagikan ke aplikasi tempat Anda membutuhkannya, daripada bergulat dengan clipboard.

Troubleshooting String yang Sangat Panjang

String panjang adalah hal normal untuk gambar besar, tapi bisa membuat editor Anda lambat. Menempel string 2 MB ke file kode bisa membekukan editor ringan selama beberapa detik.

Bagi pekerjaannya: simpan string di file atau variabel terpisah, dan rujuk dari kode yang membutuhkannya. Cara itu menjaga file utama Anda tetap mudah dibaca dan editor tetap responsif.

Jika string merusak build Anda, periksa batas panjang baris. Beberapa alat membungkus atau memotong baris yang sangat panjang, dan itu merusak string. File yang diunduh sepenuhnya menghindari masalah itu.

Saat string terasa terlalu panjang untuk dikelola, pertimbangkan lagi apakah menyematkan memang tepat. File gambar yang ditautkan sering menjadi pilihan yang lebih baik untuk apa pun di atas beberapa ratus kilobyte.

Meng-encode Gambar Lain Setelah yang Pertama

Untuk meng-encode gambar kedua, unggah dari dalam alat tanpa memuat ulang halaman. Gambar baru menggantikan yang lama, dan output diperbarui ke string yang baru.

Salin output pertama sebelum Anda berganti, karena mengganti gambar akan menghapus string sebelumnya. File yang diunduh adalah catatan paling aman jika Anda membutuhkan kedua string itu.

Mengerjakan satu set ikon dengan cara ini cepat. Unggah, salin, unggah berikutnya, salin lagi, dan seluruh set ikon ter-encode dalam beberapa menit.

Jagalah file asli tetap teratur saat Anda bekerja. Folder berisi gambar sumber dan folder berisi file output teks yang cocok mencegah kebingungan yang terjadi saat semua string terlihat sama.

Meng-encode Gambar untuk Media Sosial dan Pesan

Postingan sosial dan pesan chat terkadang hanya menerima gambar sebagai teks, terutama dalam bot, webhook, dan alur kerja otomatis. String Base64 memungkinkan gambar berjalan di dalam payload pesan yang hanya berisi teks.

Jagalah gambar ini tetap kecil. API chat bisa membatasi ukuran pesan hingga beberapa puluh kilobyte, dan foto yang di-encode ke Base64 akan melampaui batas itu sebelum tiba.

Untuk chatbot, ikon kecil atau thumbnail di bawah 10 KB ter-encode menjadi string yang muat dengan nyaman di dalam pesan. Apa pun yang lebih besar sebaiknya diunggah sebagai file dan dirujuk dengan URL.

Beberapa alat otomatisasi menerima Data URL di tempat yang seharusnya membutuhkan gambar yang di-host. Hal itu berguna saat gambar dibuat secara langsung dan belum ada tempat untuk meng-host-nya.

Uji round trip penuh sebelum Anda mengotomasinya. Kirim satu pesan dengan gambar yang ter-encode, konfirmasikan gambar itu dirender di sisi penerima, dan barulah bangun alur kerja di sekitarnya.

Ingat bahwa string itu terlihat oleh siapa pun yang bisa melihat payload pesan. Jangan meng-encode foto privat ke dalam pesan, log, atau webhook tempat teks itu bisa disimpan atau diteruskan.

Jika Anda meng-encode banyak ikon untuk satu proyek, buat daftar nama file dan string-nya. Daftar itu mencegah kebingungan saat dua ikon terlihat mirip dan string-nya tertukar.

Untuk tim, simpan string hasil encode di repositori bersama kode, bukan di pesan chat. String di chat mudah hilang atau terpotong, sementara string di repositori tercatat dalam riwayat versi.

Checklist Referensi Cepat

Unggah gambar, pilih tab output untuk tujuan Anda, lalu salin atau unduh string-nya. Uji di tempatnya sebelum mengirim apa pun yang bergantung padanya.

Kecilkan gambar besar sebelum meng-encode, gunakan raw Base64 untuk API, dan lebih pilih file yang ditautkan daripada string yang disematkan untuk apa pun yang besar atau dibagikan di banyak halaman.

Untuk latar belakang lengkapnya, baca Gambar ke Base64: Panduan Lengkap, dan untuk kerangka keputusannya, lihat Gambar Base64: Kapan Disematkan dan Kapan Tidak. Untuk mendekode string kembali menjadi file, gunakan decoder Base64 ke gambar.

Pertanyaan umum

Bisakah saya mengubah gambar menjadi Base64 di HP?

Bisa. Konverter berjalan di browser HP iOS dan Android. Unggah gambar dari galeri Anda, pilih tab output, lalu salin string-nya. Untuk string yang sangat panjang, unduh file output-nya, bukan menyalin, karena clipboard HP bisa kesulitan dengan teks besar.

Kenapa tab HTML menambahkan lebar dan tinggi ke tag gambar?

Browser membutuhkan dimensi untuk menyediakan ruang sebelum gambar didekode. Tanpa dimensi itu, layout halaman bergeser saat gambar muncul, dan itu merugikan pengalaman membaca serta skor layout shift. Alat mengisi atribut itu secara otomatis dari dimensi gambar.

Sebaiknya saya pakai Base64 atau file gambar normal untuk logo situs web saya?

Untuk logo yang muncul di banyak halaman, file normal yang ditautkan biasanya lebih baik karena browser meng-cache-nya sekali. Base64 menang saat halaman harus berupa satu file, saat logonya sangat kecil, atau saat tidak ada request terpisah yang diizinkan. Untuk sebagian besar situs, tautkan logonya.

Apa bedanya Data URL dan raw Base64?

Data URL adalah URI lengkap dengan awalan data, tipe media, dan penanda encoding, siap dipakai sebagai sumber gambar. Raw Base64 adalah string saja, tanpa awalan, dan itulah bentuk yang biasanya diharapkan API dan database. Alat menghasilkan keduanya dari gambar yang sama.

Apakah mengubah ke Base64 menghapus metadata dari gambar saya?

Encoding itu sendiri tidak menghapus apa pun, karena string membawa byte asli secara persis. Namun, beberapa alur kerja menghapus metadata sebelum meng-encode agar string-nya lebih pendek. Jika privasi penting, hapus dulu metadata dengan alat penghapus metadata, lalu encode file yang sudah bersih.

Bisakah saya meng-encode tangkapan layar langsung tanpa menyimpan file?

Bisa. Salin tangkapan layar dan tekan Ctrl+V di alat, dan tangkapan itu akan langsung ter-encode. Ini cara tercepat mendapatkan Data URL untuk screen capture, elemen UI, atau diagram yang sedang Anda lihat.
