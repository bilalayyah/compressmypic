JPG vs WebP｜ファイルサイズ・画質・対応ブラウザを徹底比較

JPGとWebPを直接比較。ファイルサイズの節約、画質、透過、ブラウザ対応、どちらを使うべき場面まで解説します。WebPは軽くて高画質ですが、古い環境ではJPGが必要なため、用途と対応状況で選ぶポイントがわかります。WebPにすれば軽くなって表示が速くなるため、サイト運営に役立ちます。

JPGは30年間、Webを支配してきました。WebPは、Googleがそれに代わるために作った挑戦者です。純粋な効率では、WebPが勝ちます。互換性では、JPGが今も王座を保ちます。

両者の選択は、理論上どちらが優れているかではありません。画像がどこに置かれ、誰が見るのか、その画像にとって何が最も重要かです。

この比較では、ファイルサイズ、画質、透過、対応状況を扱います。流行ではなく、事実で判断できるようになります。

JPGの概要

JPGは、1992年からの写真向け非可逆形式です。ファイルを小さくするために細部を捨て、その仕事を十分にこなして30年生き延びました。

地球上のすべての端末、ブラウザ、プリンター、アップロードフォームが、JPGを開けます。JPGを拒否する主流のシステムは存在せず、今まで一度もありませんでした。

JPGは8ビットカラーのみで、透過には対応しません。JPGは、画素の平らな長方形です。シンプルで、信頼でき、同時に制限もあります。

形式の古さが、効率に現れます。最近の形式は、同じ画質をより少ないバイトに詰め込みます。それでもJPGの万能性が、今も意味を持ち続けます。

WebPの概要

WebPは、Googleの最新の形式で、2010年に公開されました。非可逆と可逆の両方の圧縮、透過、さらにはアニメーションにも対応し、すべてを1つの形式で行います。

非可逆WebPは、同じ見た目の画質で、たいていJPGより25〜35%ファイルが小さいです。可逆WebPは、PNGより同じくらいの差で小さくなります。

WebPは透過も扱います。JPGはまったくできません。WebPのロゴは透けて見えますが、JPGのロゴは常に単色の背景を持ちます。

この形式は、今ではすべての主要なブラウザに対応しています。Chrome、Edge、Firefox、Safari、OperaはすべてWebPをネイティブに表示し、Webトラフィックのほぼすべてをカバーします。

ファイルサイズ：WebPが明確に勝つ

1MBのJPG写真は、同じ見た目の画質で、650KBから750KBのWebPになります。25〜35%の節約は、ほとんどの写真で一貫しています。

シンプルな画像では、節約はさらに大きくなります。平らな部分のあるスクリーンショットは、WebPで半分に縮む場合があります。最新のエンコーダーが、平らな色を効率よく扱うからです。

詳細な画像では、節約は小さくなります。無限の質感があるにぎやかな風景は、改善の余地が少なくなります。それでもWebPは、明確な差で勝ちます。

Webサイト全体では、節約は積み重なります。20枚の画像があるページは、10MBから7MBに下がるかもしれません。読み込み時間の目に見える改善です。

画質：WebPがわずかに勝つ

同じファイルサイズなら、WebPのほうがJPGよりよく見えます。最新の圧縮は、老朽化したJPG規格より、輪郭と質感を忠実に保ちます。

同じ見た目の画質なら、WebPのほうが小さいです。どちらの測り方でも、WebPは写真にとって効率のよい形式です。

違いは、高画質ではわずかです。90%のJPGと85%のWebPは、ほとんどの目には同じに見えます。WebPのファイルが小さいだけです。

違いは、低画質で大きくなります。60%のJPGはブロック状のノイズが出ますが、同じサイズのWebPはきれいで自然なままです。

透過：WebPが完全に勝つ

JPGは、透過をまったく保存できません。透明な部分は、単色で埋めなければならず、色付きの背景のロゴの周りに目に見える四角ができます。

WebPは、完全な透過に対応します。柔らかい輪郭や影のための部分的な透過も含みます。WebPのロゴは、PNGと同じように、どの背景の上でもきれいに収まります。

これにより、WebPはJPGだけでなく、WebでのPNGの本物の代わりにもなります。ロゴ、アイコン、ステッカーはすべて、PNGより小さいファイルでWebPとして機能します。

透過が必要な画像には、JPGはまったく選択肢になりません。比較はWebPとPNGの間で行われ、サイズではWebPがたいてい勝ちます。

ブラウザ対応：JPGが勝ち、WebPが追いつく

JPGは、Internet Explorerを含む、作られたすべてのブラウザで機能します。どれだけ古いソフトでも、JPGを見られない訪問者はいません。

WebPは、すべての最近のブラウザで機能します。Chrome、Edge、Firefox、Safari 14以降、Operaはすべて対応しており、トラフィックの圧倒的多数をカバーします。

差は、今ではわずかです。Safariは2020年に対応を追加し、残る非対応のブラウザは、使用量がわずかな古い版だけです。

古代のブラウザを使う少数の訪問者には、JPGのフォールバックを提供してください。HTMLのpicture要素を使えば、WebPを先に、JPGを次に提供でき、すべての人が画像を見られます。

ブラウザ以外の対応状況

メールソフトは分かれています。一部はWebPを表示しますが、他は表示しないので、メールで送る画像はJPGが安全な選択であり続けます。

プリンターや写真現像所は、ほとんどJPGかPNGを想定しています。印刷所に送ったWebPファイルは却下される場合があるので、印刷作業はJPGに変換してください。

デスクトップの写真編集ソフトは、追いつきつつあります。Photoshopは今ではWebPに対応していますが、多くの古い編集ソフトは対応していません。編集ワークフローでは、JPGが今も安全な選択です。

SNSは、アップロードをどちらにせよ独自の形式に変換するので、元の形式はそこであまり重要ではありません。JPGかWebPでアップロードすれば、プラットフォームが残りを処理します。

JPGを使うべきとき

送り先が分からない場合は、JPGを使ってください。フォーム、クライアント、プリンター、メールの受け取り人は、JPGを常に受け付けます。WebPは却下される場合があります。

メールの添付には、JPGを使ってください。メールソフトはJPGを確実に表示します。メールでのWebP対応は、アプリによって今もまちまちです。

印刷作業には、JPGを使ってください。印刷所はJPGかPNGを想定しており、WebPファイルは紙の上では利点がなく、互換性のリスクだけを加えます。

Webサイトのフォールバック形式として、JPGを使ってください。最近のブラウザにはWebPを、古いブラウザにはJPGを提供すれば、すべての訪問者が画像を見られます。

WebPを使うべきとき

Webサイトの画像には、WebPを使ってください。ファイルが小さいほど、ページの表示が速くなり、訪問者の体験と検索順位が改善します。

オンラインストアの商品写真には、WebPを使ってください。数百の画像があるカタログは、各画像が30%小さくなれば、はるかに速く読み込めます。

ブログの画像やスクリーンショットには、WebPを使ってください。同じサイズのJPGより文字がシャープに残り、ページは目に見えて速く感じます。

Webのロゴやアイコンには、WebPを使ってください。透過が機能し、ファイルはPNGより小さく、すべての最近のブラウザが表示します。

JPGとWebPの相互変換

JPGをWebPに変換するのは、80%の画質なら簡単で安全です。写真は寸法を保ち、同じに見え、ファイルは3分の1小さくなります。

WebPをJPGに変換するのも、WebPからJPGへの変換ツールを使えば同じくらい簡単です。JPGは大きくなりますが、どこでも開けます。それが変換の目的です。

常に最もよい原本から変換してください。JPGをWebPに変換し、再びJPGに戻すと、各手順で少しずつ画質が失われるので、往復は避けてください。

WebPに変換したあとも、JPGの原本を残してください。送り先がWebPを拒否する場合、再変換なしにJPGをアップロードできます。

WebPとCore Web Vitals

Googleは、Core Web Vitalsでページ速度を測定します。画像サイズは、大きな要因です。大きな画像は、メインコンテンツが表示されるまでの時間である、Largest Contentful Paintを遅くします。

サイトの画像をJPGからWebPに切り替えると、その測定が目に見えて改善することがよくあります。4秒で読み込めていたページが3秒で読み込めるようになるかもしれません。訪問者はすぐに感じます。

小さい画像は、モバイルデータも少なく使います。遅い回線の訪問者は、その違いをすぐに感じ、速いページにより長く滞在します。

検索順位もこれを反映します。Googleは、ページ速度が順位に影響すると述べており、WebP画像の速いサイトは、小さいながら本物の利点を持ちます。

結論：どちらの形式が勝つか

WebPは、効率、画質、機能で勝ちます。小さく、シャープで、より高機能で、純粋に技術的には優れた形式です。

JPGは、互換性とシンプルさで勝ちます。どこでも開け、すべてのシステムに理解され、拒否で驚かせることがありません。

Webには、JPGのフォールバック付きでWebPを使ってください。それ以外はすべてJPGです。この組み合わせで、両方の形式のよいところが得られ、悪いところは避けられます。

将来はWebPとその後継形式のものですが、現在は今もJPGが必要です。それぞれが輝く場所で使い、自由に変換してください。

メールでのJPGとWebP

メールは、JPGが今も明確に勝つ場所です。メールソフトはJPGを確実に表示しますが、WebP対応はまちまちで、メール内の壊れた画像はプロらしくありません。

WebPの画像があるニュースレターは、一部の購読者には壊れたアイコンで表示される場合があります。同じニュースレターがJPGの画像なら、すべての人に正しく表示されます。それがメールの要点です。

メールの添付でも、JPGが安全な選択です。ファイルは送れるほど小さく、すべての端末のすべてのクライアントが、特別なソフトなしに開けます。

WebPは、メールではまだ役割がありません。クライアントが一貫して採用するまで、JPGがニュースレター、添付ファイル、メールで送る署名の形式であり続けます。

すべてのニュースレターは、送る前に複数のメールソフトでテストしてください。Gmail、Outlook、Appleメールでのざっとしたテストで、購読者に届く前に壊れた画像を見つけられます。

SNSでのJPGとWebP

SNSは、アップロードを独自の形式に変換するので、元の形式より画質のほうが重要です。高画質の入力は、形式に関わらず、よりよい結果になります。

写真の投稿は、高画質のJPGでアップロードしてください。プラットフォームはどちらにせよ圧縮します。JPGの入力は、すべてのプラットフォームで最も互換性のある出発点です。

文字のあるグラフィックは、PNGか高画質のWebPでアップロードしてください。プラットフォームの圧縮を通しても、文字はシャープに残ります。告知グラフィックでは、これが重要です。

アップロード前に、プラットフォームの推奨寸法を確認してください。Instagram、Facebook、Xはそれぞれ理想のサイズがあり、形式よりサイズのほうが重要です。

アップロード後、プラットフォームの版をダウンロードして確認してください。公開された投稿をざっと見るだけで、画像がプラットフォームの処理を無事に通過したか確認できます。

印刷でのJPGとWebP

印刷所はJPGかPNGを想定しており、印刷作業にWebPの役割はありません。プリンターに送ったWebPファイルは、そのまま却下されるか、間違った色で印刷される場合があります。

印刷する写真は、90%以上のJPGが標準です。写真はきれいに印刷でき、ファイルは手頃で、印刷所のワークフローはネイティブに扱います。

文字のある印刷する書類は、JPGやWebPよりPNGのほうがよいです。可逆形式は、紙の上で文字の輪郭をすべてくっきり保ちます。

ファイルを送る前に、印刷所に好みを尋ねてください。ほとんどは、写真はJPG、グラフィックはPNGと答えます。その好みに従えば、無駄な手間を避けられます。

重要な作業は、テストプリントを1枚注文してください。1枚の小さな印刷で、色とシャープさを確認してから、大きな注文に進めます。

保管でのJPGとWebP

保管には、50年後に開ける形式が必要で、JPGのほうが安全です。30年の歴史があり、作られたすべてのシステムに対応しています。WebPはまだ若いです。

WebPはいつか保管の標準になるかもしれませんが、その日はまだ来ていません。WebPのアーカイブは、将来のソフトがその形式に対応することに依存します。可能性は高いですが、確実ではありません。

マスターには、どちらの形式も理想的ではありません。可逆のPNGやTIFFのマスターは、すべての画素を正確に保ちます。JPGと非可逆WebPは、どちらも細部を永久に捨てます。

マスターはPNGで保存し、納品用のコピーはWebPかJPGで保存してください。この分け方が、完璧なアーカイブと速い納品の両方を、どちらも損なわずに実現します。

アーカイブは、数年ごとに見直してください。形式は変わるもので、古い形式で保存したマスターは、読めなくなる前に移行する必要があるかもしれません。

5年後の形式の風景

5年後には、WebPは今のJPGと同じくらい万能になっているでしょう。ブラウザはすでに対応し、OSも追いつきつつあり、残る差は埋まりつつあります。

AVIFは、同じ期間にWebPを追い抜くかもしれません。さらに効率がよいからです。速度を気にするWebサイトはAVIFを採用し、WebPはフォールバックになります。

JPGは消えません。すべてのシステムに深く組み込まれており、今と同じように、数十年は万能のフォールバックであり続けます。

Webサイトの所有者にとって、戦略は明確です。最新の形式を、JPGのフォールバック付きで提供してください。この方法は今日機能し、形式が変わっても機能し続けます。

それ以外の人への助言は、さらにシンプルです。ファイルが開けないときは、JPGに変換してください。この助言は30年間機能してきました。これから30年も機能するでしょう。

動画サムネイルでのJPGとWebP

動画のサムネイルは、瞬時に注意を引かなければならない小さな画像です。85%のJPGサムネイルは、シャープで、小さく、すべてのプラットフォームに対応します。

WebPのサムネイルは、さらに小さいです。ページに何十ものサムネイルが表示される場合に重要です。50枚のWebPサムネイルがある動画一覧ページは、同じページのJPGよりはるかに速く読み込めます。

タイトルの重ね合わせのように、文字のあるサムネイルは、85%のWebPで、JPGより文字をシャープに保ちます。文字こそがサムネイルの中身なので、そのシャープさが重要です。

アップロード前に、プラットフォームのサムネイルのルールを確認してください。YouTube、Vimeo、その他のプラットフォームはそれぞれ推奨サイズを一覧にしており、形式よりサイズのほうが重要です。

サムネイルは、実際の表示サイズでテストしてください。フルサイズで見える欠点は、サムネイルが幅200ピクセルで表示されるなら関係ありません。

よくある質問

WebPは本当にWebサイトでJPGより優れていますか？

はい、ほとんどのWebサイトの画像では優れています。WebPは、同じ見た目の画質で25〜35%小さく、ページの表示が速くなり、Core Web Vitalsも改善します。弱点は、非常に古いブラウザとの互換性だけで、JPGのフォールバックが解決します。最近のWebサイトには、WebPが正しい選択です。

メールでWebPの画像を使えますか？

確実には使えません。一部のメールソフトはWebPを表示しますが、多くは表示せず、メール内の壊れた画像はプロらしくありません。メールの添付やニュースレターはJPGを使ってください。すべてのクライアントが表示します。WebPは、ブラウザ対応が一貫しているWebページに残してください。

WebPはPNGのように透過に対応していますか？

はい、対応しています。WebPは、柔らかい輪郭や影のための部分的な透過を含め、PNGと同じように完全な透過に対応します。そのため、WebではPNGの本物の代わりになり、たいていはるかに小さいファイルサイズで済みます。JPGは、透過をまったく保存できません。

JPGをWebPに変換すると写真の画質は傷みますか？

適切な設定なら、ほとんど傷みません。80%のWebPは、たいてい元のJPGと同じに見え、ファイルはより小さくなります。劣化が見えるのは、じっくり拡大した場合や、画質を非常に低く設定した場合だけです。Web用なら、この交換はほぼ常に割に合います。

WebサイトでWebPを使う場合、JPGのフォールバックは必要ですか？

よい慣行ですが、以前ほど必要ではありません。すべての最近のブラウザがWebPに対応しています。ただしJPGのフォールバックはコストが小さく、古いブラウザを使うまれな訪問者をカバーします。HTMLのpicture要素を使えば、両方の形式の提供は簡単です。

写真の印刷には、WebPよりJPGのほうがよいですか？

はい、よいです。プリンターや印刷所はJPGかPNGを想定しており、WebPは紙の上では利点がなく、互換性のリスクだけを加えます。印刷作業は、90%以上のJPGを使ってください。WebPはWebの形式であり、その利点は画像が画面を離れた瞬間に消えます。
