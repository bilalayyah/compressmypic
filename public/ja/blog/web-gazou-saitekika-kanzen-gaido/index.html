Web画像最適化ツールの完全ガイド

Webサイトの速さは、画像で決まります。テキストはミリ秒で読み込めますが、最適化されていない写真1枚が、ページを数秒止めることがあります。

Web画像最適化ツールは、その問題のために作られました。Webサイトの特定の場所に合わせて画像を圧縮し、そのままページに貼れるHTMLを渡します。

この記事では、プリセット、設定、そしてツールを使ってサイト全体を速くする方法を解説します。

Web画像の最適化とは

Webの最適化とは、ページ上の特定の仕事に合わせて画像を準備することです。ヒーロー画像、商品写真、サムネイルには、それぞれ異なるサイズと形式が必要です。

4つの要素があります。ファイルサイズ、寸法、形式、HTMLです。4つすべてを正しくすれば、画像は速く読み込め、シャープに見えます。

ファイルサイズがダウンロード速度を決めます。寸法が画像の収まり方を決めます。形式が互換性と画質を決めます。

HTMLが、ブラウザの画像の扱い方を決めます。遅延読み込み、幅、高さ、altテキストはすべてタグの中にあり、すべてが速度とアクセシビリティに影響します。

最適化ツールは4つすべてを一緒に処理します。それが、ファイルサイズだけを扱う普通の圧縮ツールとの違いです。

5つのWebパフォーマンスプリセット

ツールには5つのプリセットがあり、それぞれ実際のWebサイトの場所に対応しています。寸法、形式、画質を1クリックで設定します。

EC商品が初期設定です。画像を幅1200ピクセル、WebP、画質82％に制限し、商品写真に最適です。

他のプリセットは、ヒーロー画像、カード、サムネイル、SNS共有をカバーします。各プリセットは、その名前の場所に合っています。

プリセットは出発点であって、牢獄ではありません。プリセットを選んだ後、どの設定もカスタマイズでき、ページに合わせて組み合わせられます。

まず、場所に最も近いプリセットから始めましょう。結果がデザインに合わない場合にだけ、そこから調整します。

ヒーロー画像の最適化

ヒーロー画像はページの上部いっぱいに表示されるので、第一印象とLargest Contentful Paintに最も影響します。

ヒーローは、広い画面でシャープに見えるだけ大きく、大きくしすぎないことが重要です。大きすぎるヒーローは、誰も見ないピクセルに帯域幅を浪費します。

最新のサイトのヒーローにはWebPを使いましょう。同じ画質で、JPGより大きな画像を軽く保ちます。

ヒーロー画像を遅延読み込みしないこと。画面の上部にあるので、ブラウザはスクロールを待つのではなく、すぐに取得すべきです。

できればヒーローをプリロードします。最も重要な画像をブラウザに早めに伝えることで、最初の表示までの時間を実際に短縮します。

商品画像の最適化

商品画像は商品を売るので、シャープでなければなりません。ECプリセットは1200ピクセルに制限し、ほとんどのショップのレイアウトに合います。

背景はきれいに、商品は中央に保ちましょう。整った商品写真は圧縮がうまくいき、プロらしく見えます。

カタログ全体で寸法を統一します。サイズの混ざったグリッドは、圧縮がどれだけよくても乱れて見えます。

最新のショップの商品写真にはWebPが最適です。JPGを求めるマーケットプレイスでは、形式を切り替え、寸法は同じに保ちます。

アップロード後、スマホで商品ページを確認しましょう。ほとんどの買い手はモバイルで閲覧するので、画像はまずそこでよく見える必要があります。

カードとサムネイル

カードとサムネイルは小さく表示されるので、必要なデータが最も少ないです。300ピクセルで表示されるカードには、400ピクセルの画像で十分です。

小さな画像は、強い圧縮にも耐えます。画質を低くしたサムネイルでも、表示サイズが小さいのでやわらかさが隠れ、きれいに見えます。

画面の下部にあるカードは遅延読み込みします。ページを開いたときに見えないので、ブラウザは後で取得できます。

カード全体でアスペクト比を統一します。比率の混ざったグリッドは乱れて見え、ブラウザにレイアウトの再計算を強います。

サムネイルこそ、最適化の効果が最も大きい場所です。カード20枚のページは、各サムネイルを正しくサイズ設定すれば、メガバイト単位で節約できます。

「画像タグをコピー」ボタン

「画像タグをコピー」ボタンは、最適化した画像の完全なHTMLを書き出します。ソース、寸法、altテキスト、読み込み方法が含まれます。

altテキストは、ファイル名またはあなたの説明から生成されます。よいaltテキストは、アクセシビリティと検索エンジンが画像を理解する助けになります。

タグには幅と高さの属性が含まれます。これがレイアウトのずれを防ぎます。レイアウトのずれは、順位に影響するCore Web Vitalsの指標です。

画面の下部にある画像には、遅延読み込みが含まれます。ブラウザに、画像が表示領域に近づくまでダウンロードを待つよう伝えます。

タグはそのままページに貼れます。手作業での編集は不要で、すぐに使えます。

遅延読み込みの正しい使い方

遅延読み込みは、画像が必要になるまで先送りします。画像の多いページで、最も簡単な速度改善の1つです。

画面の下部にある画像に適用します。ページを開いたときに見えないので、早めにダウンロードすると帯域幅を浪費します。

ヒーローやロゴを遅延読み込みしないこと。すぐに見えるもので、遅らせると第一印象とLCPスコアが悪化します。

最適化ツールは、適切なプリセットに自動で遅延読み込みを追加します。ヒーロープリセットではオフになっており、それが正しい動きです。

遅延読み込みを追加したら、ページをテストします。スクロールして、画像が表示領域に入るとスムーズに現れることを確認します。

Web用の形式

WebPは、ほとんどのWeb画像に最適な形式です。同じ画質でJPGより小さく、PNGのように透過にも対応します。

JPGは互換性のために依然として不可欠です。メール、SNS共有、古いシステムは今もJPGを好み、SNS用OGPプリセットは自動でJPGに切り替えます。

PNGは画面の図形向きで、写真向きではありません。ロゴやアイコンはPNGでピクセル単位まで正確に残りますが、写真をPNGにすると帯域幅を浪費します。

SVGはこのツールでは扱いません。ベクター形式で、最適化ツールはJPG、PNG、WebPのようなラスター画像を扱います。

迷ったら、サイト用にはWebP、共有用にはJPGを使いましょう。最適化ツールを使えば、切り替えは1クリックです。

画質スライダー：20％から95％

画質スライダーは0から100ではなく、20から95％です。この範囲は意図的で、悪い選択からあなたを守ります。

20％を下回ると、画像は目に見えて崩れます。どんなWebサイトの場所も、その低さの画質の恩恵を受けないので、ツールはそれを提供しません。

95％を上回ると、ファイルは目に見える効果がほとんどないまま急速に大きくなります。追加のデータは、目が見ることのできない細部を保存しています。

ほとんどのプリセットは75〜85％の間にあります。この範囲が、ほぼすべての画像できれいな結果と小さなファイルサイズを両立させます。

スライダーは、プリセットの結果が画像に合わない場合にだけ調整します。細かい写真は85がよく、シンプルな図形は70で十分です。

EXIF削除とページ重量

カメラの写真には、隠れたメタデータがあります。GPSの位置情報、カメラの機種、設定です。そのデータは重さを増やし、個人情報を漏らします。

最適化ツールは、圧縮時にEXIFとGPSデータを削除します。ダウンロードしたファイルには、どこでいつ撮られたかの記録は残りません。

削除で節約できるのは1画像あたり数キロバイトだけですが、積み重なります。20枚の画像で、まとまった量になります。

プライバシーのほうが大きな利点です。公開サイトに掲載する写真には、撮影場所が含まれているべきではありません。

クライアントの仕事では、削除が不可欠です。未公開の商品やプライベートな場所が、画像のメタデータから漏れてはなりません。

サイト全体のバッチ最適化

多くの画像を1回のバッチで最適化できます。ブログ画像30枚を入れ、プリセットを選び、すべてまとめてダウンロードします。

バッチモードは、サイトの移行に最適です。ブログを新しいテーマに移行するとは、すべての画像を再最適化することであり、バッチなら数分で終わります。

バッチ全体をダウンロードする前に、いくつかの結果を確認します。よいものの中に1枚だけやわらかい画像が隠れていることがあります。

バッチ全体でプリセットを統一します。設定が混ざると結果も混ざり、公開サイトでは乱れて見えます。

プリセットではなく正確なファイルサイズの目標が必要な場合は、指定サイズ圧縮ツールに好きな数字を入力できます。

SNS共有とOGP画像

誰かがあなたのページを共有すると、プラットフォームはプレビュー画像を表示します。その画像が、新しい訪問者が最初に見るものであることが多いです。

OGP画像には特定の寸法が必要で、通常は1200×630ピクセルです。SNS用OGPプリセットは正しくサイズを設定し、JPGに切り替えます。

ファイルは数百キロバイト以下に保ちましょう。重いプレビュー画像は共有カードで遅く読み込まれ、プラットフォームによっては完全にスキップされます。

公開前に、共有カードをテストします。主要なプラットフォームにはすべて、プレビューの見た目を正確に示すデバッガがあります。

よい共有画像はシンプルで大胆です。文字は大きく、被写体は中央に、背景はすっきりさせるべきです。

Retina・高解像度画面

Retina画面は、同じ物理サイズにより多くのピクセルを詰め込みます。通常の画面でシャープに見えた画像が、Retina画面ではやわらかく見えることがあります。

修正方法は、表示サイズの2倍の幅で画像を用意することです。400ピクセル幅で表示されるサムネイルは、ファイルでは800ピクセル幅にします。

最適化ツールのプリセットは、これを考慮しています。カードプリセットは、帯域幅を浪費せずに高解像度画面でもシャープに残る画像を作ります。

小さなサムネイルでは、これはほとんど問題になりません。大きなアイキャッチ画像では、標準とRetina対応の差が目に見えます。

できれば実際の高解像度画面でテストしましょう。結果のスクリーンショットでは、確認したいやわらかさそのものが隠れてしまいます。

altテキストとアクセシビリティ

すべてのWeb画像にはaltテキストが必要です。スクリーンリーダーと検索エンジンに画像を説明し、画像の読み込みに失敗したときに表示されます。

最適化ツールは、ファイル名またはあなたの説明からaltテキストを生成します。生成されたテキストが画像をよく説明していない場合は、編集します。

altテキストは1文で書きましょう。画像が何を示しているかを説明し、125文字程度に保ちます。

装飾用の画像には、説明ではなく空のaltテキストが必要です。空白のaltは、スクリーンリーダーに画像をスキップするよう伝えます。

よいaltテキストはSEOにも役立ちます。検索エンジンはそれを読んで画像を理解し、画像検索からの流入につながることがあります。

画像のCDNとキャッシュ

コンテンツ配信ネットワーク（CDN）は、訪問者の近くのサーバーから画像を配信します。特に世界中の閲覧者に対して、ダウンロード時間を短縮します。

最適化した画像は、CDNの恩恵を最も受けます。近くで配信される小さなファイルはほぼ一瞬で読み込まれますが、遠くで配信される大きなファイルは遅く進みます。

キャッシュヘッダーは、ブラウザに画像をローカルに保持するよう伝えます。再訪する訪問者は、画像を再ダウンロードせずにページを読み込めます。

めったに変わらない画像には、長いキャッシュ時間を設定します。ロゴや商品写真は、数か月キャッシュしても安全です。

最適化と配信は一緒に働きます。速いCDN上の小さな画像は、遅いサーバー上の大きな画像に毎回勝ります。

WebPとJPGのフォールバック

古いブラウザの中には、WebPを開けないものがあります。WebPだけを配信すれば、その訪問者には壊れた画像が表示されます。

picture要素がこれを解決します。WebPを最初に、JPGを次に挙げ、ブラウザが対応する最初の形式を選びます。

各画像の両方の版を作ります。最適化ツールがWebP版を作り、同じプリセットのJPG版がフォールバックとして機能します。

古いブラウザや端末でフォールバックをテストします。JPG版は、目に見える違いなくシームレスに表示されるべきです。

WebPの対応が広がるにつれ、フォールバックの重要性は下がります。今のところ、壊れた画像に対する安い保険です。

改善を測る

前後の数字で、効果を具体的に示せます。最適化前の画像の合計重量と読み込み時間をメモし、最適化後にもう一度測ります。

一般的なページは、数メガバイトから1MB以下に下がります。その変化は、速度スコアとページの体感にすぐに現れます。

最適化後、Core Web Vitalsを確認します。ヒーロー画像がたいてい最大の表示要素なので、LCPが最も改善するはずです。

同僚にスマホでページを開いてもらいましょう。実際の回線での実際の端末が、作業の正直なテストです。

節約の簡単な記録を残しましょう。なぜ画像を最適化しなければならないのかと聞かれたとき、数字がどんな議論よりよく答えます。

手順版はWebサイトの表示速度を上げる画像最適化の方法をご覧ください。Core Web Vitalsの詳しい解説は、画像最適化でCore Web Vitalsを改善する方法です。シンプルなサイズ目標には、200KB圧縮ツールがほとんどのWeb画像をカバーします。

よくある質問

ヒーロー画像にはどのプリセットを使うべきですか？

ヒーロープリセットを使いましょう。全幅バナー用にサイズを設定し、画質を高く保ちます。ヒーローは画面の上部にあり、Largest Contentful Paintに影響するので、遅延読み込みは決してしないでください。サイトが対応している場合はWebPを使うと、その画質で最小のファイルになります。

ツールがSNS共有画像でJPGに切り替えるのはなぜですか？

SNSプラットフォームやメールクライアントは、WebPよりJPGを確実に扱います。SNS用OGPとメールプリセットは、共有画像がどこでも正しく表示されるよう、形式を自動で切り替えます。WebPを開けない古いシステムでも表示できます。

ヒーロー画像に遅延読み込みを残すべきですか？

いいえ。遅延読み込みは、画像が表示領域に近づくまでダウンロードを遅らせるので、すぐに見えるヒーローには間違っています。Largest Contentful Paintスコアを悪化させます。遅延読み込みは、画面の下部にある画像にだけ使いましょう。

「縮小のみ」オプションは何をするのですか？

小さな画像が拡大されるのを防ぎます。オンにすると、ツールはプリセットの寸法より大きな画像だけを縮小し、小さいものはそのままにします。アイコンやサムネイルが引き伸ばされるのではなく、くっきり保たれます。

ダウンロードしたファイル名に「-web」がつくのはなぜですか？

「-web」の接尾辞は、そのファイルがWeb用に最適化された版であることを示し、元画像と混同しません。hero-1200-web.webpという名前なら、そのファイルがWebサイト用に準備できたことが一瞬でわかります。

一括画像圧縮ツールの代わりにWeb画像最適化ツールを使えますか？

Webサイト用のプリセット、HTMLタグ、場所ごとのサイズ設定が必要な場合は、Web最適化ツールを使います。Web特有の設定なしにファイルを小さくするだけなら、一括圧縮ツールを使います。正確なファイルサイズの制限には、指定サイズ圧縮ツールを使います。
