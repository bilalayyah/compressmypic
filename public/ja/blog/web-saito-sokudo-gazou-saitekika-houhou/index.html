Webサイトの表示速度を上げる画像最適化の方法

Webサイトの表示速度を上げる画像最適化の手順をステップごとに解説。プリセット、正しい寸法、遅延読み込み、コピー＆ペーストできるHTMLタグを紹介します。重い画像を軽くすれば、訪問者の離脱を減らして快適なサイトにできます。適切なサイズと形式を選ぶだけで、ページの表示速度が改善します。

画像は、ほとんどのWebサイトで最も重い部分です。ページの読み込みが遅い場合、たいてい画像が原因で、その修正が最も速い速度改善です。

この記事では、最適化の全工程を順を追って説明します。ページの監査、適切なプリセットの選択、画像の最適化、HTMLの貼り付けまでです。

ブログ、ショップ、ビジネスサイトに対応し、コピー＆ペースト以上のコーディング経験は不要です。

ステップ1：まずページを監査する

何かを最適化する前に、どの画像が問題かを見つけます。ページを開き、表示が遅く見える画像をメモします。

無料の速度ツールでページを測定します。最も重い画像が一覧表示され、それぞれが読み込み時間にどれだけかかっているかがわかります。

ページの画像の合計重量をメモします。5MBの画像があるページは明らかな問題があり、500KBのページはすでに良好です。

最も悪い3枚の画像を書き留めます。そこから修正すれば、最小の労力で最大の速度向上が得られます。

ステップ2：Web画像最適化ツールを開く

Web画像最適化ツールをブラウザで開きます。アカウントもインストールも不要です。

ツールはすべて端末内で動きます。画像はローカルで処理され、サーバーにアップロードされることはありません。

サイト全体を最適化する場合は、バッチで作業します。30枚ずつのバッチが、ほとんどのブラウザで快適なサイズです。

このページをブックマークしましょう。画像の最適化は繰り返しの作業で、よく戻ってくるツールです。

ステップ3：適切なプリセットを選ぶ

画像が表示される場所に合ったプリセットを選びます。ヒーロー画像、商品写真、サムネイルには、それぞれ独自のプリセットがあります。

EC商品プリセットが初期設定です。画像を幅1200ピクセル、WebP、画質82％に制限し、ほとんどの商品写真に合います。

ブログのアイキャッチ画像には、レイアウトに応じてヒーローかカードプリセットを使います。ファイルサイズではなく、表示サイズに合わせてプリセットを選びましょう。

SNS共有画像には、SNS用OGPプリセットを使います。SNSプラットフォームがJPGを好むため、形式を自動でJPGに切り替えます。

ステップ4：画像をアップロードする

画像をアップロードエリアにドラッグするか、タップして選択します。JPG、PNG、WebP、HEICに対応しています。

入手できる最高画質の元画像をアップロードします。1200万画素の元画像は、小さなコピーより最適化ツールにずっと多くの材料を与えます。

バッチの場合は、1ページ分の画像をすべて一度に追加します。プリセットを共有するので、結果が統一されます。

設定を変える前に、アップロードが終わるのを待ちましょう。最適化するには、ツールに完全なファイルが必要です。

ステップ5：設定をカスタマイズする

プリセットを選んだ後、場所が求める場合は設定を調整します。デザインに合わせて、寸法、形式、画質を変更します。

寸法は表示サイズに近く保ちましょう。800ピクセル幅で表示される画像に、ファイルで2400ピクセルは必要ありません。

大きな画像と小さな画像が混ざるバッチでは、「縮小のみ」をオンにします。アイコンやサムネイルが大きく引き伸ばされるのを防ぎます。

画質スライダーは、必要な場合にだけ動かします。ほとんどのプリセットは75〜85％の間にあり、ほぼすべての画像に適した範囲です。

ステップ6：結果をプレビューする

ダウンロード前に、最適化した各画像をフルサイズでプレビューします。小さなサムネイルでは、フルサイズで明らかな問題が隠れます。

まず細部を確認します。服の質感、文字、輪郭が、圧縮で最初にやわらかくなる部分です。

いくつかの結果を元画像と比較します。小さな違いは普通ですが、読めない文字やまだらな肌は普通ではありません。

ファイルサイズも確認します。概要には、各画像がどれだけ縮小したかと、バッチ全体の合計の節約が表示されます。

ステップ7：HTMLタグをコピーする

各画像の「画像タグをコピー」をクリックします。タグには、ソース、寸法、altテキスト、読み込み方法が含まれ、貼り付けられる状態です。

タグ内のaltテキストを確認します。生成されたテキストが画像をよく説明していない場合は、編集します。

読み込み属性が正しいか確認します。ヒーローはすぐに読み込むべきで、画面の下部の画像は遅延読み込みすべきです。

タグを、画像が属するページに貼り付けます。手作業で編集するのではなく、古い画像タグを完全に置き換えましょう。

ステップ8：アップロードしてページをテストする

最適化した画像をサイトにアップロードします。HTMLタグとファイルが一致するよう、ツールが作ったファイル名をそのまま使います。

新しいブラウザタブでページを開きます。すべての画像が表示され、何も引き伸ばされたりぼやけたりしていないか確認します。

速度ツールをもう一度実行し、数字を比較します。画像の合計重量は大幅に下がり、読み込み時間もそれに伴って下がっているはずです。

パソコンだけでなく、スマホでもテストします。ほとんどの訪問者はモバイルで閲覧するので、ページはまずそこで速く感じる必要があります。

よくある問題の修正

画像がぼやけて見える場合、元画像が小さすぎた可能性があります。同じプリセットで、より大きな元画像から再最適化します。

ページがまだ遅く読み込まれる場合、最適化されていない画像を確認します。忘れられた5MBのバナー1枚が、バッチ全体を台無しにすることがあります。

画像が引き伸ばされて見える場合、タグ内の寸法がファイルと一致していません。手作業で編集するのではなく、ツールからタグを再コピーします。

SNSの共有で画像が表示されない場合、形式を確認します。SNSプラットフォームはJPGを好み、SNS用OGPプリセットがそれを自動で処理します。

作業例：ブログ記事

記事の画像を集め、1回のバッチでアップロードします。サムネイルにはカードプリセット、アイキャッチ画像にはヒーロープリセットを使います。

アイキャッチ画像は注意深くプレビューします。ページで最も大きな画像で、読者が最初に判断するものです。

HTMLタグをコピーして記事に貼り付けます。公開前に、各タグのaltテキストを確認します。

記事を公開し、スマホでテストします。画像は速く読み込め、スクロールしながらシャープに見えるはずです。

作業例：商品ページ

商品写真を集め、1回のバッチでアップロードします。統一された結果のために、EC商品プリセットを使います。

最も細かい商品からプレビューします。服の質感と印刷されたラベルが、最初にやわらかくなる部分です。

HTMLタグをコピーして商品ページに貼り付けます。各画像の位置に応じて、読み込み属性が正しいか確認します。

アップロード後、スマホで商品ページを確認します。ほとんどの買い手はモバイルで閲覧するので、画像はそこでよく見える必要があります。

無料の速度ツールをうまく使う

無料の速度ツールはページを測定し、問題を一覧表示します。どんな最適化作業でも、最高の出発点です。

ローカルのコピーではなく、公開ページでツールを実行します。公開ページには、ホスティング、CDN、訪問者が直面する現実の条件が含まれます。

まず画像の推奨事項を読みます。最も時間を消費するファイルを正確に挙げ、どこから始めるべきか教えてくれます。

完璧なスコアは無視しましょう。グリーンの範囲のスコアで十分です。100点を追うのは、コンテンツに使うべき時間の無駄です。

修正を1回行うたびに、ツールを再実行します。変化する数字が、作業が効果を上げているかを示します。

ページの場所ごとのサイズ選び

ページ上のすべての場所には、自然な画像サイズがあります。ファイルを場所に合わせることが、Web最適化の核心的な技術です。

ヒーロー画像は最も大きなファイルが必要で、たいてい幅1200〜1600ピクセルです。画面いっぱいに表示されるので、シャープでなければなりません。

ブログ記事のアイキャッチ画像は、800〜1200ピクセルが適しています。大きくても全画面ではないので、中間のサイズが合います。

サムネイルとアバターは、200〜400ピクセルだけで十分です。それより大きいと、誰も見えない細部に帯域幅を浪費します。

選ぶ前に、テーマでの表示幅を測ります。表示される幅がファイルの幅を決め、間違った推測はキロバイトを浪費します。

レスポンシブ画像の実践

レスポンシブ画像は、画面ごとに異なるファイルを提供します。スマホは小さなファイルを、デスクトップは大きなファイルを受け取ります。

srcset属性が、利用可能なサイズを一覧表示し、ブラウザが実行中の画面に適したものを選びます。

画像ごとに2〜3サイズ作ります。モバイル用、タブレット用、デスクトップ用のサイズが、ほぼすべての訪問者をカバーします。

レスポンシブ画像を追加したら、実際のスマホでテストします。モバイルでの読み込み改善は、たいてい劇的です。

HTMLはシンプルに保ちましょう。3サイズのsrcsetで十分です。10サイズは、目に見える効果なしに複雑さを増します。

最適化しながらの画像SEO

最適化とSEOは一緒に進みます。速いページとよく説明された画像は、遅いページと無名のファイルより順位がよくなります。

わかりやすいファイル名を使いましょう。blue-cotton-shirt.jpgという名前は、検索エンジンに画像の内容を伝えます。

すべての画像に実際のaltテキストを書きましょう。内容を1文で説明し、検索者が探すであろう重要な詳細を含めます。

ファイル名やaltテキストにキーワードを詰め込まないこと。自然な説明は、読者にも検索エンジンにも役立ちます。

サイトが画像検索に依存する場合は、画像サイトマップを提出します。検索エンジンが、見逃すかもしれない画像を発見する助けになります。

最適化した画像の長期的な管理

最適化は一度きりの作業ではありません。新しい画像が毎週届き、それぞれが前回と同じ扱いを必要とします。

最適化を公開チェックリストに組み込みます。すべての記事は、公開前に最適化ツールを通過すべきです。

サイトは四半期ごとに監査します。最適化の習慣が始まる前の古い画像は、たいていまだ重いままで、バッチですぐに修正できます。

テーマの変更に注意します。新しいテーマは、古いテーマより大きく画像を表示することがあり、古いファイルは突然小さすぎるようになります。

元画像は安全に保管します。デザインが変わったとき、元画像があれば、画質を落とさずに新しいサイズに再最適化できます。

チームでの最適化の基準

一緒に公開するチームには、共通の基準が必要です。最初の記事の前に、プリセット、名前付けのパターン、サイズの予算について合意します。

基準を1ページに書き留めます。チームのWikiにある短いガイドが、100もの小さな質問を防ぎます。

公開ごとに、画像の重さを確認する人を1人割り当てます。2人目の目が、執筆者が見逃した重い画像を見つけます。

デザインが変わったら基準を見直します。去年のテーマに合ったプリセットが、今年のレイアウトに合わないことがあります。

よい基準が、速度を日常にします。チームは、手順が自動で処理するので、最適化について考えるのをやめます。

無視すべき速度の思い込み

1つの思い込みは、速度が重要なのはホームページだけだというものです。実際には、訪問者はブログ記事や商品ページに着地し、それらも速くなければなりません。

別の思い込みは、速いホスティングが遅い画像を修正するというものです。ホスティングは助けになりますが、5MBの画像はどのホストでも遅く、最適化だけが修正方法です。

3つ目の思い込みは、WebPだけで何もかも解決するというものです。形式は助けになりますが、寸法と遅延読み込みは形式の選択と同じくらい重要です。

真実は退屈で実用的です。正しいサイズ、正しい形式、画面の下部での遅延読み込み、すべてのタグでの寸法指定です。この4つを行えば、ページは速くなります。

自分のページをテストして、疑問を解決しましょう。速度の数字は思い込みを気にせず、実際に何が機能するかを教えてくれます。

公開前の最終確認

すべての画像を最適化した後、速度ツールを最後にもう一度実行します。画像の合計重量が下がり、読み込み時間が改善したことを確認します。

モバイル回線の実際のスマホでページを開きます。ラボテストの数字は役立ちますが、スマホでの体感が真実です。

すべての画像をもう一度目で確認します。ぼやけたヒーローのある速いページは成功ではなく、注意深いプレビューがそれを見つけます。

ページごとに学び続ける

最適化するすべてのページが何かを教えます。どのプリセットが機能し、どの画像が最も難しく、速度の数字がどう動いたかをメモしましょう。これらの教訓は、修正するページと改善するサイトが増えるごとに積み重なります。

そのメモが、あなたのプレイブックになります。次のページは、前回のページがすでに質問に答えたので、短時間で終わります。

最適化ツールの詳しいガイドは、Web画像最適化ツールの完全ガイドをご覧ください。Core Web Vitalsの詳しい解説は、画像最適化でCore Web Vitalsを改善する方法です。シンプルなサイズ目標には、200KB圧縮ツールがほとんどのWeb画像をカバーします。

よくある質問

画像を最適化した後、サイトはどれくらい速くなりますか？

画像がどれだけ重かったかによります。5MBの画像があるページが500KBに下がれば、特にモバイルで数秒速く読み込めることがあります。正確な改善を確認するには、最適化の前後で速度テストを実行しましょう。

画像はサイトにアップロードする前と後、どちらで最適化すべきですか？

前です。先に最適化すれば、寸法、形式、画質、そして完成したHTMLタグをコントロールできます。先にアップロードしてプラットフォームの圧縮に頼ると、たいてい結果が悪くなります。

ブログ画像30枚を1回のバッチで最適化できますか？

はい。30枚すべてを追加し、プリセットを選んでまとめてダウンロードします。バッチ全体をダウンロードする前に、いくつかの結果をプレビューし、プリセットを統一して、サイト上の画像が均一に見えるようにしましょう。

最適化したのにヒーロー画像がまだ遅いのはなぜですか？

ヒーローの遅延読み込みがオフになっているか確認しましょう。遅らせると読み込み速度が悪化します。ヒーローの寸法が表示サイズに合っているかも確認します。大きすぎるヒーローは帯域幅を浪費します。ヒーローをプリロードするとさらに改善できます。

画像を置き換えるときにHTMLも更新する必要がありますか？

はい。寸法やファイル名が変わった場合です。HTMLタグには幅、高さ、ソースが含まれているので、古いタグは画像を引き伸ばしたり、レイアウトを壊したりすることがあります。画像を置き換えるたびに、ツールから新しいタグをコピーしましょう。

ブログのアイキャッチ画像にはどのサイズを使うべきですか？

テーマの表示サイズに合わせましょう。通常は幅1200ピクセル以下です。ヒーローまたはカードプリセットがこれを自動で処理します。表示される幅の2倍の幅で画像を提供すると、目に見える効果なしに帯域幅を浪費します。
