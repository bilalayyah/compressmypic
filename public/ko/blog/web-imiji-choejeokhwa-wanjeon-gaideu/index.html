웹사이트는 이미지만큼 빠릅니다. 글자는 몇 밀리초 만에 열리지만 최적화되지 않은 사진 한 장이 페이지를 몇 초 동안 멈추게 할 수 있습니다.

웹 이미지 최적화 도구는 이 문제를 위해 만들어졌습니다. 웹사이트의 특정 자리에 맞게 이미지를 압축한 뒤 페이지에 바로 붙여넣을 수 있는 HTML을 건네줍니다.

이 가이드에서는 프리셋, 설정, 도구를 활용해 사이트 전체를 빠르게 만드는 방법을 설명합니다.

웹 이미지 최적화란?

웹 최적화는 페이지의 특정 작업에 맞게 이미지를 준비하는 것입니다. 대표 이미지, 상품 사진, 썸네일은 각각 다른 크기와 포맷이 필요합니다.

네 가지를 다룹니다. 파일 크기, 픽셀 크기, 포맷, HTML입니다. 네 가지를 모두 맞추면 이미지가 빠르게 열리고 선명하게 보입니다.

파일 크기는 다운로드 속도를 정합니다. 픽셀 크기는 이미지가 자리에 어떻게 맞는지를 정합니다. 포맷은 호환성과 화질을 정합니다.

HTML은 브라우저가 이미지를 어떻게 다루는지 정합니다. 지연 로딩, 너비, 높이, 대체 텍스트가 모두 태그 안에 있고, 모두 속도와 접근성에 영향을 줍니다.

최적화 도구는 네 가지를 함께 처리합니다. 파일 크기만 다루는 일반 압축기와 다른 점입니다.

웹 성능 프리셋 5가지

도구는 실제 웹사이트 자리에 맞춰진 프리셋 5가지를 제공합니다. 한 번의 클릭으로 픽셀 크기, 포맷, 품질을 설정합니다.

이커머스 상품이 기본값입니다. 이미지를 너비 1200픽셀, WebP, 품질 82%로 제한해 상품 사진에 완벽하게 맞습니다.

다른 프리셋은 대표 이미지, 카드, 썸네일, 소셜 공유를 다룹니다. 각 프리셋은 이름에 맞는 자리에 맞춰져 있습니다.

프리셋은 시작점이지 감옥이 아닙니다. 프리셋을 고른 뒤 어떤 설정이든 맞춤 조정해 페이지에 맞게 섞을 수 있습니다.

자리와 가장 가까운 프리셋으로 시작하세요. 결과가 디자인에 맞지 않을 때만 거기서 조정하세요.

대표 이미지 최적화하기

대표 이미지는 페이지 상단을 채우므로 첫인상과 최대 콘텐츠풀 페인트(LCP)에 가장 중요합니다.

대표 이미지는 넓은 화면에서 선명해 보일 만큼 커야 하지만 그 이상은 안 됩니다. 너무 큰 대표 이미지는 아무도 보지 않는 픽셀에 대역폭을 낭비합니다.

최신 사이트의 대표 이미지에는 WebP를 쓰세요. 같은 화질에서 JPG보다 큰 이미지를 더 가볍게 유지합니다.

대표 이미지는 절대 지연 로딩하지 마세요. 화면 상단에 있어 브라우저가 스크롤을 기다리지 않고 즉시 가져와야 합니다.

가능하면 대표 이미지를 미리 로딩하세요. 가장 중요한 이미지를 브라우저에 일찍 알리면 첫 화면이 그려지는 시간을 실제로 줄일 수 있습니다.

상품 이미지 최적화하기

상품 이미지는 상품을 팔므로 선명하게 유지되어야 합니다. 이커머스 프리셋은 1200픽셀로 제한해 대부분 쇼핑몰 레이아웃에 맞습니다.

배경은 깔끔하게, 상품은 중앙에 두세요. 정돈된 상품 사진은 압축도 잘 되고 전문적으로 보입니다.

카탈로그 전체에서 픽셀 크기를 일관되게 유지하세요. 크기가 섞인 격자는 압축이 아무리 좋아도 지저분해 보입니다.

최신 쇼핑몰의 상품 사진에는 WebP가 이상적입니다. JPG를 요구하는 마켓플레이스에서는 포맷을 바꾸고 픽셀 크기는 그대로 유지하세요.

업로드 뒤 휴대폰에서 상품 페이지를 확인하세요. 대부분 쇼핑객은 모바일로 둘러보고 이미지는 거기서 먼저 좋아 보여야 합니다.

카드와 썸네일

카드와 썸네일은 작게 표시되므로 데이터가 가장 적게 필요합니다. 300픽셀로 표시되는 카드에는 400픽셀 이미지가 충분합니다.

작은 이미지는 더 강한 압축을 감당합니다. 낮은 품질의 썸네일도 표시 크기가 부드러움을 숨기므로 깔끔해 보입니다.

화면 아래쪽 카드는 지연 로딩하세요. 페이지가 열릴 때 보이지 않으므로 브라우저가 나중에 가져와도 됩니다.

카드 전체에서 화면 비율을 일관되게 유지하세요. 비율이 섞인 격자는 지저분해 보이고 브라우저가 레이아웃을 다시 그리게 합니다.

썸네일은 최적화 효과가 가장 큰 곳입니다. 카드 20장이 있는 페이지는 썸네일마다 제대로 크기를 맞추면 메가바이트 단위로 절약됩니다.

이미지 태그 복사 버튼

이미지 태그 복사 버튼은 최적화된 이미지의 전체 HTML을 작성합니다. 출처, 픽셀 크기, 대체 텍스트, 로딩 동작을 포함합니다.

대체 텍스트는 파일 이름이나 내 설명에서 생성됩니다. 좋은 대체 텍스트는 접근성과 검색 엔진이 이미지를 이해하는 데 도움이 됩니다.

태그에는 너비와 높이 속성이 포함됩니다. 이는 레이아웃 이동을 막아주고, 레이아웃 이동은 순위에 영향을 주는 Core Web Vitals 지표입니다.

화면 아래쪽 이미지에는 지연 로딩이 포함됩니다. 이미지가 화면에 가까워질 때까지 기다렸다가 다운로드하라고 브라우저에 알립니다.

태그를 페이지에 바로 붙여넣으세요. 바로 쓸 수 있어 수동 편집이 필요 없습니다.

지연 로딩을 제대로 하는 방법

지연 로딩은 이미지가 필요할 때까지 다운로드를 미룹니다. 이미지가 많은 페이지에서 가장 쉬운 속도 향상 방법 중 하나입니다.

화면 아래쪽 이미지에 적용하세요. 페이지가 열릴 때 보이지 않으므로 일찍 다운로드하면 대역폭을 낭비합니다.

대표 이미지나 로고는 절대 지연 로딩하지 마세요. 즉시 보이고, 늦추면 첫인상과 LCP 점수를 해칩니다.

최적화 도구는 적합한 프리셋에 지연 로딩을 자동으로 추가합니다. 대표 프리셋은 이를 끄는데, 올바른 동작입니다.

지연 로딩을 추가한 뒤 페이지를 테스트하세요. 아래로 스크롤하면 이미지가 화면에 들어오면서 부드럽게 나타나는지 확인합니다.

웹용 포맷

WebP는 대부분 웹 이미지에 가장 좋은 포맷입니다. 같은 화질에서 JPG보다 작고 PNG처럼 투명 배경을 지원합니다.

JPG는 호환성에 여전히 필수입니다. 이메일, 소셜 공유, 오래된 시스템은 여전히 JPG를 선호하고, 소셜 OG 프리셋은 자동으로 JPG로 전환합니다.

PNG는 사진이 아니라 화면 그래픽에 맞습니다. 로고나 아이콘은 PNG에서 픽셀 단위로 완벽하게 유지되지만 사진은 PNG에서 대역폭을 낭비합니다.

SVG는 이 도구에서 다루지 않습니다. 벡터 포맷이고 최적화 도구는 JPG, PNG, WebP 같은 래스터 이미지를 다룹니다.

확신이 서지 않으면 사이트에는 WebP를, 공유용에는 JPG를 쓰세요. 최적화 도구는 둘 사이의 전환을 한 번 클릭으로 만듭니다.

품질 슬라이더: 20%에서 95%

품질 슬라이더는 0에서 100이 아니라 20에서 95%까지입니다. 이 범위는 의도적인 것으로, 나쁜 선택으로부터 지켜줍니다.

20% 아래에서는 이미지가 눈에 띄게 무너집니다. 어떤 웹사이트 자리도 그 정도로 낮은 품질에서 혜택을 받지 못하므로 도구가 제공하지 않습니다.

95% 위에서는 눈에 보이는 이득이 거의 없이 파일이 빠르게 커집니다. 추가 데이터는 눈이 볼 수 없는 디테일을 보존합니다.

대부분 프리셋은 75%에서 85% 사이에 있습니다. 이 범위는 거의 모든 이미지에서 작은 파일 크기로 깔끔한 결과를 제공합니다.

프리셋 결과가 이미지에 맞지 않을 때만 슬라이더를 조정하세요. 디테일한 사진은 85를 원할 수 있고 단순한 그래픽은 70으로 충분합니다.

EXIF 제거와 페이지 무게

카메라 사진은 숨은 메타데이터를 담고 있습니다. GPS 위치, 카메라 모델, 설정입니다. 이 데이터는 무게를 더하고 개인정보를 새어 나가게 합니다.

최적화 도구는 압축 과정에서 EXIF와 GPS 데이터를 제거합니다. 다운로드한 파일에는 어디서 언제 찍었는지 기록이 남지 않습니다.

제거하면 이미지당 몇 킬로바이트만 아끼지만 쌓이면 커집니다. 이미지 20장은 함께 의미 있는 양을 절약합니다.

개인정보가 더 큰 혜택입니다. 공개 사이트에 게시되는 사진에는 촬영한 장소가 담겨 있어서는 안 됩니다.

고객 작업에서는 제거가 필수입니다. 미공개 상품과 비공개 장소는 이미지 메타데이터로 새어 나가서는 안 됩니다.

사이트 전체를 일괄 최적화하기

많은 이미지를 한 번에 일괄 최적화할 수 있습니다. 블로그 이미지 30장을 넣고 프리셋을 고른 뒤 모두 함께 다운로드하세요.

일괄 모드는 사이트 이전에 이상적입니다. 블로그를 새 테마로 옮기면 모든 이미지를 다시 최적화해야 하고 일괄 처리는 몇 분이면 처리합니다.

일괄 전체를 다운로드하기 전에 몇 개 결과를 확인하세요. 좋은 결과 속에 부드러운 이미지 하나가 숨어 있을 수 있습니다.

일괄 처리 전체에서 프리셋을 일관되게 유지하세요. 설정이 섞이면 결과도 섞여 공개된 사이트에서 지저분해 보입니다.

프리셋 대신 정확한 파일 크기 목표가 필요하다면 목표 파일 크기 압축기에 원하는 숫자를 입력하세요.

소셜 공유와 오픈 그래프 이미지

누군가 내 페이지를 공유하면 플랫폼이 미리 보기 이미지를 보여줍니다. 그 이미지는 새로운 방문자가 가장 먼저 보는 것인 경우가 많습니다.

오픈 그래프 이미지에는 보통 1200 x 630 픽셀 같은 특정 픽셀 크기가 필요합니다. 소셜 OG 프리셋은 크기를 정확히 맞추고 JPG로 전환합니다.

파일은 수백 킬로바이트 아래로 유지하세요. 무거운 미리 보기 이미지는 공유 카드에서 느리게 열리고 일부 플랫폼은 이를 건너뜁니다.

게시하기 전에 공유 카드를 테스트하세요. 모든 주요 플랫폼은 미리 보기가 어떻게 보일지 정확히 보여주는 디버거를 제공합니다.

좋은 공유 이미지는 단순하고 대담합니다. 글자는 커야 하고, 피사체는 중앙에 있어야 하며, 배경은 깔끔해야 합니다.

레티나·고해상도 화면

레티나 화면은 같은 물리적 크기에 더 많은 픽셀을 담습니다. 일반 화면에서 선명해 보이던 이미지가 레티나 화면에서는 부드럽게 보일 수 있습니다.

해결책은 표시 크기보다 두 배 넓은 이미지를 제공하는 것입니다. 400픽셀 너비로 표시되는 썸네일은 파일에서 800픽셀이어야 합니다.

최적화 도구의 프리셋은 이를 감안합니다. 카드 프리셋은 대역폭을 낭비하지 않으면서 고해상도 화면에서도 선명하게 유지되는 이미지를 만듭니다.

작은 썸네일에서는 별 차이가 없습니다. 큰 대표 이미지에서는 표준과 레티나용의 차이가 눈에 보입니다.

가능하면 실제 고해상도 화면에서 테스트하세요. 결과의 스크린샷은 확인하려는 부드러움 자체를 숨깁니다.

대체 텍스트와 접근성

모든 웹 이미지에는 대체 텍스트가 필요합니다. 화면 읽기 프로그램과 검색 엔진에 이미지를 설명하고, 이미지가 열리지 않을 때 표시됩니다.

최적화 도구는 파일 이름이나 내 설명에서 대체 텍스트를 생성합니다. 생성된 글자가 이미지를 잘 설명하지 못하면 편집하세요.

대체 텍스트는 문장으로 쓰세요. 이미지가 무엇에 쓰이는지가 아니라 무엇을 보여주는지 설명하고 125자 정도로 유지하세요.

장식용 이미지는 설명이 아니라 빈 대체 텍스트가 필요합니다. 빈 대체 텍스트는 화면 읽기 프로그램에 이미지를 건너뛰라고 알립니다.

좋은 대체 텍스트는 SEO에도 도움이 됩니다. 검색 엔진은 이를 읽어 이미지를 이해하고, 이미지 검색에서 방문자를 가져올 수 있습니다.

이미지용 CDN과 캐싱

콘텐츠 전송 네트워크(CDN)는 방문자 가까운 서버에서 이미지를 제공합니다. 특히 전 세계 보는 사람에게 다운로드 시간을 줄여줍니다.

최적화된 이미지는 CDN에서 가장 큰 혜택을 봅니다. 가까운 곳에서 제공되는 작은 파일은 거의 즉시 열리지만 멀리서 제공되는 큰 파일은 느리게 열립니다.

캐시 헤더는 브라우저에 이미지를 로컬에 보관하라고 알립니다. 재방문자는 이미지를 다시 다운로드하지 않고 페이지를 엽니다.

거의 바뀌지 않는 이미지에는 긴 캐시 시간을 설정하세요. 로고나 상품 사진은 몇 달 동안 안전하게 캐시할 수 있습니다.

최적화와 전송은 함께 동작합니다. 빠른 CDN의 작은 이미지는 느린 서버의 큰 이미지를 매번 이깁니다.

JPG 대체와 함께 쓰는 WebP

일부 오래된 브라우저는 WebP를 열 수 없습니다. WebP만 제공하면 그 방문자는 깨진 이미지를 보게 됩니다.

picture 요소가 이를 해결합니다. WebP를 먼저, JPG를 다음으로 나열하고 브라우저가 지원하는 첫 번째 포맷을 고릅니다.

각 이미지의 두 버전을 만드세요. 최적화 도구가 WebP 복사본을 만들고, 같은 프리셋의 JPG 복사본이 대체용으로 쓰입니다.

오래된 브라우저나 기기에서 대체 버전을 테스트하세요. JPG 버전이 눈에 띄는 차이 없이 자연스럽게 나타나야 합니다.

WebP 지원이 늘면서 대체의 중요성은 줄어듭니다. 지금으로서는 깨진 이미지에 대한 저렴한 보험입니다.

개선 효과 측정하기

전후 숫자는 혜택을 구체적으로 만듭니다. 최적화 전후의 전체 이미지 무게와 로딩 시간을 적어두세요.

일반적인 페이지는 수 메가바이트에서 1MB 아래로 떨어집니다. 이 변화는 속도 점수와 페이지가 느껴지는 방식에 즉시 나타납니다.

최적화 뒤 Core Web Vitals를 확인하세요. 대표 이미지가 보통 가장 큰 화면 그리기이므로 LCP가 가장 많이 좋아져야 합니다.

동료에게 휴대폰으로 페이지를 열어달라고 하세요. 실제 인터넷 환경의 새 기기가 내 작업에 대한 정직한 테스트입니다.

절약 내역을 간단히 기록하세요. 누군가 이미지를 최적화해야 하는 이유를 물으면 숫자가 어떤 주장보다 잘 답해줍니다.

실전 단계는 웹사이트 속도용 이미지 최적화 방법에서 확인하세요. Core Web Vitals 깊이 있는 설명은 이미지 최적화와 Core Web Vitals: LCP와 파일 크기를 참고하세요. 간단한 크기 목표에는 200KB 압축기가 대부분 웹 이미지를 다룹니다.

자주 묻는 질문

대표 이미지에는 어떤 프리셋을 써야 하나요?

대표 프리셋을 쓰세요. 전체 너비 배너에 맞게 크기를 정하고 화질을 높게 유지합니다. 대표 이미지는 화면 상단에 있어 최대 콘텐츠풀 페인트에 영향을 주므로 절대 지연 로딩하지 마세요. 사이트가 지원하면 WebP를 써서 같은 화질에서 파일을 가장 작게 유지하세요.

도구가 소셜 공유 이미지에서 JPG로 전환하는 이유는 무엇인가요?

소셜 플랫폼과 이메일 클라이언트는 WebP보다 JPG를 더 안정적으로 처리합니다. 소셜 OG와 이메일 프리셋은 포맷을 자동으로 전환해 공유 이미지가 WebP를 열 수 없는 오래된 시스템을 포함해 어디서나 제대로 표시되게 합니다.

대표 이미지에 지연 로딩을 켜둬야 하나요?

아니요, 켜두지 마세요. 지연 로딩은 이미지가 화면에 가까워질 때까지 다운로드를 미루는데, 대표 이미지는 즉시 보이므로 잘못된 방식입니다. 최대 콘텐츠풀 페인트 점수를 해칩니다. 화면 아래쪽 이미지에만 지연 로딩을 쓰세요.

크기만 줄이기 옵션은 무엇을 하나요?

작은 이미지가 확대되는 것을 막습니다. 켜져 있으면 도구는 프리셋 크기보다 큰 이미지만 줄이고 작은 이미지는 그대로 둡니다. 아이콘과 썸네일이 늘어나는 대신 선명하게 유지됩니다.

다운로드한 파일 이름 끝에 -web이 붙는 이유는 무엇인가요?

-web 접미사는 웹 최적화 버전임을 표시해 원본과 혼동되지 않게 합니다. hero-1200-web.webp 같은 이름은 파일이 웹사이트용으로 준비됐다는 것을 즉시 알려줍니다.

대량 이미지 압축기 대신 웹 이미지 최적화 도구를 쓸 수 있나요?

웹사이트용 프리셋, HTML 태그, 자리별 크기 설정이 필요하면 웹 최적화 도구를 쓰세요. 웹 전용 설정 없이 파일만 작게 만들려면 대량 압축기를 쓰세요. 정확한 파일 크기 제한에는 목표 파일 크기 압축기를 쓰세요.
