Imagem para Base64 para usar no código

Desenvolvedores muitas vezes precisam de uma imagem como texto, e não como arquivo. Um ícone dentro de uma folha de estilo, um logotipo dentro de um e-mail HTML ou uma imagem dentro de uma carga JSON precisam que a imagem seja convertida em caracteres.

Base64 é a codificação que torna isso possível. Ela transforma os bytes binários de uma imagem em uma string de texto simples que pode viver dentro de código, marcação e mensagens.

Este guia explica como funciona o conversor de imagem para Base64 do CompressMyPic, para que serve cada formato de saída e quando embutir uma imagem é inteligente e quando é um erro.

O que é Base64?

Base64 é uma forma de representar dados binários como texto. Ela pega os bytes brutos de um arquivo e os reescreve usando 64 caracteres seguros: as letras de A a Z, de a a z, os dígitos de 0 a 9, mais e barra, com sinais de igual como preenchimento.

Os caracteres são seguros porque aparecem em todos os sistemas de texto. Um e-mail, um arquivo JSON, uma folha de estilo e um banco de dados conseguem guardar uma string Base64 sem corrompê-la, o que não é verdade para bytes brutos de imagem.

Base64 não é criptografia nem compressão. Quem recebe a string consegue decodificá-la de volta para a imagem original, e a string é sempre mais longa que o arquivo de onde veio.

Pense nisso como uma tradução, não uma transformação. A imagem continua sendo a mesma imagem; só o alfabeto usado para escrevê-la mudou.

Como funciona a codificação Base64

A codificação lê o arquivo de imagem de três em três bytes. Cada grupo de três bytes, 24 bits no total, é dividido em quatro grupos de seis bits, e cada grupo de seis bits vira um caractere Base64.

Quando o tamanho do arquivo não é múltiplo de três, o codificador adiciona sinais de igual como preenchimento. Um sinal de igual significa que o último grupo tinha dois bytes, e dois sinais de igual significam que tinha só um.

O resultado é uma string de texto que contém a imagem inteira. Decodificar reverte o processo com exatidão, transformando os caracteres de volta nos bytes originais, sem nenhuma perda.

O conversor faz tudo isso localmente no seu navegador. A imagem é lida, codificada e exibida sem sair do seu dispositivo, então diagramas privados e materiais de clientes ficam privados.

O custo extra de 33 por cento

A saída Base64 é cerca de 33 por cento maior que o arquivo original. Uma imagem de 90 KB vira uma string de aproximadamente 120 KB, porque quatro caracteres de texto carregam só três bytes de dados.

O custo extra é uma propriedade fixa da codificação, não uma falha da ferramenta. Todo codificador Base64 em qualquer linguagem produz o mesmo aumento de tamanho para a mesma entrada.

As saídas de HTML e CSS são um pouco maiores ainda, porque adicionam um invólucro ao redor da string. A tag de imagem adiciona marcação, e a função CSS adiciona sua própria sintaxe, além dos 33 por cento.

Esse custo extra é a primeira coisa a considerar antes de embutir. Um ícone pequeno cresce de 3 KB para 4 KB, o que ninguém percebe, mas uma foto de 2 MB cresce para 2,7 MB, o que todo mundo percebe.

Quatro formatos de saída em uma ferramenta

O conversor oferece quatro formatos de saída, cada um combinado com um trabalho diferente. Você escolhe a aba que combina com seu código, e a ferramenta gera o trecho exato de que você precisa.

A aba Data URL entrega a URI de dados completa, pronta para colar em uma fonte de imagem ou em uma folha de estilo. Ela inclui o tipo de mídia, o marcador de codificação e a string Base64 em uma peça só.

A aba Base64 bruto entrega só a string em si, sem prefixo. Essa é a forma que cargas de API e bancos de dados geralmente querem, porque o código receptor adiciona seu próprio contexto.

A aba de imagem HTML entrega um elemento de imagem completo com a Data URL como fonte, além de atributos de largura e altura preenchidos automaticamente. A aba CSS entrega uma função url() envolvendo a Data URL, pronta para um fundo ou uma máscara.

Data URLs explicadas

Uma Data URL começa com a palavra data, seguida do tipo de mídia, do marcador de codificação e da string Base64. Uma típica é data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA.

Os navegadores entendem Data URLs em qualquer lugar em que uma URL normal funcionaria. Você pode usá-la como fonte de imagem, fundo de folha de estilo ou destino de link, e o navegador vai decodificá-la e renderizá-la.

A vantagem é a autossuficiência. Uma página que usa Data URLs não tem arquivos de imagem separados para buscar, então funciona offline, em um único arquivo e em contextos em que requisições externas são bloqueadas.

A desvantagem é o tamanho. O custo extra de 33 por cento se aplica a cada imagem embutida, e uma página com muitas Data URLs fica pesada e lenta para analisar.

Base64 bruto explicado

Base64 bruto é a string sem o prefixo de dados. É o que você envia quando o receptor já conhece o tipo de imagem ou quando o tipo viaja em um campo separado.

Cargas de API são o principal caso de uso. Um objeto JSON pode carregar um campo chamado imagem com a string bruta, mais um campo chamado tipo MIME com o formato, e o servidor reconstrói o arquivo a partir dos dois.

Bancos de dados usam Base64 bruto da mesma forma. Guardar uma imagem como texto em uma coluna de texto evita tipos de coluna binária, que alguns sistemas lidam mal.

Quando você copiar Base64 bruto, mantenha o preenchimento. Os sinais de igual no final fazem parte da codificação, e removê-los pode quebrar decodificadores que esperam uma string completa.

O trecho de imagem HTML

A aba HTML gera um elemento de imagem completo com a Data URL como fonte. Ela também preenche os atributos de largura e altura automaticamente a partir das dimensões da imagem.

Esses atributos importam mais do que parecem. Sem eles, o navegador não conhece o tamanho da imagem até decodificar a string, e o layout da página muda quando a imagem finalmente aparece.

Com largura e altura presentes, o navegador reserva a quantidade certa de espaço na hora. O layout fica estável, o que é melhor para os leitores e para as pontuações de mudança de layout.

O trecho está pronto para colar em qualquer arquivo HTML. Adicione um atributo alt descrevendo a imagem antes de publicá-lo, já que a ferramenta não sabe o que a imagem mostra.

O trecho CSS url()

A aba CSS envolve a Data URL em uma função url(), produzindo um valor que você pode colar em uma propriedade background-image ou similar. É a forma mais rápida de colocar uma imagem pequena em uma folha de estilo.

Imagens CSS embutidas são comuns para ícones, padrões e fundos decorativos. Elas carregam junto com a folha de estilo, então não há requisição separada nem flash de decoração ausente.

O custo é o peso da folha de estilo. Uma folha cheia de imagens embutidas cresce, e os navegadores não conseguem armazenar as imagens em cache separadamente do CSS que as contém.

Use a forma CSS para imagens pequenas e estáveis que raramente mudam. Um logotipo ou um padrão repetido serve; uma galeria de fotos não, porque a folha de estilo ficaria enorme.

Qualidade: a codificação não muda nada

Codificar uma imagem para Base64 não muda um único pixel. O processo é totalmente reversível, e decodificar a string devolve os bytes originais exatos.

GIFs animados mantêm a animação, arquivos SVG mantêm o código e fotografias mantêm cada detalhe. A codificação é uma representação diferente, não uma imagem diferente.

Essa é uma diferença importante em relação à conversão de formatos. Mudar um PNG para JPG perde dados, mas codificar um PNG para Base64 não perde nada.

A única coisa que muda é o tamanho. A string é cerca de um terço maior que o arquivo, e esse custo é o preço de carregar dados binários como texto.

Quais formatos e tamanhos são aceitos

O conversor aceita arquivos PNG, JPG, WebP, GIF, SVG, BMP e ICO, até 15 MB cada. Isso cobre logotipos, ícones, fotos e imagens animadas em uma única ferramenta.

Arquivos SVG codificam bem porque já são texto. A ferramenta lê o código SVG e o codifica como qualquer outro arquivo, produzindo uma string que decodifica de volta para o mesmo gráfico vetorial.

Arquivos ICO de favicon também funcionam, o que é útil quando um site precisa do ícone embutido em uma página de arquivo único ou em um modelo de e-mail. O ICO codificado decodifica de volta para um arquivo de ícone válido.

Para arquivos perto do limite de 15 MB, considere encolher primeiro. Um PNG grande comprimido para um JPG menor antes de codificar produz uma string bem mais curta, e a perda de qualidade costuma ser invisível.

Quando embutir uma imagem Base64

Embuta imagens pequenas que são essenciais para a página. Ícones, logotipos e pequenos gráficos decorativos com poucos kilobytes são ideais, porque o custo extra é desprezível e a requisição economizada é real.

Embuta imagens em documentos de arquivo único. Um e-mail HTML, um relatório independente ou uma página offline não consegue buscar arquivos externos, então embutir é a única forma de as imagens aparecerem.

Embuta imagens em cargas de API e arquivos de configuração. Quando a imagem precisa viajar dentro de JSON ou dentro de um registro de banco de dados, Base64 é a forma padrão de carregá-la.

Embuta quando a imagem muda raramente. Um logotipo que fica igual por anos não custa nada para embutir, enquanto uma imagem que atualiza toda semana força uma mudança de código a cada vez.

Quando não embutir

Não embuta fotos grandes. Uma fotografia de 2 MB vira uma string de 2,7 MB dentro do seu HTML, e o navegador precisa baixar e analisar tudo antes que a página possa renderizar.

Não embuta imagens que aparecem em muitas páginas. Um logotipo embutido em cada página é baixado a cada vez, enquanto um logotipo vinculado é armazenado em cache uma vez e reutilizado em todo o site.

Não embuta imagens em e-mails sem verificar o cliente. Alguns clientes de e-mail bloqueiam imagens Base64 embutidas, e sua mensagem pode chegar com imagens quebradas para esses leitores.

Não embuta imagens que precisam ser indexadas ou compartilhadas. Um mecanismo de busca não consegue descobrir facilmente uma imagem embutida, e um leitor não consegue clicar com o botão direito e salvá-la como consegue com um arquivo normal.

Base64 em e-mails e APIs

E-mails HTML são um dos usos mais antigos de imagens Base64. Um e-mail é uma única mensagem, então uma imagem embutida viaja com ele e é exibida mesmo quando o leitor está offline.

Nem todos os clientes de e-mail concordam, porém. Alguns bloqueiam imagens Base64 embutidas por motivos de segurança, então teste seu modelo nos clientes que seu público realmente usa antes de depender de imagens embutidas.

As APIs usam Base64 por um motivo diferente: JSON não consegue carregar dados binários. Um endpoint de envio de imagem que aceita JSON espera a imagem como uma string Base64, muitas vezes com o tipo de mídia em um campo separado.

Quando você monta essa carga, use a aba de Base64 bruto. Ela entrega a string sem o prefixo de dados, que é a forma que a maioria das APIs espera.

Privacidade: a codificação acontece no seu navegador

Codificar uma imagem online significaria enviá-la para um servidor, o que é uma má ideia para ícones proprietários, diagramas confidenciais ou materiais de clientes. Esta ferramenta nunca faz isso.

O arquivo é lido pelo seu navegador, codificado no seu dispositivo, e a string é mostrada para você localmente. Nenhuma cópia da imagem ou da string sai do seu computador.

Isso também significa que a ferramenta funciona offline depois que a página carrega. Você pode codificar ícones em um avião ou em um escritório seguro sem nenhum acesso à rede.

Para equipes que lidam com material visual sensível, a codificação local é o recurso decisivo. A string que você copia é sua, e nenhum servidor jamais vê a imagem nem sua forma codificada.

Como usar a ferramenta de imagem para Base64

Abra o conversor de imagem para Base64 e solte sua imagem na área de envio, ou cole uma captura de tela direto da área de transferência. Arquivos de até 15 MB são aceitos.

Escolha a aba de saída que combina com seu trabalho: Data URL para uma URI completa, Bruto para cargas de API, HTML para um elemento de imagem pronto ou CSS para um fundo de folha de estilo.

Copie a saída com o botão de copiar ou baixe-a como arquivo quando a string for longa e copiar parecer arriscado. O download salva o texto exato, sem truncamento.

Perguntas frequentes

Codificar em Base64 é o mesmo que comprimir uma imagem?

Não, é o oposto em termos de tamanho. A compressão deixa um arquivo menor, enquanto Base64 o deixa cerca de 33 por cento maior. A codificação muda a representação de binário para texto sem mudar nenhum pixel. Se você precisa de um arquivo menor, comprima a imagem primeiro e depois codifique o resultado comprimido.

Posso embutir uma imagem Base64 em um documento Word ou PDF?

Não diretamente como uma string Base64. Arquivos Word e PDF guardam imagens como dados binários dentro do documento, não como texto Base64. Base64 é para código web, e-mails, cargas JSON e outros formatos baseados em texto. Converta a imagem para um arquivo normal primeiro para uso em documentos.

Por que minha string Base64 é tão longa?

Porque ela carrega a imagem inteira como texto, e texto é um meio menos eficiente que binário. Uma imagem de 90 KB vira cerca de 120 KB de caracteres, e uma foto de 1 MB vira cerca de 1,4 MB de texto. O tamanho é normal. Para strings muito longas, use o botão de download em vez de copiar.

A codificação Base64 funciona para GIFs animados?

Sim. A codificação não toca nos dados de pixels, então um GIF animado codifica em uma string que decodifica de volta para o mesmo arquivo animado. A animação, a contagem de quadros e o tempo são todos preservados com exatidão.

Qual é a maior imagem que posso converter para Base64 aqui?

Arquivos de até 15 MB são aceitos. Arquivos maiores produzem strings extremamente longas, difíceis de copiar e lentas para analisar em um navegador. Encolha ou comprima imagens grandes antes de codificar e considere vincular em vez de embutir para qualquer coisa acima de algumas centenas de kilobytes.

Os mecanismos de busca conseguem ver imagens embutidas como Base64?

Na maior parte, não. Um mecanismo de busca pode tecnicamente decodificar uma Data URL, mas imagens embutidas não são indexadas, classificadas nem mostradas na busca de imagens como arquivos de imagem vinculados são. Se o tráfego de busca de imagens importa, vincule a imagem como arquivo em vez de embuti-la.
