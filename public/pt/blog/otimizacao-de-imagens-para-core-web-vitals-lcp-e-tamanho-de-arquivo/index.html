Otimização de imagens para Core Web Vitals: LCP e tamanho de arquivo

Como a otimização de imagens melhora o Core Web Vitals: LCP, CLS e INP explicados, com correções práticas para páginas lentas.

O Core Web Vitals são as pontuações de velocidade que o Google usa para julgar suas páginas. Elas medem a rapidez com que o maior conteúdo aparece, a estabilidade do layout e a velocidade de resposta da página.

As imagens afetam as três pontuações. Uma imagem principal pesada atrasa a maior pintura, uma largura faltando causa mudança de layout e uma página inchada deixa a interação lenta.

Este artigo explica como a otimização de imagens move cada pontuação e o que corrigir primeiro numa página lenta.

O que é o Core Web Vitals?

O Core Web Vitals são três métricas que descrevem a experiência do usuário ao carregar uma página. Elas são medidas em visitantes reais, não num laboratório.

Largest Contentful Paint, ou LCP, mede quanto tempo o maior elemento visível leva para aparecer. Na maioria das páginas, esse elemento é uma imagem.

Cumulative Layout Shift, ou CLS, mede o quanto a página se move enquanto carrega. As imagens sem dimensões são a causa mais comum.

Interaction to Next Paint, ou INP, mede a rapidez com que a página responde a cliques e toques. As páginas pesadas, com muitas imagens grandes, respondem mais devagar.

O Google usa essas pontuações no ranqueamento das buscas. As páginas mais rápidas ranqueiam melhor, e a otimização de imagens é a maior alavanca que a maioria dos sites tem.

LCP: por que a imagem principal decide tudo

O LCP geralmente é decidido pela imagem principal. Ela é o maior elemento na tela, então a página não é considerada carregada até ela aparecer.

Uma imagem principal de 5 MB pode levar segundos para baixar numa conexão móvel. Durante esses segundos, o visitante vê um espaço em branco onde a imagem principal deveria estar.

Comprimir a imagem principal para algumas centenas de kilobytes corta essa espera drasticamente. A imagem aparece mais cedo, e a pontuação de LCP melhora na hora.

As dimensões também importam. Uma imagem principal servida com o dobro do tamanho de exibição desperdiça banda com pixels que ninguém vê, atrasando ainda mais a pintura.

Pré-carregar a imagem principal também ajuda. Avisar o navegador cedo sobre a imagem mais importante permite que ele comece o download antes de qualquer outra coisa.

Corrigindo um LCP lento passo a passo

Primeiro, encontre o elemento LCP. As ferramentas de velocidade o nomeiam diretamente, e geralmente é a imagem principal ou um banner grande.

Segundo, otimize essa imagem com o Otimizador de imagens para web. Use a predefinição de imagem principal, que a dimensiona corretamente e mantém a qualidade alta.

Terceiro, confira se o carregamento preguiçoso está desligado para a imagem principal. Atrasar a imagem mais importante é o erro de LCP mais comum.

Quarto, pré-carregue a imagem principal no cabeçalho da página. O navegador então a busca primeiro, antes que folhas de estilo e scripts disputem a banda.

Quinto, teste a página de novo. O tempo de LCP deve ter caído bastante, muitas vezes vários segundos no celular.

CLS: como as imagens movem o layout

O CLS mede movimentos inesperados. Quando uma imagem carrega tarde sem espaço reservado, o texto abaixo dela pula para baixo, e o visitante perde o lugar.

O conserto é simples: inclua sempre largura e altura na tag da imagem. O navegador então reserva o espaço antes de a imagem chegar.

O botão Copiar tag de imagem do otimizador inclui essas dimensões automaticamente. Colar a tag como ela é evita a mudança por completo.

A proporção também importa. Uma imagem com a proporção errada distorce quando preenche o espaço reservado, o que parece quebrado mesmo sem mudança.

Confira a página carregando do zero e observando qualquer movimento. Qualquer pulo que você vir é um problema de CLS esperando para prejudicar sua pontuação.

INP: como o peso das imagens deixa a interação lenta

O INP mede a responsividade. Quando um visitante toca num botão, a página deve reagir rápido, e as páginas pesadas reagem devagar.

As imagens afetam o INP indiretamente. Uma página com megabytes de imagens mantém o navegador ocupado baixando e decodificando, o que atrasa a resposta aos toques.

O carregamento preguiçoso ajuda aqui. As imagens abaixo da dobra não precisam baixar antes de a página ficar interativa, então adiá-las libera o navegador.

Decodificar imagens grandes também custa tempo. Uma imagem gigante leva mais tempo para decodificar que uma de tamanho certo, mesmo depois de baixar.

O conserto é o mesmo que para o LCP: dimensione cada imagem corretamente, use carregamento preguiçoso nas que estão abaixo da dobra e mantenha o peso total da página baixo.

Medindo o Core Web Vitals direito

Meça em aparelhos reais, não só numa conexão rápida de escritório. A maioria dos visitantes navega no celular, e as pontuações de celular são as que contam.

Use as ferramentas gratuitas de velocidade para ter uma base. Anote os números de LCP, CLS e INP antes de mudar qualquer coisa.

Mude uma coisa de cada vez. Otimizar a imagem principal e testar de novo mostra exatamente quanto a imagem principal estava custando.

Teste de novo depois de cada rodada de correções. As pontuações se movem em passos, e cada passo mostra se a última mudança ajudou.

Lembre-se de que as pontuações variam por visitante. Um único teste é um retrato; vários testes ao longo de dias dão a imagem real.

Definindo um orçamento de imagens para uma página

Um orçamento de imagens limita o peso total das imagens numa página. Um orçamento comum é 1 MB para uma página de conteúdo e 2 MB para uma galeria.

Divida o orçamento pelo número de imagens. Dez imagens dividindo um orçamento de 1 MB ficam com 100 KB cada, que é um alvo sensato.

Dê à imagem principal uma parte maior. Ela merece 300 KB ou 400 KB, enquanto as imagens de apoio ficam com 100 KB cada.

Imponha o orçamento no seu fluxo de publicação. Uma lista que inclua o peso das imagens impede que imagens pesadas cheguem ao site ao vivo.

Revise o orçamento quando o design mudar. Um tema novo com imagens maiores precisa de um orçamento maior, ou de imagens menores para combinar.

Formatos e Core Web Vitals

O WebP é o melhor formato para o Core Web Vitals. Ele é menor que o JPG com a mesma qualidade, o que ajuda o LCP diretamente.

Os navegadores modernos todos aceitam WebP. O formato não é mais um risco para sites comuns, e o ganho de velocidade é real.

O JPG continua como retorno para sistemas mais antigos. Quando a compatibilidade importa mais que a velocidade, o JPG é a escolha segura.

O PNG prejudica o Core Web Vitals para fotos. Seus arquivos grandes atrasam o LCP e incham a página, então reserve o PNG só para gráficos.

Sirva o menor formato que o navegador do visitante aceitar. Essa única regra captura a maior parte do benefício de formato disponível.

Imagens responsivas e troca de resolução

As imagens responsivas servem tamanhos diferentes para telas diferentes. Um celular recebe um arquivo pequeno, enquanto um computador recebe um maior.

O atributo HTML srcset lista os tamanhos disponíveis, e o navegador escolhe o certo para a tela em que está rodando.

Isso importa para o LCP no celular. Um celular baixando uma imagem principal de tamanho de computador desperdiça segundos com pixels que sua tela pequena não consegue mostrar.

Gere dois ou três tamanhos por imagem: um tamanho para celular, um para tablet e um para computador. As predefinições do otimizador fazem cada um num clique.

Teste num celular de verdade depois de adicionar imagens responsivas. A melhora de LCP no celular costuma ser dramática.

Erros comuns de Core Web Vitals

Usar carregamento preguiçoso na imagem principal é o erro mais comum. Ele atrasa o elemento LCP e garante uma pontuação ruim.

Faltar largura e altura é o segundo. As imagens sem dimensões movem o layout e prejudicam a pontuação de CLS.

Servir imagens gigantes é o terceiro. Uma imagem de 4000 pixels exibida com 800 pixels desperdiça banda e atrasa a pintura.

Esquecer as imagens abaixo da dobra é o quarto. Uma página pode ter uma imagem principal rápida e continuar lenta no geral se vinte miniaturas sem otimização vierem depois.

Corrigir esses quatro erros resolve a maioria dos problemas de Core Web Vitals relacionados a imagens. Eles são simples e funcionam.

O que corrigir primeiro: uma ordem de prioridade

Corrija primeiro a imagem LCP. Ela tem o maior efeito isolado na pontuação e na primeira impressão do visitante.

Corrija as dimensões faltando em segundo. Adicionar largura e altura a cada tag de imagem é rápido e elimina a mudança de layout.

Corrija o peso total em terceiro. Use carregamento preguiçoso nas imagens abaixo da dobra e comprima o resto, trazendo a página para dentro do orçamento.

Corrija a responsividade em quarto. As imagens responsivas ajudam mais os visitantes de celular, e as pontuações de celular importam mais.

Teste de novo depois de cada passo. As pontuações vão dizer quando a página está boa o bastante e quando mais trabalho é necessário.

Dados de campo vs dados de laboratório

O Core Web Vitals vem em dois tipos: dados de laboratório de um único teste e dados de campo de visitantes reais ao longo de semanas.

Os dados de laboratório são instantâneos e repetíveis. Eles dizem como a página se sai numa conexão rápida num teste controlado.

Os dados de campo são mais lentos, mas honestos. Eles refletem visitantes reais em celulares reais com conexões reais, incluindo as lentas.

O Google ranqueia com dados de campo. Uma página que pontua bem no laboratório, mas mal no campo, ainda vai ranquear mal.

Use dados de laboratório para encontrar problemas e dados de campo para confirmar correções. Os dois juntos dão a imagem completa da velocidade da sua página.

Quando o elemento LCP não é uma imagem

Às vezes a maior pintura é um bloco de texto, não uma imagem. Nesse caso, a otimização de imagens ajuda menos, e fontes e folhas de estilo importam mais.

Confira o que a ferramenta de velocidade nomeia como elemento LCP. Se for texto, olhe o carregamento de fontes e os estilos que bloqueiam a renderização.

As imagens ainda podem atrasar um LCP de texto. Uma imagem de fundo pesada ou um logotipo de carregamento lento podem segurar a página inteira.

Otimize as imagens de qualquer jeito. Uma página mais leve ajuda cada métrica, mesmo quando o elemento LCP em si é texto.

Não otimize no escuro. Saber qual elemento move a pontuação diz onde gastar seu esforço.

CLS além das imagens: fontes e anúncios

As imagens são a causa mais comum de CLS, mas não a única. As fontes de web e os anúncios também movem o layout conforme carregam.

As fontes movem o texto quando trocam. Usar font-display swap com um retorno próximo reduz o pulo visível.

Os anúncios movem o conteúdo quando carregam tarde. Reservar espaço para os espaços de anúncio evita que a página pule quando o anúncio chega.

Corrija primeiro as imagens, pois são a vitória mais fácil. Depois olhe fontes e anúncios se a pontuação de CLS continuar ruim.

Uma página sem nenhuma mudança de layout parece calma e profissional. Os visitantes percebem a estabilidade mesmo sem saber nomeá-la.

INP e scripts pesados

As imagens raramente são o principal problema de INP. O JavaScript pesado costuma ser a maior causa de interação lenta.

Ainda assim, o trabalho com imagens ajuda o INP. Uma página mais leve deixa o navegador com mais tempo para responder a toques e cliques.

Os custos de decodificação também importam. Uma imagem gigante leva mais tempo para decodificar que uma de tamanho certo, e a decodificação bloqueia a interação.

Mantenha os scripts de terceiros enxutos. Análises, widgets de chat e incorporações sociais disputam a atenção do navegador com sua página.

Pense no INP como um orçamento. Cada script e imagem gasta dele, e a página precisa responder antes de o orçamento acabar.

Celular primeiro: por que as pontuações de celular importam mais

A maioria dos visitantes navega no celular, e o Google ranqueia com pontuações de celular. Uma página rápida no computador, mas lenta no celular, vai ranquear mal.

Os celulares têm conexões mais lentas e processadores mais fracos. A mesma imagem principal leva mais tempo para baixar e decodificar num celular que num computador.

Otimize primeiro para o celular. Uma página rápida no celular é rápida em todo lugar, enquanto o contrário não é verdade.

Teste num celular de verdade, não só num simulador de computador. O simulador esconde a lentidão real que os visitantes de fato sentem.

A otimização com o celular primeiro não é uma tendência. É como a web funciona agora, e as pontuações refletem isso.

Monitoramento contínuo do Core Web Vitals

O Core Web Vitals muda com o tempo. Imagens novas, plugins novos e temas novos podem prejudicar as pontuações em silêncio.

Confira as pontuações pelo menos uma vez por mês. Uma conferência regular pega os problemas antes de afetarem o ranqueamento.

Configure alertas se sua plataforma aceitar. Um alerta quando o LCP cruzar o limite economiza semanas de ranqueamento lento.

Revise as pontuações depois de cada reformulação. Um tema novo muda cada espaço de imagem, e as otimizações antigas podem não servir mais.

A velocidade é um hábito, não um projeto. Os sites que continuam rápidos são os que continuam observando.

Uma conferência final antes de publicar

Rode a ferramenta de velocidade uma última vez depois de todas as correções. Confirme se LCP, CLS e INP estão todos na faixa verde antes de seguir em frente.

Carregue a página num celular de verdade com conexão móvel. Os números de um teste de laboratório são úteis, mas a sensação no celular é a verdade.

Perguntas frequentes

O que é uma boa pontuação de LCP?

O Google considera um LCP abaixo de 2,5 segundos bom. A maioria das páginas erra esse alvo por causa de uma imagem principal pesada. Comprimir a imagem principal, servi-la no tamanho certo e pré-carregá-la são os jeitos mais rápidos de ficar abaixo do limite.

Como as imagens causam mudança de layout?

Quando uma imagem carrega sem os atributos de largura e altura, o navegador não sabe quanto espaço reservar. A imagem chega tarde e empurra o conteúdo abaixo dela para baixo, o que conta como mudança de layout. Incluir as dimensões na tag evita isso.

O carregamento preguiçoso melhora o Core Web Vitals?

Sim, para imagens abaixo da dobra. Adiá-las libera banda para a imagem principal e deixa a página interativa mais cedo. Nunca use carregamento preguiçoso na imagem principal ou no logotipo, pois atrasá-los prejudica o LCP diretamente.

Por que minha pontuação de LCP no celular é pior que no computador?

As conexões de celular são mais lentas e os processadores de celular são mais fracos, então a mesma imagem principal leva mais tempo para baixar e decodificar. Otimizar a imagem principal, servir uma versão menor para celular e pré-carregá-la vão fechar a maior parte da diferença.

Só a otimização de imagens consegue corrigir uma pontuação ruim de Core Web Vitals?

Muitas vezes sim, quando as imagens são o principal problema. Uma página com 5 MB de imagens vai melhorar drasticamente depois de otimizadas. Se a pontuação continuar ruim, o problema pode ser hospedagem lenta, scripts pesados ou folhas de estilo que bloqueiam a renderização.

Com que frequência devo conferir o Core Web Vitals de novo?

Depois de cada mudança de design e pelo menos uma vez por mês. Imagens novas, temas novos e plugins novos podem prejudicar as pontuações em silêncio. Uma conferência mensal pega os problemas antes de afetarem o ranqueamento.
