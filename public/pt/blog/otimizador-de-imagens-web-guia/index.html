Otimizador de imagens para web: guia completo

Um site é tão rápido quanto suas imagens. O texto carrega em milissegundos, mas uma única foto sem otimização pode travar uma página por segundos.

O Otimizador de imagens para web foi feito para esse problema. Ele comprime imagens para espaços específicos do site e depois entrega o HTML para colar direto na sua página.

Este guia explica as predefinições, as configurações e como usar a ferramenta para deixar um site inteiro mais rápido.

O que é otimização de imagens para web?

A otimização para web significa preparar uma imagem para um trabalho específico na página. Uma imagem principal, uma foto de produto e uma miniatura precisam de tamanhos e formatos diferentes.

Ela cobre quatro coisas: tamanho do arquivo, dimensões, formato e HTML. Acertar os quatro faz a imagem carregar rápido e ficar nítida.

O tamanho do arquivo decide a velocidade do download. As dimensões decidem como a imagem cabe no espaço dela. O formato decide a compatibilidade e a qualidade.

O HTML decide como o navegador trata a imagem. O carregamento preguiçoso, a largura, a altura e o texto alternativo vivem na tag, e todos afetam a velocidade e a acessibilidade.

O otimizador cuida dos quatro juntos. É isso que o diferencia de um compressor simples, que só cuida do tamanho do arquivo.

As cinco predefinições de desempenho para web

A ferramenta oferece cinco predefinições, cada uma mapeada para um espaço real do site. Elas definem as dimensões, o formato e a qualidade num clique só.

Produto de e-commerce é a padrão. Ela limita as imagens a 1200 pixels de largura em WebP com 82% de qualidade, o que serve perfeitamente para fotos de produto.

As outras predefinições cobrem imagens principais, cartões, miniaturas e compartilhamento social. Cada uma corresponde ao espaço cujo nome carrega.

As predefinições são pontos de partida, não prisões. Você pode personalizar qualquer configuração depois de escolher uma predefinição, misturando conforme a sua página.

Comece com a predefinição mais próxima do seu espaço. Ajuste a partir daí só se o resultado não servir ao design.

Otimizando imagens principais

As imagens principais preenchem o topo da página, então importam mais para a primeira impressão e para o Largest Contentful Paint.

Uma imagem principal deve ser grande o bastante para ficar nítida em telas largas, mas não maior. Uma imagem principal gigante desperdiça banda com pixels que ninguém vê.

Use WebP para imagens principais em sites modernos. Ele mantém a imagem grande mais leve que o JPG com a mesma qualidade.

Nunca use carregamento preguiçoso numa imagem principal. Ela está acima da dobra, então o navegador deve buscá-la na hora, não esperar uma rolagem.

Pré-carregue a imagem principal quando puder. Avisar o navegador cedo sobre a imagem mais importante economiza tempo real na primeira pintura.

Otimizando imagens de produto

As imagens de produto vendem o produto, então precisam continuar nítidas. A predefinição de e-commerce as limita a 1200 pixels, o que serve à maioria dos layouts de loja.

Mantenha o fundo limpo e o produto centralizado. Uma foto de produto arrumada comprime melhor e parece mais profissional.

Use dimensões consistentes em todo o catálogo. Uma grade de tamanhos mistos parece desleixada, por melhor que a compressão seja.

O WebP é ideal para fotos de produto em lojas modernas. Para marketplaces que exigem JPG, troque o formato e mantenha as mesmas dimensões.

Confira a página do produto no celular depois de enviar. A maioria dos compradores navega no celular, e a imagem precisa ficar boa lá primeiro.

Cartões e miniaturas

Os cartões e as miniaturas são mostrados pequenos, então precisam de menos dados. Uma imagem de 400 pixels basta para um cartão exibido com 300 pixels.

As imagens pequenas toleram compressão mais pesada. Uma miniatura com qualidade menor continua limpa, porque o tamanho de exibição esconde a suavidade.

Use carregamento preguiçoso nos cartões abaixo da dobra. Eles não são visíveis quando a página abre, então o navegador pode buscá-los depois.

Mantenha a proporção consistente entre os cartões. Uma grade de proporções misturadas parece bagunçada e força o navegador a recalcular o layout.

As miniaturas são onde a otimização mais compensa. Uma página com vinte cartões economiza megabytes quando cada miniatura tem o tamanho certo.

O botão Copiar tag de imagem

O botão Copiar tag de imagem escreve o HTML completo da sua imagem otimizada. Ele inclui a fonte, as dimensões, o texto alternativo e o comportamento de carregamento.

O texto alternativo é gerado a partir do nome do arquivo ou da sua descrição. Um bom texto alternativo ajuda a acessibilidade e os mecanismos de busca a entender a imagem.

A tag inclui os atributos de largura e altura. Eles evitam mudanças de layout, que são uma métrica do Core Web Vitals que afeta o ranqueamento.

O carregamento preguiçoso é incluído para imagens abaixo da dobra. Ele diz ao navegador para esperar até a imagem se aproximar da tela antes de baixá-la.

Cole a tag direto na sua página. Ela está pronta para usar, sem nenhuma edição manual.

Carregamento preguiçoso feito direito

O carregamento preguiçoso adia as imagens até serem necessárias. É uma das vitórias de velocidade mais fáceis em qualquer página cheia de imagens.

Aplique às imagens abaixo da dobra. Elas não são visíveis quando a página abre, então baixá-las cedo desperdiça banda.

Nunca use carregamento preguiçoso na imagem principal ou no logotipo. Eles são visíveis na hora, e atrasá-los prejudica a primeira impressão e a pontuação de LCP.

O otimizador adiciona o carregamento preguiçoso automaticamente para predefinições adequadas. A predefinição de imagem principal deixa desligado, que é o comportamento certo.

Teste a página depois de adicionar o carregamento preguiçoso. Role para baixo e confirme se as imagens aparecem suavemente ao entrar na tela.

Formatos para a web

O WebP é o melhor formato para a maioria das imagens de web. Ele é menor que o JPG com a mesma qualidade e aceita transparência como o PNG.

O JPG continua essencial para compatibilidade. E-mail, compartilhamento social e sistemas mais antigos ainda preferem JPG, e a predefinição Social OG troca para ele automaticamente.

O PNG serve para gráficos de interface, não para fotos. Um logotipo ou ícone fica perfeito em PNG, pixel a pixel, enquanto uma foto em PNG desperdiça banda.

O SVG não é tratado por esta ferramenta. É um formato vetorial, e o otimizador trabalha com imagens raster como JPG, PNG e WebP.

Na dúvida, use WebP para o site e JPG para compartilhar. O otimizador torna a troca entre eles um trabalho de um clique.

O controle de qualidade: 20 a 95%

O controle de qualidade vai de 20 a 95%, não de 0 a 100. Esse intervalo é deliberado e protege você de escolhas ruins.

Abaixo de 20%, as imagens se desfazem visivelmente. Nenhum espaço de site ganha com uma qualidade tão baixa, então a ferramenta não oferece.

Acima de 95%, o arquivo cresce rápido com quase nenhum ganho visível. Os dados extras preservam detalhes que o olho não consegue ver.

A maioria das predefinições fica entre 75 e 85%. Esse intervalo dá resultados limpos com arquivos pequenos para quase toda imagem.

Ajuste o controle só quando o resultado da predefinição não servir à imagem. Uma foto detalhada pode querer 85, enquanto um gráfico simples fica bem com 70.

Remoção de EXIF e peso da página

As fotos de câmera carregam metadados escondidos: localização GPS, modelo da câmera e configurações. Esses dados adicionam peso e vazam informações privadas.

O otimizador remove os dados EXIF e GPS durante a compressão. O arquivo baixado não guarda registro de onde ou quando foi tirado.

A remoção economiza só alguns kilobytes por imagem, mas soma. Vinte imagens economizam uma quantidade significativa juntas.

A privacidade é o benefício maior. Uma foto publicada num site público não deveria conter o local onde foi tirada.

Para trabalhos de clientes, a remoção é essencial. Produtos ainda não lançados e locais privados não devem vazar pelos metadados das imagens.

Otimização em lote para sites inteiros

Você pode otimizar muitas imagens num lote só. Solte trinta imagens de blog, escolha uma predefinição e baixe todas juntas.

O modo em lote é ideal para migrações de site. Mover um blog para um tema novo significa reotimizar cada imagem, e um lote resolve em minutos.

Confira alguns resultados antes de baixar o lote inteiro. Uma única imagem suave pode se esconder entre as boas.

Mantenha a predefinição consistente em todo o lote. Configurações misturadas produzem resultados misturados, que ficam desleixados no site ao vivo.

Para alvos exatos de tamanho de arquivo em vez de predefinições, o compressor de tamanho exato aceita qualquer número que você digitar.

Compartilhamento social e imagens Open Graph

Quando alguém compartilha sua página, a plataforma mostra uma imagem de prévia. Essa imagem costuma ser a primeira coisa que um novo visitante vê.

As imagens Open Graph precisam de dimensões específicas, geralmente 1200 por 630 pixels. A predefinição Social OG dimensiona corretamente e troca para JPG.

Mantenha o arquivo abaixo de algumas centenas de kilobytes. Uma imagem de prévia pesada carrega devagar no cartão de compartilhamento, e algumas plataformas a ignoram por completo.

Teste o cartão de compartilhamento antes de publicar. Cada plataforma importante oferece um depurador que mostra exatamente como a prévia vai ficar.

Uma boa imagem de compartilhamento é simples e forte. O texto deve ser grande, o assunto centralizado e o fundo sem bagunça.

Telas Retina e de alta densidade

As telas Retina concentram mais pixels no mesmo tamanho físico. Uma imagem nítida numa tela normal pode parecer suave numa tela Retina.

O conserto é servir uma imagem com o dobro da largura do tamanho de exibição. Uma miniatura mostrada com 400 pixels de largura deve ter 800 pixels no arquivo.

As predefinições do otimizador consideram isso. Uma predefinição de cartão produz uma imagem que continua nítida em telas de alta densidade sem desperdiçar banda.

Para miniaturas pequenas, isso importa pouco. Para imagens de destaque grandes, a diferença entre padrão e pronta para Retina é visível.

Teste numa tela real de alta densidade quando puder. Capturas de tela do resultado escondem justamente a suavidade que você está tentando conferir.

Texto alternativo e acessibilidade

Toda imagem de web precisa de texto alternativo. Ele descreve a imagem para leitores de tela e para mecanismos de busca, e aparece quando a imagem não carrega.

O otimizador gera o texto alternativo a partir do nome do arquivo ou da sua descrição. Edite quando o texto gerado não descrever bem a imagem.

Escreva o texto alternativo como uma frase. Descreva o que a imagem mostra, não para que ela serve, e mantenha abaixo de uns 125 caracteres.

As imagens decorativas precisam de texto alternativo vazio, não de uma descrição. Um texto alternativo em branco diz aos leitores de tela para pular a imagem por completo.

Um bom texto alternativo também ajuda o SEO. Os mecanismos de busca o leem para entender a imagem, o que pode trazer tráfego da busca de imagens.

CDNs e cache para imagens

Uma rede de entrega de conteúdo serve suas imagens a partir de servidores perto de cada visitante. Isso corta o tempo de download, principalmente para um público global.

As imagens otimizadas ganham mais com uma CDN. Um arquivo pequeno servido de perto carrega quase na hora, enquanto um arquivo grande servido de longe arrasta.

Os cabeçalhos de cache dizem aos navegadores para guardar as imagens localmente. Um visitante que volta carrega a página sem baixar as imagens de novo.

Defina tempos longos de cache para imagens que raramente mudam. Um logotipo ou uma foto de produto pode ficar em cache com segurança por meses.

Otimização e entrega trabalham juntas. Uma imagem pequena numa CDN rápida supera uma imagem grande num servidor lento sempre.

WebP com retorno para JPG

Alguns navegadores mais antigos não conseguem abrir WebP. Servir só WebP deixaria esses visitantes com imagens quebradas.

O elemento picture resolve isso. Ele lista WebP primeiro e JPG em segundo, e o navegador escolhe o primeiro formato que ele suporta.

Gere as duas versões de cada imagem. O otimizador produz a cópia WebP, e uma cópia JPG da mesma predefinição serve como retorno.

Teste o retorno num navegador ou aparelho mais antigo. A versão JPG deve aparecer sem problema, sem nenhuma diferença visível.

Conforme o suporte ao WebP cresce, o retorno importa menos. Por enquanto, é um seguro barato contra imagens quebradas.

Medindo a melhora

Os números de antes e depois deixam o benefício concreto. Anote o peso total das imagens e o tempo de carregamento antes da otimização e meça de novo depois.

Uma página típica cai de vários megabytes para menos de um. Essa mudança aparece na hora nas pontuações de velocidade e na sensação da página.

Confira o Core Web Vitals depois da otimização. O LCP deve melhorar mais, pois a imagem principal costuma ser a maior pintura.

Peça a um colega para carregar a página no celular dele. Um aparelho novo numa conexão real é o teste honesto do seu trabalho.

Guarde um registro simples das economias. Quando alguém perguntar por que as imagens precisam ser otimizadas, os números respondem melhor que qualquer argumento.

Para os passos práticos, leia Como otimizar imagens para a velocidade do site. Para o mergulho profundo no Core Web Vitals, veja Otimização de imagens para Core Web Vitals: LCP e tamanho de arquivo. Para alvos simples de tamanho, o compressor de 200 KB cobre a maioria das imagens de web.

Perguntas frequentes

Qual predefinição devo usar para uma imagem principal?

Use a predefinição de imagem principal, que dimensiona a imagem para um banner de largura cheia e mantém a qualidade alta. Nunca use carregamento preguiçoso numa imagem principal, pois ela está acima da dobra e afeta o Largest Contentful Paint. Use WebP quando o site aceitar, para o menor arquivo com essa qualidade.

Por que a ferramenta troca para JPG nas imagens de compartilhamento social?

As plataformas sociais e os clientes de e-mail lidam com JPG de forma mais confiável que com WebP. A predefinição Social OG e de e-mail troca o formato automaticamente para suas imagens compartilhadas aparecerem corretamente em todo lugar, mesmo em sistemas mais antigos que não conseguem abrir WebP.

Devo manter o carregamento preguiçoso na minha imagem principal?

Não. O carregamento preguiçoso atrasa o download até a imagem se aproximar da tela, o que é errado para uma imagem principal visível na hora. Isso vai prejudicar sua pontuação de Largest Contentful Paint. Mantenha o carregamento preguiçoso só para imagens abaixo da dobra.

O que a opção Só reduzir faz?

Ela protege imagens pequenas de serem ampliadas. Quando ligada, a ferramenta só reduz imagens maiores que as dimensões da predefinição e deixa as menores intocadas. Isso mantém ícones e miniaturas nítidos em vez de esticá-los.

Por que os arquivos baixados têm -web no final do nome?

O sufixo -web marca o arquivo como a versão otimizada para web, para não ser confundido com o original. Um nome como hero-1200-web.webp diz na hora que o arquivo está pronto para o site.

Posso usar o Otimizador de imagens para web em vez do Compressor de imagens em lote?

Use o Otimizador de web quando precisar de predefinições, tags HTML e dimensionamento específico para cada espaço de um site. Use o Compressor em lote quando só precisar de arquivos menores, sem configurações específicas de web. Para limites exatos de tamanho de arquivo, use o compressor de tamanho exato.
