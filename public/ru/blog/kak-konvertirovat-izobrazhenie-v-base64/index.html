Как конвертировать изображение в Base64 за 4 шага

Конвертируйте картинку в Base64 за четыре шага: загрузите, выберите вывод Data URL, сырой, HTML или CSS, затем скопируйте или скачайте. Работает для PNG, JPG, SVG, GIF и ICO.

Вам нужна картинка как текст: логотип для таблицы стилей, иконка для письма или изображение для полезной нагрузки JSON. Конвертация занимает около минуты, когда вы знаете шаги.

В этом руководстве мы пройдём четыре шага конвертации картинки в Base64: загрузите файл, выберите формат вывода, скопируйте или скачайте строку и вставьте её в код.

Не нужно устанавливать программы, создавать аккаунт или что-либо загружать. Картинка кодируется локально в браузере от начала до конца.

Что нужно перед началом

Нужен сам файл картинки в формате PNG, JPG, WebP, GIF, SVG, BMP или ICO, до 15 МБ. Обычные кандидаты — логотипы, иконки и маленькие фото.

Знайте, куда идёт строка. HTML-страница хочет Data URL, таблица стилей — значение CSS url(), а API обычно хочет сырую строку без префикса.

Если картинка большая, подумайте о том, чтобы сначала уменьшить её. Фото на 2 МБ становится строкой на 2,7 МБ, которую неудобно копировать и медленно разбирать, а сжатая версия может быть в десять раз меньше.

Браузер — всё программное обеспечение, которое нужно. Инструмент работает в Chrome, Safari, Firefox и Edge, на компьютере и телефоне, без расширений.

Шаг 1: загрузите картинку или вставьте скриншот

Откройте конвертер изображений в Base64 и перетащите картинку в область загрузки. Можно также кликнуть по области и выбрать файл на устройстве.

Если картинка прямо сейчас на вашем экране, скопируйте её и вставьте через Ctrl+V. Инструмент принимает изображения из буфера обмена напрямую, поэтому скриншот можно закодировать, не сохраняя файл.

Инструмент читает файл и показывает предпросмотр с его размерами и форматом. Проверьте, что предпросмотр — та картинка, которую вы хотели, ведь скопированная строка будет именно этим файлом.

Если загрузили не тот файл, закодируйте другой из инструмента. Предыдущий вывод заменяется, и можно продолжать работу без перезагрузки страницы.

Шаг 2: выберите формат вывода

Над областью вывода находятся четыре вкладки: Data URL, «Сырой», HTML и CSS. Выберите ту, которая соответствует месту, куда идёт строка.

Выберите Data URL, когда нужен полный URI для источника картинки или фона таблицы стилей. Он включает тип носителя и маркер кодировки, поэтому работает везде, где работает URL.

Выберите «Сырой», когда отправляете картинку в API или сохраняете её в базу данных. Сырой вывод — это только строка, без префикса, и именно эту форму ожидает большинство API.

Выберите HTML, когда нужен готовый элемент картинки. Инструмент генерирует тег с Data URL как источником и автоматически заполняет атрибуты ширины и высоты. Выберите CSS, когда нужно значение url() для фона или маски.

Шаг 3: скопируйте вывод или скачайте его

Нажмите кнопку «Копировать вывод», чтобы поместить строку в буфер обмена. Для коротких строк, таких как иконки и логотипы, этого достаточно.

Для длинных строк вместо этого используйте кнопку скачивания. Копирование строки на несколько мегабайт может быть медленным или ненадёжным, а скачанный текстовый файл несёт точный вывод без усечения.

Если браузер блокирует доступ к буферу обмена, инструмент сообщит об этом. Разрешите странице доступ к буферу обмена или используйте кнопку скачивания как обходной путь, которому вообще не нужны разрешения.

Проверьте процент накладных расходов, показанный рядом с выводом. Он говорит, насколько строка больше исходного файла — обычно около 33 процентов плюс немного за обёртку.

Шаг 4: вставьте строку в код

Вставьте вывод туда, где ему место: Data URL — в источник картинки или таблицу стилей, сырую строку — в поле JSON, HTML-сниппет — на страницу или значение CSS — в свойство фона.

Сразу проверьте результат. Откройте страницу, отправьте тестовое письмо или вызовите API и подтвердите, что картинка появляется. Строка, вставленная не в то поле, молча не сработает или покажет битую картинку.

Храните исходный файл картинки. Если встроенную версию когда-нибудь понадобится изменить, вы перекодируете из оригинала, а не декодируете строку и кодируете её заново.

Для логотипа или иконки подумайте о том, чтобы сохранить сниппет в проекте как повторно используемую переменную или частичный шаблон. Тогда длинная строка живёт в одном месте, а не вставляется в каждый файл, которому она нужна.

Как закодировать SVG-логотип

SVG-логотипы кодируются чисто, потому что они уже являются текстом. Загрузите файл SVG, и инструмент создаст строку Base64, которая декодируется обратно в ту же векторную графику.

Data URL для SVG начинается с data:image/svg+xml;base64, за которым следует строка. Вставьте его в источник картинки, и логотип отрисуется резко при любом размере.

Следите, однако, за размером. Сложный SVG со многими путями может быть большим, а его форма Base64 ещё на треть больше. Простой логотип подходит, а детальную иллюстрацию лучше связать как файл.

Для очень маленьких SVG подумайте о просто URL-кодированном SVG вместо Base64. Он короче, но требует аккуратного экранирования, поэтому Base64 остаётся более безопасным выбором по умолчанию для большинства людей.

Как закодировать фавиконку

Файлы фавиконок ICO работают в конвертере так же, как любой другой формат. Загрузите файл .ico и скопируйте Data URL для использования в однофайловой странице или шаблоне письма.

Большинство сайтов должны связывать фавиконку как файл, а не встраивать её. Связанная фавиконка кэшируется браузером, а встроенная скачивается с каждой страницей, которая её содержит.

Встраивание имеет смысл для однофайловых страниц, офлайн-документов и шаблонов писем, где отдельный файл не может быть получен. В этих контекстах встроенная иконка — единственный способ, чтобы фавиконка вообще появилась.

Если фавиконки ещё нет, генератор фавиконок может создать её из любой картинки, а затем вы сможете закодировать результат здесь.

Как кодировать картинки для HTML-писем

HTML-письма не могут полагаться на внешние файлы картинок, потому что многие клиенты по умолчанию блокируют удалённые картинки. Встраивание картинки как Data URL заставляет её появляться сразу, даже офлайн.

Держите встроенные картинки в письмах маленькими. Логотип или небольшой баннер работают хорошо, а большая фотография делает сообщение тяжёлым и медленным для открытия на телефоне.

Проверяйте перед отправкой. Некоторые почтовые клиенты блокируют встроенные картинки Base64, и ваше сообщение может прийти с битыми картинками для этих читателей. Отправьте тест в клиенты, которыми пользуется ваша аудитория.

Когда клиент блокирует Base64, вернитесь к размещённой картинке с обычным URL. Размещённая картинка требует от читателя загрузки удалённого содержимого, но работает в каждом клиенте, который это разрешает.

Как кодировать картинки для полезной нагрузки API JSON

JSON не может нести бинарные данные, поэтому конечные точки загрузки картинок, принимающие JSON, ожидают картинку как строку Base64. Вкладка сырого вывода даёт именно эту форму.

Скопируйте сырую строку в поле JSON, которое документирует API, и отправьте тип носителя в отдельном поле, если API его просит. Сервер декодирует строку и восстанавливает файл.

Следите за размером полезной нагрузки. Картинка на 1 МБ становится полем JSON на 1,4 МБ, а некоторые API отклоняют полезные нагрузки сверх лимита. Сожмите картинку перед кодированием, если у API есть ограничение размера.

Сначала протестируйте с маленькой картинкой. Успешный обмен с крошечной иконкой доказывает, что имена полей и формат правильные, прежде чем вы отправите большую рабочую картинку.

Как уменьшить картинку перед кодированием

Кодирование большой картинки создаёт очень длинную строку, а длинные строки неудобно копировать, медленно разбирать и тяжело хранить. Почти всегда стоит сначала уменьшить её.

Сожмите картинку с помощью сжимателя изображений, прежде чем кодировать её. Фото, уменьшенное с 2 МБ до 200 КБ, создаёт строку в десять раз короче, а потеря качества обычно невидима.

Также измените размер, когда размер показа маленький. Иконке, показанной в 64 пикселя, не нужен исходник на 2000 пикселей, а меньший исходник кодируется в куда более короткую строку.

Для фотографий конвертируйте в JPG перед кодированием, если прозрачность не нужна. Файлы JPG куда меньше PNG для фотографий, а меньший файл означает более короткую строку.

Проблемы с копированием в буфер обмена

Если кнопка копирования ничего не делает, браузер мог заблокировать доступ к буферу обмена. Инструмент покажет сообщение, объясняющее блокировку, и вы сможете разрешить доступ для страницы.

Некоторые браузеры разрешают запись в буфер обмена только после действия пользователя на защищённой странице. Клик по кнопке считается действием, но старый браузер или ограничительная настройка всё равно могут отказать.

Кнопка скачивания — надёжный запасной вариант. Она сохраняет точный вывод как текстовый файл без участия буфера обмена, а вы можете открыть файл и скопировать оттуда.

На телефоне длинные строки могут медленно копироваться. Вместо этого скачайте выходной файл, а затем поделитесь им с приложением, где он нужен, вместо борьбы с буфером обмена.

Проблемы с очень длинными строками

Длинная строка нормальна для большой картинки, но она может замедлить ваш редактор. Вставка строки на 2 МБ в файл кода может заморозить лёгкий редактор на секунды.

Разделите работу: храните строку в отдельном файле или переменной и ссылайтесь на неё из кода, которому она нужна. Это держит основные файлы читаемыми, а редактор — отзывчивым.

Если строка ломает вашу сборку, проверьте лимиты длины строки. Некоторые инструменты переносят или усекают очень длинные строки, что повреждает строку. Скачанный файл полностью избегает этой проблемы.

Когда строка кажется слишком длинной для управления, пересмотрите само встраивание. Связанный файл картинки часто оказывается лучшим выбором для всего, что больше нескольких сотен килобайт.

Как закодировать ещё одну картинку после первой

Чтобы закодировать вторую картинку, загрузите её из инструмента без перезагрузки страницы. Новая картинка заменяет старую, а вывод обновляется до новой строки.

Скопируйте первый вывод перед переключением, потому что замена картинки стирает предыдущую строку. Скачанный файл — самая безопасная запись, если нужны обе строки.

Работа с набором иконок таким способом быстрая. Загрузите, скопируйте, загрузите следующую, скопируйте снова — и весь набор иконок закодирован за несколько минут.

Держите исходные файлы организованными во время работы. Папка исходных картинок и соответствующая папка выходных текстовых файлов предотвращают путаницу, которая возникает, когда все строки выглядят одинаково.

Как кодировать картинки для соцсетей и мессенджеров

Посты в соцсетях и сообщения в чатах иногда принимают картинки только как текст, особенно в ботах, вебхуках и автоматизированных процессах. Строка Base64 позволяет картинке путешествовать внутри текстового сообщения.

Держите эти картинки крошечными. API чата может ограничивать размер сообщения несколькими десятками килобайт, а фото, закодированное в Base64, превысит этот лимит ещё до прибытия.

Для чат-ботов маленькая иконка или миниатюра до 10 КБ кодируется в строку, которая комфортно помещается в сообщение. Всё большее следует загружать как файл и ссылаться по URL.

Некоторые инструменты автоматизации принимают Data URL там, где иначе понадобилась бы размещённая картинка. Это полезно, когда картинка генерируется на лету и разместить её пока негде.

Проверьте полный обмен, прежде чем автоматизировать его. Отправьте одно сообщение с закодированной картинкой, подтвердите, что она отрисовывается на принимающей стороне, и только затем стройте процесс вокруг неё.

Помните, что строка видна всем, кто может видеть полезную нагрузку сообщения. Не кодируйте приватные фото в сообщения, журналы или вебхуки, где текст может храниться или пересылаться.

Быстрая шпаргалка

Загрузите картинку, выберите вкладку вывода для места назначения, скопируйте или скачайте строку. Проверьте её на месте, прежде чем выпускать что-либо, что от неё зависит.

Уменьшайте большие картинки перед кодированием, используйте сырой Base64 для API и предпочитайте связанный файл встроенной строке для всего большого или общего на страницах.

Вот пример из практики. API принимает аватар пользователя в поле JSON, и другого способа загрузки нет. Вы сжимаете фото до 200 КБ, кодируете его в сырой Base64 и отправляете в поле image. Сервер декодирует строку и сохраняет файл — весь обмен происходит одним запросом.

Для фона в CSS кодирование тоже выручает. Маленький повторяющийся узор в виде Data URL внутри background-image загружается вместе с таблицей стилей, без отдельного запроса. Страница отрисовывается сразу, без вспышки пустого фона.

Если вы встраиваете логотип в шаблон письма, держите файл исходника рядом. Когда бренд обновит логотип, вы перекодируете новый файл за минуту, а не будете искать старую строку по всему проекту и гадать, та ли это версия.

Проверяйте строку после вставки в код. Откройте страницу в браузере, отправьте тестовое письмо или вызовите API с маленькой картинкой. Ошибка в одном символе строки даёт битую картинку, а найти её глазами в стене текста почти невозможно.

На телефоне кодируйте только маленькие картинки. Копирование строки на мегабайт через мобильный буфер обмена медленное и ненадёжное — скачайте выходной файл и поделитесь им с нужным приложением, вместо того чтобы бороться с буфером обмена.

Ещё один полезный случай — иконки для чат-бота. Бот отправляет сообщения с маленькой иконкой, а хостинга для картинок у него нет. Закодированная строка в пару килобайт решает задачу: сообщение уходит одним запросом, а иконка отображается у пользователя.

Храните закодированные строки в отдельном файле конфигурации, а не в коде страниц. Когда картинка меняется, вы правите одну строку в одном месте, а не ищете её по всему проекту среди стен текста.

И последний совет: держите исходники иконок в отдельной папке с понятными именами. Когда набор иконок закодирован, легко забыть, какой файл дал какую строку, а папка с исходниками и matching-файлами вывода снимает эту проблему полностью.

Частые вопросы

Можно ли конвертировать картинку в Base64 на телефоне?

Да. Конвертер работает в мобильных браузерах на iOS и Android. Загрузите картинку из галереи, выберите вкладку вывода и скопируйте строку. Для очень длинных строк скачайте выходной файл вместо копирования, ведь мобильные буферы обмена могут с трудом справляться с большим текстом.

Почему вкладка HTML добавляет ширину и высоту в тег картинки?

Браузеру нужны размеры, чтобы зарезервировать место до декодирования картинки. Без них макет страницы сдвигается, когда картинка появляется, что вредит впечатлению от чтения и показателю сдвига макета. Инструмент автоматически заполняет атрибуты из размеров картинки.

Использовать ли Base64 или обычный файл картинки для логотипа сайта?

Для логотипа, который появляется на многих страницах, обычный связанный файл обычно лучше, ведь браузер кэширует его один раз. Base64 выигрывает, когда страница должна быть одним файлом, когда логотип крошечный или когда отдельный запрос не разрешён. Для большинства сайтов связывайте логотип.

Чем Data URL отличается от сырого Base64?

Data URL — это полный URI с префиксом data, типом носителя и маркером кодировки, готовый к использованию как источник картинки. Сырой Base64 — это только строка, без префикса, и именно эту форму обычно ожидают API и базы данных. Инструмент генерирует оба варианта из одной картинки.

Удаляет ли конвертация в Base64 метаданные моей картинки?

Само кодирование ничего не удаляет, ведь строка несёт точные исходные байты. Однако некоторые процессы удаляют метаданные перед кодированием, чтобы строка была короче. Если важна приватность, сначала удалите метаданные инструментом удаления метаданных, а затем кодируйте чистый файл.

Можно ли закодировать скриншот напрямую, не сохраняя файл?

Да. Скопируйте скриншот и нажмите Ctrl+V в инструменте, и он будет закодирован сразу. Это самый быстрый способ получить Data URL для снимка экрана, элемента интерфейса или диаграммы, на которую вы смотрите прямо сейчас.
