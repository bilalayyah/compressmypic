Favicon 尺寸全解析：从 16×16 到 512×512

每一个Favicon尺寸是做什么用的：16×16标签图标、32×32高清屏、180×180苹果图标、192×192与512×512安卓图标，以及ICO容器如何把它们串在一起。一次备齐所有尺寸，网站图标在任何设备上都清晰。还讲了缺了某个尺寸会怎样、ICO容器怎么打包，以及安装后怎样逐个检查。

Favicon 不是一张图，而是一组不同尺寸的图片，每个尺寸对应浏览器或设备里的一个位置。最小的是标签页用的 16×16 像素，最大的是安卓安装界面用的 512×512 像素。

弄清楚每个尺寸用在哪里，能帮你避开两个经典问题：模糊的标签图标，以及发虚的主屏幕图标。这篇指南会从 16 像素讲到 512 像素，逐个说明完整图标包里的每个尺寸是做什么的。

这些尺寸都来自 Favicon 生成器的一次上传，你永远不用手工导出每个尺寸。但知道图标包里有什么，能帮你检查有没有缺文件，也能帮你设计出在每个尺寸下都好用的图形。

16 像素标签图标

16×16 像素是 Favicon 与生俱来的尺寸，至今仍是大多数人最常看到的尺寸。它待在浏览器标签页里，紧挨着页面标题，宽度大概相当于一个大写字母。

在这个尺寸下，只有最大胆的形状能活下来。单个字母、实心符号、高对比的图形都清晰可辨。细线会消失，渐变会压成一个色调，小字会变成噪点。先为这个尺寸设计，其他尺寸自然就顺了。

每个浏览器都会在标签栏用 16 像素图标，大多数浏览器还会在收藏夹菜单和历史记录里用它。这是图标包里最辛苦的尺寸，一个常客每天会看到它几百次。

检查图标时，先看 16 像素预览，再看别的。如果图形在这个尺寸下还认得出来，那在任何地方都认得出来。如果这里已经糊了，再大的尺寸也救不回来。

32 像素高清屏标签图标

32×32 像素是标签图标的高清屏版本。高密度屏幕在同样的空间里塞进了两倍的物理像素，所以浏览器会请求 32 像素的图标，让现代笔记本和台式机上的标签图形保持锐利。

在普通屏幕上，32 像素图标会被缩到 16 像素显示，和小文件看起来一样。在高清屏上，它会以完整清晰度渲染，边缘看起来锐利而不是发软。差别不大，并排比较才能看出来。

ICO 容器里同时装着 16 和 32 像素两个版本，浏览器会根据当前屏幕自动挑选。你不用在两者之间做选择，也不用分开提供。

为 16 像素设计的图形在 32 像素下完全没问题，更大的尺寸只会增加清晰度。反过来不行：一个需要 32 像素细节才能看懂的图形，压到 16 像素就会散掉。

48 像素快捷方式图标

48×48 像素是 Windows 桌面快捷方式和任务栏固定图标用的尺寸。有人把你的网站拖到桌面，或者固定到任务栏，出现的就是这个 48 像素图标。

它还会出现在某些浏览器的收藏夹管理器和老浏览器的地址栏里。这是个中间尺寸：比标签图标大，能多显示一点细节，但依然小到简单为王。

ICO 文件里除了小尺寸，也包含 48 像素这个尺寸，所以桌面快捷方式能拿到一个真正的图标，而不是被拉伸的 16 像素文件。拉伸后的图标在这个尺寸下看起来发软、不专业，所以才需要一个专用的尺寸。

大多数网站从没想过这个尺寸，大多数访客也不会刻意注意到它。但在某天有人把你的网站固定到任务栏、每天早上都看到它的时候，这个尺寸就有了意义。

64 与 96 像素尺寸

64 和 96 像素的图标服务于中间场景：更大的收藏夹磁贴、浏览器新标签页，以及一些扩展程序的界面。它们出现在浏览器有比标签页多、比主屏幕少的一点空间的时候。

在 64 像素下，Logo 可以比 16 像素时多带一点个性。双色图形，或者带背景形状的简单符号，读起来都不错。到了 96 像素，图标开始像一个小的应用磁贴，而不只是标签标记。

这些尺寸也装在 ICO 容器里，附带提供，不用额外花成本。浏览器会挑一个最接近需要的尺寸，再缩放剩下的部分，边缘保持干净。

设计的时候基本不用专门考虑这两个尺寸，因为任何在 16 和 180 像素下都好用的图形，在 64 和 96 像素下也好用。它们存在的意义是填补空档，让任何场景都不会拿到一个缩放得很糟的图标。

180 像素 Apple Touch 图标

180×180 像素是 Apple Touch Icon，iPhone 或 iPad 用户把网站添加到主屏幕时用的就是它。这是第一个大到可以当作设计来评判的尺寸，而不只是一个标签标记。

苹果会忽略这个图标的透明部分，用黑色填充透明区域。透明背景的 Logo 会得到黑色的边角，看起来像个错误，所以纯色背景填充是这里的标准做法。品牌色方块后面的 Logo 是安全又好看的选择。

苹果还会给主屏幕图标加上自己的圆角遮罩，你的 180 像素图片的四个角会被系统形状盖住。设计时要记住这一点：重要细节别放在角落，否则会被遮罩裁掉。

Apple Touch Icon 是一个独立的 PNG 文件，不在 ICO 容器里。它通过 HTML 代码里的专用链接标签引用，只有当用户把网站添加到主屏幕时，浏览器才会去下载它。

192 像素安卓图标

192×192 像素是安卓主屏幕图标，在网页清单里列出。安卓用户把网站添加到主屏幕时，出现在应用旁边的就是这个图标。

安卓会根据设备和启动器的不同，给图标套上遮罩，所以安全区域很重要。图形要居中，周围留出留白，因为启动器可能把它裁成圆形、圆角方形或其他形状。

192 像素图标还用于安装提示，以及某些设备应用抽屉里的网站入口。它需要看起来像一个应用图标，而不是一个缩小版 Logo：粗壮、居中、一眼就能看懂。

和苹果图标不同，安卓图标可以用透明背景，但纯色背景依然是更安全的选择。纯色填充能保证图标在任何启动器和壁纸上看起来一致，透明图形则可能和花哨的背景撞在一起。

512 像素安卓图标

512×512 像素是图标包里最大的尺寸，用于安卓启动画面和安装提示。用户打开已安装的网络应用，页面加载期间，启动画面上出现的就是这个图标。

在这个尺寸下，源图的每个瑕疵都看得清清楚楚。低分辨率 Logo 拉伸到 512 像素会发软，JPG 的压缩痕迹也会原形毕露。这是整个图标包里对源文件要求最苛刻的尺寸。

源图至少要 512 像素，或者直接用 SVG，这样最大的图标和最小的图标一样锐利。矢量源图在这里最理想，因为它放大到 512 像素完全没有损失。

512 像素图标也是很多建站工具在后台设置网站图标时索要的文件。上传这个 PNG，建站工具就拿到了一个又大又干净的源图，可以按自己的需要去缩放。

ICO 容器是怎么工作的？

ICO 格式是一个容器，一个文件里可以装好几张不同尺寸的图片。一个典型的 favicon.ico 包含 16、32、48，有时还有 64 像素的版本，每种尺寸在容器里都是一张独立的图片。

浏览器需要图标时，会打开 ICO 文件，看看里面有哪些尺寸，挑一个最接近需要的。这就是为什么一个文件能同时服务标签页、收藏夹菜单和桌面快捷方式，不用分开下载。

生成器产出的 ICO 文件是真正的多帧 ICO 二进制文件。这个区别很重要，因为一个改了后缀名的 PNG 能骗过某些浏览器，却会在另一些浏览器里失败，在校验格式的工具里更会直接报错。

现代浏览器也可以直接用 PNG 格式的 Favicon，所以图标包里也包含 PNG 文件。ICO 文件仍然是默认选择，因为它历史悠久：哪怕没有加代码，浏览器也会默认到网站根目录请求 favicon.ico。

哪个尺寸做什么用：一张速查图

标签图标是 16 像素，高清屏用 32 像素。桌面快捷方式和任务栏固定用 48 像素。更大的收藏夹磁贴和新标签页用 64 和 96 像素。苹果主屏幕用 180 像素，安卓主屏幕用 192 像素，启动画面和安装提示用 512 像素。

每个尺寸对应不同的观看距离。标签图标是在一堆标签里一眼扫过，主屏幕图标是在一堆应用里特意查看，启动画面图标是页面加载时独自展示。设计必须在三种距离下都成立。

整套图标包只用五个文件就覆盖了所有场景：ICO 容器、Apple Touch PNG、两个安卓 PNG，以及列出安卓图标的清单文件。一套完整的配置不需要更多东西。

如果发现图标包里少了某个尺寸，重新生成一整套，别手工补文件。手工加进去的文件可能尺寸不对、格式不对，而重新生成的图标包能保证每个尺寸都和同一个源图保持一致。

如何为所有尺寸做设计？

先为最小的尺寸设计。如果图形在 16 像素下还认得出来，那在更大的尺寸下一定认得出来，因为更大的尺寸只会增加空间和清晰度。如果图形需要 180 像素才能看懂，那它在最常被看到的标签页里一定会失败。

用一个粗壮的形状、一到两种颜色、强烈的对比。品牌色底上的单个字母，是最可靠的 Favicon 设计。用五种颜色的精细插画，是最不可靠的。

发布之前，在 16、180 和 512 像素三个尺寸下测试图形。这三个尺寸分别代表标签页、主屏幕和启动画面。如果设计在三个尺寸下都站得住，中间的尺寸自然不用担心。

如果 Logo 实在简化不到这个程度，就用它的一部分，而不是整个 Logo。Logo 里的一个符号、一个字母，或者最容易辨认的形状，往往比把整个文字商标挤进方形里效果更好。

如何检查你的图标包？

生成之后打开 ZIP，确认 ICO 文件、Apple Touch PNG、192 和 512 像素的安卓 PNG，以及清单文件都在。少了文件通常是下载中断造成的，重新生成一次就好。

把图标包装到网站上，然后检查标签图标、收藏夹图标，以及真手机上的主屏幕图标。每次检查测试的都是不同的尺寸，合起来就覆盖了从 16 到 512 像素的整个范围。

旧图标还在的话，清一下浏览器缓存，再用隐私窗口测试，看看新访客看到的是什么。隐私窗口的缓存是空的，显示的是当前的文件，而不是存下来的旧副本。

如果某个尺寸看着不对，其他尺寸都正常，问题通常出在源图上。低分辨率的源图在 512 像素下失败，细节太多的源图在 16 像素下失败。换个更好的源图重新生成，别去手工改某一个输出文件。

常见问题

我需要的最小 Favicon 尺寸是多少？

最小是 16×16 像素，用于浏览器标签页。这也是最难设计的尺寸，因为只有最大胆的形状能在这么小的空间里活下来。下载图标包之前，一定要先检查 16 像素的预览。

小小的标签图标，为什么还需要 512×512 的图标？

512 像素的图标不是给标签页用的。安卓用它做启动画面和安装提示，图标会在那里被放大显示。图标包里没有它，安卓上的图标就会被拉伸或直接缺失，哪怕标签图标工作正常。

只用 PNG 格式的 Favicon 够吗，还是必须有 ICO 文件？

PNG 在现代浏览器里能用，但 ICO 文件仍然是默认选择：哪怕没有加代码，浏览器也会到网站根目录请求 favicon.ico，而且 ICO 容器一个文件里可以装好几种尺寸。完整的图标包会同时包含两种格式，覆盖所有浏览器和场景。

做 Favicon 的源 Logo 应该多大？

至少 512×512 像素，或者用没有固定分辨率的 SVG。图标包里最大的图标是 512 像素，源图更小的话就会被拉伸，看起来发软。大尺寸源图或矢量文件能让每个尺寸都保持清晰。

为什么 Apple Touch Icon 需要纯色背景？

苹果会把主屏幕图标的透明区域填充成黑色，看起来像渲染出了问题。纯色品牌背景能彻底避开黑色边角，让图标看起来像一个特意设计的应用图标。

所有浏览器用的 Favicon 尺寸都一样吗？

大体一样，但不完全相同。所有浏览器在标签页都用 16 和 32 像素，而苹果和安卓各自有自己的主屏幕尺寸。完整的图标包会覆盖共用的尺寸，再加上各平台专用的尺寸，所以你不用逐个浏览器去查。
