如何把图片转成 Base64：4 步完成

4步把图片转成Base64：上传、选择Data URL、原始、HTML或CSS输出，再复制或下载。支持PNG、JPG、SVG、GIF、ICO，小图标和Logo转成代码就能直接嵌进网页和样式表里。还讲了四种输出格式分别适合什么场景、复制和下载怎么选，以及大图转Base64之前要先想清楚的事。

你需要把图片变成文字：样式表用的 Logo、邮件用的图标，或者 JSON 数据里的一张图片。知道步骤之后，转换大约一分钟就能完成。

本指南会用 4 个步骤带你把图片转成 Base64：上传文件、选择输出格式、复制或下载字符串，再把它粘贴进代码。

不用安装软件，不用注册账号，什么都不上传。图片从头到尾都在你的浏览器本地编码。

开始之前需要准备什么

你需要图片文件本身，格式为 PNG、JPG、WebP、GIF、SVG、BMP 或 ICO，单个最大 15 MB。Logo、图标和小照片是最常见的候选。

知道字符串要去哪里。HTML 页面想要 Data URL，样式表想要 CSS url() 值，API 通常想要没有任何前缀的原始字符串。

如果图片很大，先考虑缩小。一张 2 MB 的照片会变成 2.7 MB 的字符串，复制起来很别扭，解析起来也很慢，而压缩后的版本可能只有它的十分之一。

一个浏览器就是你需要的全部软件。工具在 Chrome、Safari、Firefox、Edge 上都能运行，桌面端和手机端都可以，不用装扩展。

第 1 步：上传图片或粘贴截图

打开图片转 Base64 工具，把图片拖进上传区域。也可以点击上传区域，从设备里选择文件。

如果图片就在你现在的屏幕上，复制它，再用 Ctrl+V 粘贴。工具直接支持剪贴板图片，所以截图不用先保存文件就能编码。

工具会读取文件，显示预览以及它的尺寸和格式。检查一下预览是不是你想要的那张图片，因为你复制的字符串就是这个确切的文件。

如果传错了文件，可以在工具里再编码另一张。之前的输出会被替换，不用重新加载页面就能继续工作。

第 2 步：选择输出格式

输出区域上方有四个标签页：Data URL、原始、HTML、CSS。选择和字符串去向匹配的那一个。

需要完整的 URI 用在图片源或样式表背景时，选 Data URL。它包含媒体类型和编码标记，在任何能用 URL 的地方都能用。

要把图片发给 API 或存在数据库里时，选原始格式。原始输出只有字符串本身，没有前缀，这正是大多数 API 期望的形式。

想要一个现成的图片元素时，选 HTML。工具会生成标签，Data URL 作为源，宽度和高度属性会自动填好。想要背景或遮罩用的 url() 值时，选 CSS。

第 3 步：复制输出或下载

点击「复制输出」按钮，把字符串放进剪贴板。对图标和 Logo 这样的短字符串来说，这就够了。

字符串很长时，改用下载按钮。复制几 MB 的字符串可能很慢或不可靠，而下载的文本文件承载的是精确的输出，没有任何截断。

如果浏览器屏蔽了剪贴板访问，工具会提示你。可以给这个页面允许剪贴板权限，或者用下载按钮绕过去，下载完全不需要权限。

留意输出旁边显示的膨胀百分比。它告诉你字符串比原始文件大多少，通常在 33% 左右，再加上包装的一点点。

第 4 步：把字符串粘贴进代码

把输出粘贴到它该去的地方：Data URL 进图片源或样式表，原始字符串进 JSON 字段，HTML 代码片段进页面，CSS 值进背景属性。

马上测试结果。打开页面、发送测试邮件或调用 API，确认图片出现。字符串粘贴进错误的字段会悄悄失败，或者显示损坏的图片。

保留原始图片文件。如果嵌入的版本将来需要改，你要从原始文件重新编码，而不是解码字符串再重新编码。

对 Logo 或图标来说，可以考虑把代码片段保存为项目里可复用的变量或局部文件。这样长字符串只存在一个地方，而不是被粘贴进每个需要它的文件。

编码 SVG Logo

SVG Logo 编码得很干净，因为它们本身就是文本。上传 SVG 文件，工具生成的 Base64 字符串解码后还是同一个矢量图形。

SVG 的 Data URL 以 data:image/svg+xml;base64 开头，后面是字符串。把它粘贴进图片源，Logo 在任何尺寸下都渲染得很清晰。

不过要留意大小。路径很多的复杂 SVG 可能很大，它的 Base64 形式还要再大三分之一。简单的 Logo 没问题，细节丰富的插画用链接文件可能更好。

对非常小的 SVG，可以考虑用纯 URL 编码的 SVG 代替 Base64。它更短，但需要小心转义，所以对大多数人来说，Base64 仍然是更安全的默认选择。

编码 Favicon

Favicon ICO 文件在转换器里和其他格式一样好用。上传 .ico 文件，复制 Data URL，用在单文件页面或邮件模板里。

大多数网站还是应该把 favicon 当作文件链接，而不是嵌入。链接的 favicon 会被浏览器缓存，而嵌入的 favicon每个包含它的页面都要重新下载。

嵌入适合单文件页面、离线文档和邮件模板，在这些场景里没有单独的文件可以获取，嵌入的图标是 favicon 能出现的唯一方式。

如果你还没有 favicon，favicon 生成器可以从任意图片生成一个，然后你可以在这里编码它。

为 HTML 邮件编码图片

HTML 邮件不能依赖外部图片文件，因为很多客户端默认屏蔽远程图片。把图片嵌为 Data URL，能让它立即显示，即使离线也能显示。

邮件里嵌入的图片要保持小。Logo 或小横幅效果很好，但大照片会让消息变重，在手机上打开很慢。

发送之前先测试。有些邮件客户端会屏蔽内联 Base64 图片，你的消息送到那些读者手里时图片会损坏。给你的受众使用的客户端发一封测试邮件。

当某个客户端屏蔽 Base64 时，改用带正常 URL 的托管图片。托管图片需要读者加载远程内容，但在允许它的每个客户端里都能用。

为 API 的 JSON 数据编码图片

JSON 无法承载二进制数据，所以接受 JSON 的图片上传接口会要求图片以 Base64 字符串的形式出现。原始输出标签页给出的正是这种形式。

把原始字符串复制进 API 文档指定的 JSON 字段，如果 API 要求，再把媒体类型放在另一个字段里。服务器解码字符串，重建文件。

留意请求体大小。一张 1 MB 的图片会变成 1.4 MB 的 JSON 字段，有些 API 会拒绝超过上限的请求体。如果 API 有大小上限，编码之前先压缩图片。

先用一张小图片测试。一次成功的小图标往返能证明字段名和格式都对了，之后再发送大的生产图片。

编码之前先缩小图片

编码一张大图片会产生很长的字符串，长字符串复制起来别扭、解析起来慢、存储起来也重。先缩小几乎总是值得的。

编码之前，用图片压缩器压缩图片。一张照片从 2 MB 减到 200 KB，生成的字符串会短十倍，质量损失通常看不出来。

显示尺寸很小时，也要缩放。以 64 像素显示的图标不需要 2000 像素的源文件，更小的源文件编码成的字符串要短得多。

照片在不需要透明度时，编码之前先转成 JPG。照片存为 JPG 比 PNG 小得多，文件更小意味着字符串更短。

疑难解答：剪贴板复制问题

如果复制按钮点了没反应，可能是浏览器屏蔽了剪贴板访问。工具会显示一条说明屏蔽的消息，你可以给这个页面允许权限。

有些浏览器只允许在安全页面上的用户操作之后写入剪贴板。点击按钮算是一次用户操作，但旧浏览器或严格的设置仍然可能拒绝。

下载按钮是可靠的后备方案。它把精确的输出保存为文本文件，完全不涉及剪贴板，你可以打开文件再从里面复制。

在手机上，长字符串复制起来可能很慢。改成下载输出文件，再分享到你需要它的应用里，而不是和剪贴板较劲。

疑难解答：非常长的字符串

大图片的字符串很长是正常的，但它会让编辑器变慢。把 2 MB 的字符串粘贴进代码文件，轻量编辑器可能卡住好几秒。

分开处理：把字符串存在单独的文件或变量里，再从需要它的代码里引用。这样主文件保持可读，编辑器也保持响应。

如果字符串破坏了你的构建，检查行长度限制。有些工具会换行或截断非常长的行，这会损坏字符串。下载的文件能完全避免这个问题。

当字符串长到难以管理时，重新考虑到底要不要嵌入。几百 KB 以上的内容，链接图片文件往往是更好的选择。

编码第一张之后再编码另一张

要编码第二张图片，不用重新加载页面，直接在工具里上传它。新图片会替换旧图片，输出会更新为新的字符串。

切换之前先复制第一份输出，因为替换图片会清除之前的字符串。如果两份字符串都需要，下载文件是最安全的记录方式。

这样处理一整套图标很快。上传、复制、上传下一张、再复制，几分钟就能把整套图标编码完。

工作时把原始文件整理好。源图片一个文件夹、输出文本文件一个对应的文件夹，能避免字符串看起来都一样时发生的混淆。

为社交媒体与消息编码图片

社交帖子和聊天消息有时只接受文本形式的图片，尤其是在机器人、webhook 和自动化流程里。Base64 字符串能让图片放在纯文本消息里传输。

这类图片要保持非常小。聊天 API 可能把消息大小限制在几十 KB，一张照片编码成 Base64 还没送到就超过了上限。

对聊天机器人来说，10 KB 以下的小图标或缩略图编码成的字符串能轻松放进一条消息。更大的内容应该以文件形式上传，用 URL 引用。

有些自动化工具在本来需要托管图片的地方接受 Data URL。当图片是实时生成、还没有地方托管时，这很有用。

自动化之前，先测试完整的往返过程。发一条带编码图片的消息，确认接收方能正常渲染，再围绕它搭建流程。

记住，任何能看到消息内容的人都能看到这个字符串。不要把私人照片编码进消息、日志或 webhook，因为文本可能被存储或转发。

快速参考清单

上传图片，按目标位置选择输出标签页，复制或下载字符串。任何依赖它的东西发布之前，先在原地测试。

大图片编码之前先缩小，API 用原始 Base64，大型或跨页面共享的内容优先用链接文件而不是嵌入字符串。

常见问题

可以在手机上把图片转成 Base64 吗？

可以。转换器在 iOS 和 Android 的手机浏览器里都能运行。从相册上传图片，选择输出标签页，复制字符串。字符串很长时，改成下载输出文件，因为手机剪贴板处理大文本可能很吃力。

为什么 HTML 标签页会给图片标签加宽度和高度？

浏览器需要尺寸来预留空间，图片解码之前就知道要留多大地方。没有它们，图片出现时页面版式会跳动，影响阅读体验和版式偏移分数。工具会根据图片尺寸自动填好这些属性。

网站 Logo 应该用 Base64 还是普通图片文件？

出现在很多页面上的 Logo，普通链接文件通常更好，因为浏览器只缓存一次。Base64 的优势在于页面必须是单个文件、Logo 非常小，或者不允许单独请求的时候。对大多数网站来说，链接 Logo 是更好的选择。

Data URL 和原始 Base64 有什么区别？

Data URL 是完整的 URI，带有 data 前缀、媒体类型和编码标记，可以直接用作图片源。原始 Base64 只有字符串本身，没有前缀，是 API 和数据库通常期望的形式。工具会从同一张图片生成这两种形式。

转成 Base64 会去掉图片的元数据吗？

编码本身不会去掉任何东西，因为字符串承载的是精确的原始字节。不过，有些流程会在编码之前去掉元数据，让字符串更短。如果隐私很重要，先用删除元数据工具清理文件，再编码干净的文件。

能直接编码截图，不用先保存文件吗？

可以。复制截图，在工具里按 Ctrl+V，它会立即编码。这是从截屏、界面元素或你正在看的设计图获取 Data URL 最快的办法。
