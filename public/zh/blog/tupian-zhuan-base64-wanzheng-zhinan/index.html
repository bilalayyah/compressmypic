开发者常常需要把图片当作文字而不是文件来用。样式表里的图标、HTML 邮件里的 Logo，或者 JSON 数据里的图片，都需要把图片转换成字符。

Base64 就是让这件事成为可能的编码。它把图片的二进制字节变成一串纯文本字符串，可以放进代码、标记和消息里。

本指南会介绍 CompressMyPic 图片转 Base64 工具的工作方式、每种输出格式的用途，以及什么时候嵌入图片是明智的、什么时候是个错误。

什么是 Base64？

Base64 是一种把二进制数据表示为文本的方式。它把文件的原始字节重写成 64 个安全字符：大写字母 A 到 Z、小写字母 a 到 z、数字 0 到 9，再加上加号和斜杠，等号用作填充。

这些字符是安全的，因为它们出现在每一种文本系统里。邮件、JSON 文件、样式表和数据库都能容纳一个 Base64 字符串而不损坏它，原始图片字节就做不到这一点。

Base64 不是加密，也不是压缩。收到字符串的任何人都能把它解码回原始图片，而且字符串永远比它来源的文件更长。

把它想成一种翻译，而不是一种转换。图片还是同一张图片，只是写下来用的字母表换了。

Base64 编码的工作原理

编码每次读取图片文件的三个字节。每组三个字节一共 24 位，会被拆成四组六位，每组六位变成一个 Base64 字符。

当文件长度不是三的倍数时，编码器会加上等号作为填充。一个等号表示最后一组有两个字节，两个等号表示只有一个字节。

结果是一串包含整张图片的文本。解码会精确地反向执行这个过程，把字符变回原始字节，完全没有任何损失。

转换器在你的浏览器本地完成这一切。图片被读取、编码、显示，全程没有离开你的设备，所以私密的设计图和客户素材依然是私密的。

33% 的体积膨胀

Base64 输出比原始文件大约 33%。一张 90 KB 的图片会变成大约 120 KB 的字符串，因为四个文本字符只能承载三个字节的数据。

这种膨胀是编码的固定属性，不是工具的缺陷。任何语言里的任何 Base64 编码器，对同样的输入都会产生同样大小的增量。

HTML 和 CSS 输出还要再大一点，因为它们会在字符串外面加一层包装。图片标签加了标记，CSS 函数加了自己的语法，都是在 33% 之上再加的。

嵌入之前，首先要考虑的就是这种膨胀。一个 3 KB 的小图标变成 4 KB，没人会注意到；但一张 2 MB 的照片变成 2.7 MB，每个人都会注意到。

一个工具，四种输出格式

转换器提供四种输出格式，每种对应不同的工作。你选择符合代码的那个标签页，工具会生成你需要的精确代码片段。

Data URL 标签页给出完整的 Data URI，可以直接粘贴进图片源或样式表。它把媒体类型、编码标记和 Base64 字符串合在一个整体里。

原始 Base64 标签页只给出字符串本身，没有前缀。这是 API 数据和数据库通常想要的形式，因为接收代码会自己加上上下文。

HTML 图片标签页给出一个完整的图片元素，Data URL 作为源，宽度和高度属性会自动填好。CSS 标签页给出一个包着 Data URL 的 url() 函数，可以直接用作背景或遮罩。

Data URL 详解

Data URL 以 data 这个词开头，后面是媒体类型、编码标记和 Base64 字符串。典型的样子是 data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA。

浏览器在任何能用普通 URL 的地方都能理解 Data URL。你可以把它用作图片源、样式表背景或链接目标，浏览器会解码并渲染它。

好处是自包含。使用 Data URL 的页面没有需要单独获取的图片文件，所以可以离线工作、可以做成单个文件，也可以在外部请求被屏蔽的环境里使用。

坏处是体积。33% 的膨胀适用于每个嵌入的图片，包含很多 Data URL 的页面会变得沉重、解析缓慢。

原始 Base64 详解

原始 Base64 是没有 data 前缀的字符串。当接收方已经知道图片类型，或者类型放在另一个字段里传输时，就用这种形式。

API 数据是主要的用例。一个 JSON 对象可以用一个叫 image 的字段承载原始字符串，再用一个叫 mimeType 的字段承载格式，服务器根据这两个字段重建文件。

数据库也一样使用原始 Base64。把图片以文本形式存在文本列里，可以避开二进制列类型，有些系统处理二进制列很糟糕。

复制原始 Base64 时，要保留填充。末尾的等号是编码的一部分，去掉它们会让要求完整字符串的解码器出错。

HTML 图片代码片段

HTML 标签页会生成一个完整的图片元素，Data URL 作为源。它还会根据图片尺寸自动填好宽度和高度属性。

这些属性比看起来重要得多。没有它们，浏览器在解码字符串之前不知道图片大小，图片最终出现时页面版式会跳动。

有了宽度和高度，浏览器会立即预留出正确大小的空间。版式保持稳定，这对读者和版式偏移分数都有好处。

这个代码片段可以直接粘贴进任何 HTML 文件。发布之前记得加一个 alt 属性描述图片，因为工具不知道这张图片画的是什么。

CSS url() 代码片段

CSS 标签页把 Data URL 包进一个 url() 函数，生成一个可以直接粘贴进 background-image 或类似属性的值。这是把小图片放进样式表最快的办法。

嵌入的 CSS 图片常用于图标、图案和装饰背景。它们随样式表一起加载，没有单独的请求，也不会出现装饰缺失的闪烁。

代价是样式表变重。塞满嵌入图片的样式表会变大，浏览器也无法把图片和包含它们的 CSS 分开缓存。

CSS 形式适合小而稳定的图片。Logo 或重复图案符合条件，照片库就不行，因为样式表会变得巨大。

质量：编码什么都不改变

把图片编码成 Base64 不会改变任何一个像素。这个过程完全可逆，解码字符串会返回完全相同的原始字节。

动图 GIF 会保留动画，SVG 文件会保留代码，照片会保留每个细节。编码是一种不同的表示方式，不是一张不同的图片。

这和转换格式有重要区别。把 PNG 转成 JPG 会丢失数据，但把 PNG 编码成 Base64 什么都不会丢失。

唯一变化的是大小。字符串比文件大约大三分之一，这就是用文本承载二进制数据的代价。

支持哪些格式与大小

转换器接受 PNG、JPG、WebP、GIF、SVG、BMP、ICO 文件，单个最大 15 MB。Logo、图标、照片和动态图片都可以在一个工具里处理。

SVG 文件编码得很干净，因为它们本身就是文本。工具读取 SVG 代码，像编码其他文件一样编码它，生成的字符串解码后还是同一个矢量图形。

Favicon ICO 文件也可以用，当网站需要把图标嵌进单文件页面或邮件模板时很方便。编码后的 ICO 解码回来还是一个有效的图标文件。

接近 15 MB 上限的文件，建议先缩小。把大的 PNG 先压缩成更小的 JPG 再编码，生成的字符串会短得多，质量损失常常看不出来。

什么时候该嵌入 Base64 图片

嵌入那些小而关键的图片。几 KB 以下的图标、Logo 和小装饰图形是理想选择，因为膨胀可以忽略不计，省下的请求却是实实在在的。

嵌入单文件文档里的图片。HTML 邮件、独立报告或离线页面无法获取外部文件，嵌入是图片能显示的唯一办法。

嵌入 API 数据和配置文件里的图片。当图片必须放在 JSON 里或数据库记录里时，Base64 是标准的承载方式。

嵌入很少变化的图片。一个多年不变的 Logo 嵌入了也没什么成本，而每周更新的图片每次都要改代码。

什么时候不该嵌入

不要嵌入大照片。一张 2 MB 的照片会变成 HTML 里 2.7 MB 的字符串，浏览器必须先下载并解析全部内容，页面才能渲染。

不要嵌入出现在很多页面上的图片。嵌在每个页面里的 Logo 每次都要重新下载，而链接的 Logo 只缓存一次，全站都能复用。

不要不经检查就把图片嵌进邮件。有些邮件客户端会屏蔽内联 Base64 图片，你的消息送到那些读者手里时图片会损坏。

不要嵌入需要被索引或分享的图片。搜索引擎很难发现嵌入的图片，读者也无法像对待普通文件那样右键保存它。

Base64 在邮件与 API 中的使用

HTML 邮件是最早使用 Base64 图片的场景之一。邮件就是一条单独的消息，嵌入的图片会随它一起传输，读者离线时也能显示。

不过，并不是所有邮件客户端都认同。有些出于安全原因屏蔽内联 Base64 图片，所以依赖嵌入之前，先在你的受众实际使用的客户端里测试模板。

API 使用 Base64 的原因是另一个：JSON 无法承载二进制数据。接受 JSON 的图片上传接口会要求图片以 Base64 字符串的形式出现，媒体类型常常放在另一个字段里。

构建这样的请求时，用原始 Base64 标签页。它给出的字符串没有 data 前缀，这正是大多数 API 期望的形式。

隐私：编码在你的浏览器里进行

在网上编码图片意味着要把它上传到服务器，对专有图标、保密设计图或客户素材来说，这是个坏主意。这个工具永远不会这样做。

文件由你的浏览器读取，在你的设备上编码，字符串在本地显示给你。图片或字符串的任何副本都不会离开你的电脑。

这也意味着页面加载好之后，工具可以离线使用。在飞机上或安全的办公室里，没有任何网络也能编码图标。

对处理敏感视觉素材的团队来说，本地编码就是决定性的功能。你复制的字符串属于你，没有任何服务器见过图片或它的编码形式。

如何使用图片转 Base64 工具

打开图片转 Base64 工具，把图片拖进上传区域，或者直接从剪贴板粘贴截图。单个文件最大 15 MB。

选择符合你工作的输出标签页：Data URL 适合完整的 URI，原始格式适合 API 数据，HTML 适合现成的图片元素，CSS 适合样式表背景。

用复制按钮复制输出，或者在字符串很长、复制感觉不保险时下载为文件。下载会保存精确的文本，没有任何截断。

常见问题

Base64 编码和压缩图片是一回事吗？

不是，从大小上说正好相反。压缩让文件变小，Base64 让文件大约增大 33%。编码只是把表示方式从二进制变成文本，不改变任何像素。如果需要更小的文件，先压缩图片，再编码压缩后的结果。

能把 Base64 图片嵌进 Word 文档或 PDF 吗？

不能直接以 Base64 字符串的形式嵌进去。Word 和 PDF 文件把图片以二进制数据的形式存在文档内部，而不是 Base64 文本。Base64 适用于网页代码、邮件、JSON 数据和其他基于文本的格式。文档使用时，先把图片转成普通文件。

为什么我的 Base64 字符串这么长？

因为它以文本形式承载整张图片，而文本作为载体的效率比二进制低。一张 90 KB 的图片会变成大约 120 KB 的字符，一张 1 MB 的照片会变成大约 1.4 MB 的文本。长度是正常的。字符串很长时，用下载按钮代替复制。

Base64 编码支持动图 GIF 吗？

支持。编码不碰像素数据，所以动图 GIF 编码成的字符串解码后还是同一个动图文件。动画、帧数和时间都完整保留。

这里能转换的最大图片是多大？

单个文件最大 15 MB。更大的文件会生成极长的字符串，复制起来很别扭，浏览器解析起来也很慢。编码之前先缩小或压缩大图片，几百 KB 以上的内容建议用链接而不是嵌入。

搜索引擎能看到嵌为 Base64 的图片吗？

基本看不到。搜索引擎在技术上可以解码 Data URL，但嵌入的图片不会像链接的图片文件那样被索引、排名或出现在图片搜索里。如果图片搜索流量很重要，用链接文件代替嵌入。
